# Continuation study redesign: feasibility decision draft

Status: planning only. This is outcome-informed by the closed maintained-packaged frame. It does not reopen any study, authorize a new sample, dispatch an application job or register a confirmatory result. The original goal remains a competent comparison of incremental native-continuation information, not deployment success as a substitute research contribution.

## Diagnosis and retained question

The last frame admitted zero workflows. Its two ordinary application attempts stopped before resource writes. Deployment provenance, source-mapping limits, external authentication and incomplete state mapping caused additional attrition. Thus it supplied no test of whether native continuation adds information beyond H/S/A. Broadening a search until a discrepancy appears would not repair this.

Retain the question: among preselected workflows with successful ordinary controls, does an accepted API-produced state permit an equivalent API edit but prevent the native edit, and what accounts for that difference? Report a conditional result for the admitted cohort. Never extrapolate to all applications or claim an agent-specific effect without a separate agent intervention.

## Separate engineering calibration from scientific admission

For a future, separately frozen frame, first fix candidate identities and order without looking for defects. An independently maintained deployment suite could be a sampling source, but its inclusion criteria, exposure overlap, revision provenance, ordinary task coverage and licenses must be assessed before use. No benchmark is selected by this draft. An organizational sandbox is another access option, subject to publication rights and a declared convenience-sample interpretation; it is not automatically independent or publishable.

Permit adapter debugging on ordinary valid operations during a declared engineering stage. Record every attempt, failure, source read, change and cost. Set a fixed wall-time/job budget for each candidate before calibration; do not reset it after a failure or transfer unused allowance to a promising candidate. The exact numeric budget must be chosen against remaining resources before execution, not copied from the exhausted study after observing failures. Existing closed runs cannot become this stage's first attempt or be rerun under a new label.

Debugging may repair navigation, selectors and deployment wiring. It may not change application validators, install an artificial authentication bypass, modify required fields, exclude troublesome side effects or simplify the native serializer. Only ordinary predeclared values are permitted. Any incidental nonordinary behavior is logged as prior exposure; it cannot silently become a new evaluation case. Qualification is not evidence of effectiveness.

Select a workflow by a predeclared structural ordering, not expected validation disagreement. Freeze the supported workflow and full interface/schema/state contract before scientific values execute. A failed selected workflow is retained, not replaced with a later resource. Freeze adapters after engineering qualification, not before ordinary navigation has ever been exercised. Any subsequent adapter defect invalidates affected measurements; retain them and follow a predeclared policy rather than unbounded reruns.

## Collection and independence records

Retain a machine-readable dependency queue: repository/revision/path, parent path, discovery timestamp, depth, reason, queue position, scheduled freeze, collection status and content hashes. Use a reproducible ordering rule across the entire queue, not merely within batches. Source limits must be resource-motivated and chosen before collection. Complete the eligible candidate dispositions even if the frame is unproductive.

Snapshot the pre-study exposure index before new inspection. Track source, documentation, issue and prior-development exposure separately; avoid issue/fix searches for case selection. Establish conservative family groups using declared aliases/lineage and inspected provenance before claiming independent families. Unresolved ancestry does not become independence because the repository name is new. No claims about absence from model training.

The full screened frame remains the feasibility denominator. The qualified cohort is a selected subset; deployment convenience and native-control success induce selection bias. Report every exclusion and the work spent on it. Four families may remain a minimum descriptive feasibility gate, but it is not a power analysis or evidence of journal adequacy. Do not expand the frame because the gate or a positive-finding count is missed.

## Required admission proof

Every admitted workflow needs exact source/runtime identities; ordinary local actor initialization; actual native create/edit navigation; original operation schema and supported dialect; captured producer and native-update serialization; complete resource/relationship/authentication persistence map; and successful ordinary native/native, API/native and API/API controls. Retain original schema absence/unsupportedness rather than synthesizing frontend requirements for S. An S-unavailable cohort would answer a different comparator question and must be designated before sampling, not after outcomes.

Use one accepted API producer and two isolated restores of its immutable checkpoint. Compare exact values, identifiers, timestamps, relationships and relevant actor state before edit and after native navigation; no value normalization. Retain application background writers or establish their quiescence through evidence. Different states are unpaired. The API continuation receives the actual equivalent native serialization and all relevant shared context. Read back persisted results after each edit. Same intent alone is insufficient equivalence.

H observes immediate response, S the original schema, A the equivalent API edit/readback, and U native edit/readback. None is ground truth for requirements. Do not add frontend constraints to S or withhold relevant serialization context from A to create an artificial U advantage. A source-aware comparator can be added only with specified shared information and competent coverage, prospectively.

## Scientific inputs and inference

Retain a deterministic input policy chosen without inspecting expected discrepancies: unchanged control, then omission and null singly for eligible text properties in fixed order. Fields, maximum cases and edit target must be frozen before outcomes. Rejected producers do not enter accepted-state continuation comparisons. Ambiguous responses, unsupported schemas, timeouts and drift remain distinct outcomes.

Report H/S strata and A/U overlap with all denominators. Treat correlated cases as clustered within workflow/family. Do not count each field mutation as an independent defect. A native-only failure is operational evidence, not automatically a requirement violation. Independent documented obligations and a prespecified mechanism check are required for a stronger claim. A repair observation is within-case evidence, not randomized causal proof. A null incremental result is acceptable; unavailable comparisons do not establish a null effect.

## Go/no-go before any new acquisition

A separate execution registration requires: a justified fixed frame with no defect-based selection; workable original deployment instructions; explicit exposure/family handling; total budgets including failed calibration; a queue implementation and artifact retention plan; precise control and serializer checks; and an interpretable result even if no discrepancies occur. The access option is currently unresolved. No provider is charged and no scientific case runs until these prerequisites are concretely specified.

Current decision: no new cohort or runtime from this draft. Determine access and assess whether engineering qualification can be made reproducible within the $100 ceiling and available effort. If not, report the current feasibility result and keep the Q1 empirical objective unachieved. A polished manuscript cannot compensate for missing comparative evidence.

## Offline queue implementation status

The prepared dependency_queue_v1 module provides fixed-revision roots, parent edges, depth, lexical batch scheduling, freeze identifiers, terminal observations, explicit discovery sealing and an event ledger. Failures consume allowance; repeated observations and overlapping open batches are rejected. Four local unit tests cover breadth-first precedence, duplicate-parent retention, freeze/terminal requirements, failed-attempt accounting and atomic rejection. This is an offline state-transition component, not an integrated collector or independent audit of review completeness. Caller-supplied freeze identifiers must still be verified against remote-published schedules by the collector. State durability, content verification and read access controls remain integration requirements. No new candidate sources were fetched.
