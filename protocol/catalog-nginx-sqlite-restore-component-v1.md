# AccessList stopped-writer SQLite file restoration

This component replaces only /data/database.sqlite in the registered disposable Nginx Proxy Manager instance, after mounted filesystem restoration. It neither starts nor stops a container. It requires the actual Docker inspection guard for fully stopped writers, disabled restart policy and the exact two writable bind mounts. The original backup must be outside both state roots, a single regular file without extended attributes, at most 64 MiB and match its complete previously recorded SHA256. Require native extended-attribute inspection; do not bypass it on unsupported platforms.

Before mutation, validate the destination and all existing database.sqlite-wal, database.sqlite-shm and database.sqlite-journal entries as single regular files without extended attributes. Reject symlinks/hard links. Stage a private replacement file in the same directory, fsync it, verify both staged and source backup hashes, and preserve the original database mode/ownership/timestamps. Recheck authoritative container identity and unchanged destination/sidecars before replacing the database. Remove only those three previously validated sidecars, fsync the directory, recheck stopped container identity, final database hash and sidecar absence. Do not mix an old journal with the standalone verified backup.

A failed pre-replacement check leaves the database/sidecars untouched; staging files are cleaned up. Replacement plus sidecar removal is not a transaction over all files: an interruption or post-replacement failure remains a failed restore. Keep the application stopped and preserve diagnostics; never restart or claim success from partial file replacement. The function's successful return only establishes byte restoration. The original driver must subsequently establish full logical state/integrity and the enclosing recipe must establish full application/filesystem/actor equivalence before startup/continuation. No table, audit row or timestamp exception is admitted here.

Six tests use synthetic SQLite fixture files and mocked container inspection to exercise file replacement, precise sidecar removal, hash/lifecycle rejection, symlink handling and location bounds. Those tests do not establish actual Docker lifecycle behavior or compatibility with the application's pinned driver. Run native filesystem checks on Linux CI. No application job is authorized by this component specification.
