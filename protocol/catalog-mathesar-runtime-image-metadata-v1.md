# Mathesar ordinary runtime image metadata

Before any build or application run, resolve immutable linux/amd64 metadata for two Docker Official Images: library/python:3.14-bookworm (the acquired Dockerfile's default PYTHON_VERSION) and library/postgres:17.12-bookworm (PostgreSQL major17, matching the app's original production major). Use original Dockerfile target minimal with an external PostgreSQL service in the future runtime recipe; no Dockerfile/application patch is authorized here. The browser image/Node harness pin from the completed development qualification remains separately recorded and must be verified before reuse.

For each image, allow exactly four sequential HTTPS requests: anonymous public pull-token request to auth.docker.io for that repository; tag manifest/index; selected linux/amd64 child manifest; its config blob. Limit 30 seconds/request and 120 seconds/image, no retry, tag substitution or mirror. JSON envelope bounds: token 64 KiB (keep token only in memory), index 2 MiB, child manifest 1 MiB, config 256 KiB. Require exactly one linux/amd64 image candidate, verify selected child/config SHA256 identities, and retain raw public manifests/config plus hashes, layer sizes and errors. If unavailable, record the failure; do not silently choose another tag or modify the source runtime.

No layer download, Docker invocation, package install, application archive, external paid service or credential access. Anonymous pull tokens are transient and are not repository secrets; do not print or persist them. This stage does not qualify image availability on Actions, source build success, restoration, native actionability or scientific outcomes.
