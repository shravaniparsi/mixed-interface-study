# Ordinary database outcome comparison

This prospective rule covers the two frozen ordinary AccessList edits only. It does not apply automatically to altered inputs, authorize dispatch or establish full application-state equivalence. No Nginx Proxy Manager runtime outcome has been observed. Preserve the full private typed snapshots and each original timestamp.

The comparator consumes a common pre-edit snapshot and two complete post-edit snapshots from the original-driver inventory. Starting-state equality remains exact and is checked separately before each branch. All schemas, table sets and column definitions must remain unchanged. Tables outside access_list, access_list_auth, access_list_client, audit_log and sqlite_sequence must remain identical to the common pre-edit snapshot, including row multiplicities. Within the affected entity tables, all non-subject rows remain unchanged.

For either ordinary edit, the subject access_list row may change only modified_on. Source update patches name and both booleans using the complete unchanged ordinary values, invoking the original model's update timestamp. Root created_on, owner, metadata and all other root values remain unchanged.

The client row is deleted and reinserted by the original update. Require exactly one target client before and after, its next original autoincrement ID, and unchanged fields except new created_on/modified_on plus the address value when address is the scheduled edit. For the password edit, require exactly one replacement auth row with the next original auth sequence ID and the frozen new password; other non-ID/non-timestamp fields remain unchanged. For the address edit, the auth row, including its password and timestamps, remains byte-for-byte equivalent at the typed-value level.

The audit history must remain unchanged. Require exactly one additional audit row with the next original audit sequence ID, the same actor, the subject list ID, object_type=access-list and action=updated. Retain and compare all audit metadata and other values between branches. Sequence changes are exactly +1 for the client and audit tables, and +1 for auth only on a password edit. Missing original sequences, unexpected IDs, duplicate IDs, schema changes and extra mutations fail ordinary qualification; they are not silently normalized.

The only timestamp cells admitted for branch-relative comparison are the subject root's modified_on; the replacement client's created_on/modified_on; the replacement auth row's created_on/modified_on for a password edit; and the new audit row's created_on/modified_on. Require each to be canonical SQLite timestamp text inside that branch's observed operation interval. The runtime must establish original localtime as UTC and retain actual clock observations. The interval must be monotonic and no longer than 120 seconds. Floor the observed endpoints to seconds to match the original datetime precision; add no further tolerance. Replace those verified cells with comparison markers only in a copied state, and compare every remaining value across branches. Return all original timestamps as private evidence.

Eight synthetic tests pass, covering both edit types, preserved audit metadata, forbidden historical/root timestamps, out-of-window times, incorrect actor/sequence, changed unedited credentials and matching-but-unrelated branch mutations. These tests use constructed typed snapshots, not a live database or the installed driver. The original runtime schema, observed time windows and actual update behavior remain qualification hypotheses. The separate password-file predicate, filesystem/configuration/actor checks, and native/API request equality remain mandatory.
