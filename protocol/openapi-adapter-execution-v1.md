# OpenAPI adapter comparison: execution freeze v1

This protocol extends the fixed selection and source-input registrations. It authorizes one initial three-subject matrix at the commit containing the execution manifest after its unit checks pass. The sample, versions, 48 source cases and source semantics are unchanged. No runtime converter schemas or outcomes have been observed when this file is written.

## Bindings and environments

Use the three public stdio entry points archived from the pinned releases. Object body fields remain flat tool arguments; PATCH additionally supplies record_id=seed. No extra values, defaults, null deletion or body reshaping are applied by the study client. Select exactly one discovered tool whose lowercase alphanumeric name equals the source operationId after the same normalization. Missing/ambiguous matches end the subject as a binding failure; retain all source cases as unexecuted. This rule permits documented slugification without outcome-driven remapping. Tool discovery is saved in full. The client requests MCP 2025-03-26 and records the server's negotiated version.

Two npm distribution records report gitHead matching the frozen source commits. They are publisher metadata, not independently verified build attestations. Python fastmcp is a metapackage requiring fastmcp-slim at the same version; the lock identifies both artifacts by hashes. Release identity is established by version and registry hashes; equivalence of wheel contents to every source file has not been established. Report this distinction. Resolve Python for Linux x86_64/Python 3.12, using uv 0.9.9; Node locks were generated with npm 8.1.2 without installs or scripts. The local Node 16 engine warnings are expected: execution is fixed to Node 22.19.0. Runtime installs must honor lockfiles; save installed dependency inventories and installation failures.

## Fixed schedule and qualification

Each subject gets two complete repetitions of the 48 inputs, giving 96 paired observations per qualified subject and 288 maximum across three subjects. Repetitions are stability checks, not independent observations. Move the all-ordinary POST and PATCH cases to the beginning, preserving remaining inventory order. Both ordinary cases must be advertised-schema-valid and preserve expected state; failure stops that subject. No separate replacement controls. Repeat one executes direct REST then MCP; repeat two reverses route order. Both routes reset and independently verify the full initial database before every call. No model or human task study is involved.

Before converter initialization, run all 192 reference-calibration cases and reconstruct their HTTP and database evidence. This is measurement calibration, excluded from converter denominators. Source validity has already been checked independently. For every converter case validate advertised inputSchema without pruning invalid cases: record validation errors and still make the fixed call. Each case records stdio exchange, outbound HTTP, follow-up read, full SQLite state, status and elapsed time. No discovery-based argument repair is allowed.

## Comparisons and reporting

Direct REST must succeed with expected state or execution stops as a measurement failure. Compare outbound method, path, JSON body (including absence/null/type/array order) and declared content-type equivalences. JSON object key order and formatting are ignored. This fixture explicitly accepts both JSON MIME types for PATCH; these are equivalent only under this source contract. The HTTP capture logs content type but not every HTTP header: this comparator is complete for the fixture's declared request semantics, not a universal HTTP equivalence oracle. Save raw bodies for inspection.

Report advertised-schema validity, no outbound request, persisted-state difference, request difference without state difference, preserved state with tool error, and preservation separately. A source-valid case rejected before HTTP is a representability/runtime outcome, not a persisted-state defect. Record unexecuted cases when qualification or infrastructure stops a subject. State differences require inspection against raw evidence and source-level explanation before any natural-converter-fault claim. Variants and repetitions cannot be counted as independent defects. The state check does not claim incremental detection over a complete request comparator. No population rates or inferential p values are planned for this purposive three-subject sample.

## Budget and stop rules

Three initial jobs, each at most 15 minutes; at most one separately registered infrastructure-only correction per subject, also 15 minutes. Total ceiling remains 90 application-job minutes including setup and calibration. Free public GitHub Actions only; zero paid model calls. No automatic workflow retries or finding-driven repetitions. A scientific mismatch is not grounds for an infrastructure correction. No new cases, versions, subjects or patches may be introduced into this cohort after results. Record all job times, failures and actual billing evidence available.

The completed experiment will determine feasibility and characterize this synthetic fixture. It cannot by itself establish Q1 readiness or real-application prevalence. Further publication claims depend on verified prior-art differentiation and independent application evidence.
