# Docker-reported root-layer comparison

The integrated ordinary scenario now inventories exactly every path reported by Docker diff at each runtime snapshot. This covers changed image-layer files beyond the separately inventoried mounted application roots. It does not claim to inventory process memory, unreported mount contents, or the complete unchanged image; the immutable build, full source/dependency inventory, actual topology and registered-root checks remain mandatory.

Retain raw Docker diff, parse only A/C/D entries with unique canonical absolute paths, and inspect those exact paths inside the original container using its Python runtime. Do not recurse into directories or follow symlink targets. Retain kind, mode, UID/GID, nanosecond modification time, file length/SHA256/link count, and literal symlink targets. Retain absent entries and FIFO/socket kinds without reading them. Reject device files, unrecorded extended attributes, over 100,000 paths, input over 8 MiB, or regular-file content over 2 GiB. Recheck file identity/metadata after hashing. Re-read Docker diff after inspection and require the raw response to agree. These observations remain non-atomic; existing quiescence/process-continuity and checkpoint requirements still apply.

Before/after root-layer changed-path membership must agree. Paths within the nine registered roots are handled by their separate complete operation/restart comparisons. Every other path must retain Docker change kind and exact recorded state, with these source-derived startup-only exceptions: pre-existing /etc/passwd, group, shadow, gshadow, subuid, subgid and their trailing-hyphen backup files, plus /etc/.pwd.lock, may change only modification time within the observed startup interval. All account contents, ownership, permissions and other properties remain exact. Ancestor directory modification times may likewise change during startup while their other metadata remains exact. These admissions reflect original user/group setup and separately checked startup file replacements, not a blanket /etc exception.

No supervision-state, executable, certificate-tool installation, log or cache content wildcard is admitted. Unknown added/removed paths, changed supervisor contents, modified application code, or account-content changes fail the comparison. Unexplained changes make qualification unavailable and must be retained; they are not counted as natural defects. The predicate may reject an ordinary runtime. There is no outcome-dependent exception expansion or scientific-input rerun.

Run this comparison across the unchanged warm checkpoint, each intentional restart and every ordinary operation, alongside the existing registered-root/database/credential comparisons. Raw root-layer snapshots and comparison reports are private and use the encrypted retention mechanism. Full qualification remains conditional on successful live execution and the complete parent registration/workflow.
