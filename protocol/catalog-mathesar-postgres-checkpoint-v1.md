# Mathesar PostgreSQL checkpoint implementation v1

Implementation: scripts/extension/mathesar_postgres_checkpoint_v1.py. This is an unexecuted helper for the first registered ordinary qualification job, not evidence that restoration works or authorization to start that job. No new application attempt is allocated here.

Use the registered PostgreSQL 17.12 linux/amd64 image. The fixed service container is study-mathesar-postgres, with network none, role study, database study. The application container study-mathesar must exist and be stopped for every capture, inspection and restore. Reject other live connections to study, additional non-template databases beyond postgres/study, large objects, foreign tables and materialized views. These unsupported states cause qualification failure rather than being omitted.

Capture uses pg_dump --username study --dbname study --format custom. Inspect persisted state before and after capture and require equality. Restore uses pg_restore --username study --dbname study --clean --if-exists --single-transaction --exit-on-error, passing the hash-verified archive on stdin. Keep the same database and cluster; do not recreate cluster roles, change role settings or silently repair database configuration. A discrepancy after restore stops the comparison. Existing unexpected objects not removed by pg_restore remain detectable in the relation/schema inventory.

Compare every non-system ordinary/partition table, enumerating all children and querying ONLY each relation, preserving duplicate rows. Hash sorted row_to_json text with original column values, including sessions, password hashes, timestamps, analytics and maintenance records. Compare sequence last_value/is_called, schema-only dump hash, roles, role membership, role/database settings, database configuration, tablespaces and server settings. No target-field or timestamp exception is allowed. Schema dump comparison removes only its two paired, matching random psql restrict/unrestrict guard lines; these are dump transport tokens rather than stored application values. Unexpected guard format is a failure. Raw dumps stay private on the ephemeral runner; publish table counts and cryptographic digests, not session or credential contents.

The helper checks stopped persisted state. The runtime orchestrator must additionally preserve the same application image/environment, verify analytics disabled and InstallationID absent, preserve the actor's browser session privately, restart the original app without migrations, and record warm/native/API actionability and full request/readback equality. This helper does not clone caches/process state, check browser identity, or establish warm-state equivalence. Its first actual database roundtrip belongs inside the existing ordinary qualification cap. Static syntax checks do not qualify PostgreSQL behavior.

Sources: PostgreSQL 17 pg_dump documentation (https://www.postgresql.org/docs/17/app-pgdump.html) describes consistent single-database custom archives and the separate scope of cluster globals. PostgreSQL 17 pg_restore documentation (https://www.postgresql.org/docs/17/app-pgrestore.html) specifies clean restoration, single-transaction and exit-on-error. The unchanged cluster-global checks are required because the archive does not restore that scope.
