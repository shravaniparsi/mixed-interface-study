# Common campaign bindings and engineering preflight v1

This first common binding set covers fifteen exact pairs across four workflow templates: nine generated RealWorld pairs and six timing-qualified PetClinic controls. Its builder reconstructs corpus review v5 and independently verifies all three relevant runtime archives before collecting source jobs, case specifications, branch order, source profiles and measured cost availability. It selects the later mutation-run API reference once; the earlier control-run repetition does not become another catalog entry. The full catalog remains 75 entries. The other 60 entries, including two singletons, remain explicitly unbound by this interface.

The common preflight creates a terminal-policy-v2 campaign plan and maps each common job to an unchanged, source-qualified runtime job. Case hashes, effective branch IDs, same-workflow/same-producer reference controls, qualified branch order, fresh-reset requirements, source bytes, policy version and timing availability are checked. The planned ordering must match the runtime order already qualified; removing or rearranging entries can require a new ordering qualification and is rejected when those orders differ. Singletons never enter the paired planner.

For registered follow-up jobs, the binder requires the complete initial terminal sequence and the existing policy's actual follow-up plan. It rejects missing trigger evidence, halted sweeps and forged roles or identities. The outer common job carries the repetition and role; the unchanged inner job is a source-specific execution template. Each outer job has a distinct attempt namespace and requires fresh execution. Binding a follow-up does not attest that a repeated application attempt occurred. Retained raw evidence cannot be relabelled as a new repetition.

Costs attached to bindings are verified historical attempt measurements used only to establish measurement availability. They are not timeout predictions, calibration values or performance estimates. Runtime profiles remain separate by source version and cost boundary; no cross-profile pooling is performed. The unknown and missing-evidence generated outcomes remain recorded and do not become clean observations merely because their timing is measurable.

This package is executable planning and preflight code, not a common application executor. Its dispatch authorization and primary freeze fields are always false. The selected subset is an engineering integration cohort, not a reduced primary research population; remaining entries have not been discarded. Next connect these bindings to an executor that retains both outer and inner job identities and fresh-attempt provenance, test that bridge on exposed controls, and extend remaining runtime families. Primary batching, deadline capacity, calibration and freeze remain open. No application run is launched by this preparation.
