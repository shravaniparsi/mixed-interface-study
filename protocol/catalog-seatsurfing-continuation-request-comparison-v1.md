# SeatSurfing complete continuation request comparison v1

This component implements the existing prospective request-matching policy for the fixed scalar-edit workflow. It does not authorize dispatch or establish runtime qualification.

The native worker records a request-ID boundary after observed network settlement immediately before the original scalar edit. Its edit result retains that boundary and the complete settled network observation, including ancillary response capture. The comparator includes every request after that boundary, not only requests to the expected update endpoint. The mapped original scalar-edit branch has no automatic readback or navigation. An extra read, write, asset request, failed request or incomplete capture makes this component unavailable; it is not silently discarded.

The complete main PUT and each source-ordered attribute POST must match method, exact isolated endpoint, the original bearer credential, JSON content type, and every JSON key/value. Requests with cookies are outside the current transport qualification. Each expected native request requires exactly one header observation, response and finished event, and the original ordinary 204 status. Ancillary requests are compared in dispatch order; their response completion order is not required to match. Asynchronously recorded response bodies do not provide a synchronous main-response timestamp, so the comparator does not invent that temporal claim.

The independent API continuation must declare successful independent source-input acquisition, materialize the exact same complete plan, and retain exactly the expected main/ancillary envelopes with original 204 responses, completion timestamps and zero retries. Reconstructing an equal body from native trace data does not satisfy the acquisition requirement. Native and API loading provenance remain distinct. The native main-response observation and complete-payload check must also succeed.

The result establishes complete write-plan agreement only. The additional browser-added transport headers remain retained but unqualified by this component; no universal header-independence claim is made. Actor signature/session/permission verification, source transport review, identical relevant starting state, original warm controls, complete post-state comparison and artifact provenance must independently pass before the enclosing ordinary control qualifies.

Seven synthetic tests cover main/ancillary agreement, extra reads/writes, complete-body differences, missing completion, status differences, bearer/cookie differences, unequal independently generated plans and unsettled/failed observations. They execute no application requests. This component does not increase the prescheduled ordinary controls or the fixed project's attempt budget.
