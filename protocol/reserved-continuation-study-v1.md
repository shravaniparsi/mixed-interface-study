# Reserved-frame continuation comparison v1

## Question and scope

Does native browser continuation reveal operational incompatibility of persisted API-created states beyond immediate HTTP status, request-schema validation, and an equivalent API edit/readback? This is a descriptive comparison of observation methods, not a new algorithm, a selector study, a representative prevalence estimate, or an agent intervention. Earlier studies and exposed development results remain separate. The retired conditional-evaluator novelty claim stays retired.

The fixed frame is all nine evaluation_reserved rows at their existing commits in project-family-partition-v1.json. Preserve all nine and their eight conservative family groups, search ranks, prior metadata exposure and unresolved ancestry. No replacement, expanded search, favorable application substitution or stopping after a positive result. The top-star Angular/Spring topic frame has technology, popularity, tutorial and generator bias. Absence of a prior reference is not proof of independence or absence from model training. If new provenance links a reserved family to development, retain it but quarantine it from independent claims.

Sort paths by UTF-8 lexicographic order and take the first 32 per repository, retaining total candidate counts and the excluded tail. Fetch those components and corresponding same-stem .html files only when present in the tree, plus the first root README and LICENSE filename in sorted order. Each file is bounded at 256 KiB, timeout 30 seconds, no retries, with a total source-collection deadline of 900 seconds; missing/oversized/error records remain. This admits bounded coverage, not all project forms. A source schedule with blob IDs and hashes is published before fetching contents.

A later dependency-only pass may read at most 24 additional files per project: imports/routes/services/build/authentication/configuration needed to bind those candidates, in lexicographic breadth-first order, with each path justified and published before fetch. No issue history, fixes, commit messages, challenge solutions or outcome-guided searches. No traversal beyond the bound. Root documents may incidentally reveal findings; log any such exposure and quarantine the affected workflow. No claims of blinded human annotation.

Choose exactly the lexicographically first source-established resource workflow in this candidate prefix that has native create and edit, a JSON API create and update, a stable readback identity, the same local actor for both routes, and at least two independently editable persisted scalar text fields. Join via explicit service/resource bindings; filenames alone do not establish a pair. Text fields must map unambiguously to top-level JSON properties. Exclude secrets/passwords, identity keys, file uploads, rich text, external-service requirements, and fields with source-required irreversible side effects. Log every candidate disposition. Do not require a validation discrepancy, optional schema field, or predicted defect. Freeze the chosen workflow before build/control execution. ## Methods and shared information

All observations receive the same revision, actor, state reset, ordinary control, producer body and request/response trace; source mapping is shared and disclosed. No frontend-derived constraint is inserted into an API-only baseline.

H: retain producer HTTP status and response body; never equate 2xx with workflow correctness.
S: validate the producer JSON against the original supplied/generated request schema with the already qualified OpenAPI/jsonschema environment (openapi-schema-validator 0.6.3, jsonschema 4.26.0, Python 3.12.13). Select the original operation and resolve local references; do not synthesize missing constraints from UI/source. Missing specification, unresolved references, unsupported dialect and validator errors are separate unavailable outcomes. Record specification hash, dialect and request serialization. Report Python-regex semantic limitations rather than claiming arbitrary ECMA/Java regex equivalence.
A: after API create and readback in a fresh reset, perform the equivalent direct API edit, then read back ID and fields.
U: after the identical API create and readback in a separate fresh reset, load the native editor, make the same unrelated edit through ordinary controls, save when enabled, and read back ID and fields. Do not force-enable controls, inject form validity or silently repair data.

Freeze each adapter's ordinary create/update bodies, input-to-field mapping, readback projection, identity binding, selectors and default handling before variant execution. A's update serializer must follow the source-established native update mapping from readback values, preserving the target condition. Ordinary U traffic must qualify that mapping. If native serialization/default behavior cannot be established, report A/U equivalence unresolved, not U-only detection. No code changes after variant outcomes; unsupported cases stay unsupported. The original native UI is the continuation under test, not a mocked frontend. These are explicit baseline definitions, not claims to run RESTler, AutoBypass or another published tool.

## Fixed inputs and execution

Select the first four eligible mapped text properties in lexicographic order (or all if fewer). Preserve a valid ordinary body from native create. For every selected property use exactly omission and explicit null, singly, plus one unchanged control. At most nine cases per workflow. No length/regex boundary additions after outcomes. For each case, the unrelated edit uses the first different eligible property, with its value frozen from an ordinary native successful edit. No inferred requirements from error-message branches or nonNullable options.

Run A and U in separate fresh databases/application contexts, each with one API producer. A rejected producer ends that branch; it does not earn downstream coverage. Non-2xx may have side effects, so no claim of absent persistence follows without observation. For accepted producers, require readback and compare stored fields across branches before crediting a paired comparison. Normalize only identity values generated independently by reset; retain all other differences. If state differs, report unpaired/unresolved.

When U Save is disabled after the unrelated edit, a prespecified diagnostic may restore only the varied field to its ordinary value, then attempt one native save and readback. This follows the unrepaired primary observation and does not replace it. It provides within-case repair evidence, not randomized causal proof. Record other fields and any normalization. No additional mutation or rerun selected by the outcome.

Before experimental cases, qualify ordinary native create/edit and API-create/native-edit plus the API serializer on the chosen workflow. Per project allow one build/control attempt and at most one explicitly versioned infrastructure-only correction before any variant outcomes, retaining both. No application validation changes. Publish immutable binary/environment IDs and adapters before the experiment. A project-specific execution freeze is required; this protocol alone is not permission to run unspecified adapters.

## Bounds, analysis and stop

Source admission covers all nine projects regardless of earlier findings. Free standard public Actions only, no paid model/service calls, no larger runners; the existing $100 ceiling remains. Builds/ordinary-control qualification: at most two 30-minute jobs/project. Scientific measurement: at most 18 fresh branches/project, 15 minutes each, max three concurrent jobs; one scheduled execution per branch. Record runtime, setup, observer work and service billable metadata separately. Never convert zero reported billable_ms into an audited total-project dollar invoice. Application/browser traffic is isolated from public services; dependency downloads precede runtime isolation. Never execute candidate package lifecycle scripts locally.

Primary reporting is the complete project/family disposition table and, among accepted paired states, A/U outcome overlap: both complete, only A completes, only U completes, neither completes, unresolved. H/S classifications are explanatory strata, not ground-truth defect labels. Retain rejected, not-run, timeout, unsupported and unpaired cases with full denominators. Count workflows/families separately from correlated field/operator variants. Requirement violations need the independent-api-obligation-evidence-v1 policy; otherwise label only observed operational incompatibility. No p-values or population confidence intervals from this convenience sample.

A pragmatic minimum for a multi-project descriptive interpretation is four qualified workflows from four non-quarantined family groups; this is a feasibility threshold, not a power calculation or guarantee of journal adequacy. Below it, report feasibility only. Finish the fixed frame whether results are positive or negative. No minimum number of defects is required, and no additions seek a positive result. After closure, judge novelty, baseline increment, provenance, reproducibility and independent evidence; a null result or insufficient coverage may leave no defensible Q1 submission. Original selector/agent questions remain unanswered by this study.
