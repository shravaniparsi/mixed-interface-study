# GitLab source-derived input inventory v1

## Scope and freeze

Freeze 24 producer input specifications across the four GitLab families with documented producer and continuation operations. This is an analyst-selected, bounded API-contract sample, not exhaustive schema coverage or 24 independent defects. It precedes frontend-validator and evaluator inspection and application startup. Runtime validity, native representability, fixture binding and task compatibility remain qualification outcomes. The selection of six specifications per family is a resource bound, not a power calculation.

Each family has four common specifications: omit description; send an empty string; send `Continuation study`; send `Café 東京`. The remaining two specify false and true for initialize_with_readme (both project families), confidential (issue), or squash (merge request). Change one optional field from the ordinary producer at a time; do not form a cross product. Optional does not imply nullable. No null, undocumented sentinel, invalid type, invented maximum, or undocumented default is introduced. The empty string is a type-compatible candidate, not a claim that documentation guarantees its acceptance. All rejected inputs remain in the denominator.

Required payload bindings come from the fixed benchmark representative and an isolated fixture. Project name and path preserve the task identity; visibility preserves an explicit task requirement. Issues retain the requested title; MRs retain the requested source and target branches and a fixed qualified title if unspecified. Omit assignee/due date and reviewers at production because they are the specified continuation. Describe this sequential decomposition as an adaptation where the native create form can perform both actions together. Resolve and freeze all concrete bindings before scientific dispatch; unresolved placeholders are not executable cases.

## Interpretation strata

Initializing a README before a task that requests README creation changes the resource lifecycle. Retain that specification as a lifecycle control; do not silently switch the continuation to update and report original-task failure. Explicit false and omission must be compared by readback, not assumed identical. Confidentiality and squash are semantic settings that must be matched across channels and preserved; an expected access restriction is not a defect. Description variants are adapted task inputs when the benchmark leaves that field unspecified. This study therefore uses benchmark-derived tasks, not original benchmark scores.

The directory family remains unresolved: the inspected file and commit APIs document file actions, not an independently persisted empty-directory producer. This is limited evidence from these documents, not proof that no endpoint exists. No placeholder file surrogate is allowed. Reddit remains unqualified pending version-matched API identification. Neither family is replaced.

## Baseline requirements

For every qualified specification use separate fresh fixtures for native producer/native continuation, API producer/native continuation, and API producer/API continuation. Match actors, roles, initial objects, branches and logical producer fields. Record any native-unrepresentable specification separately; do not impute a successful native baseline. An ordinary control must pass before a family enters scientific execution.

Before continuation, read back name/path/visibility/description and repository contents for projects; title/description/type/confidentiality/assignees/due date for issues; title/description/source/target/squash/reviewers/state for MRs. Also capture relevant permissions, feature availability and namespace membership. Compare logical values while recording generated IDs and timestamps separately. A producer mismatch is its own outcome and cannot be attributed to continuation.

API continuation projections: repository file creation requires project ID, encoded file path, branch, content and commit_message; issue update requires project ID, issue IID, assignee_ids and due_date; MR update requires project ID, MR IID and reviewer_ids; project membership requires project ID, user_id and access_level for each requested existing user. Resolve role choices from task requirements or freeze a disclosed adaptation. Retrieve external README content independently and freeze it before scientific runs. These are complete required operation projections, not a promise to send every optional attribute and accidentally overwrite preserved state. Grant the same relevant contract and shared constraints to all baselines.

Record HTTP request/response, native action and error, pre/post persisted state, expected changes and preserved fields. Producer rejection, fixture failure, native unrepresentability, lifecycle restriction, task incompatibility, baseline-covered difference and requirement-backed defect are distinct outcomes. An incremental detection requires failure missed by the competent API continuation and shared checks, plus matched-state counterfactual evidence.

## Remaining gate

This inventory freezes input specifications only. It authorizes no scientific execution. Concrete content/actors, authentication, isolated reset, native controls, instrumentation, repetition/order, cost cap and stopping rules must be registered before dispatch. Runtime qualification is a separate bounded engineering job, and its exposures must be retained. Do not add or replace specifications after outcomes.
