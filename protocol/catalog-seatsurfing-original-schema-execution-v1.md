# SeatSurfing original schema compilation and execution preparation

Extend the registered source-build component to compile the existing original Go schema probe in a separate image. The original application image remains unchanged. Bind the probe source hash in the eventual qualification registration. Verify the actual server/healthcheck build-stage go.mod/go.sum identities against the frozen checkout, as well as verifying the host checkout; a clean host tree alone cannot establish that the stage copies stayed unchanged.

Use the exact inspected local original server-builder image as the schema build parent. Copy only the study's previously published main.go probe and original go.mod/go.sum reference bytes into a separate context. Compile with the original Go toolchain and module under `go build -mod=readonly`, with the RUN network disabled and the same BuildKit module/compiler caches already populated by the original server build. Do not install dependencies, update versions, extract a weaker schema or alter original validation code after failure. Compare stage go.mod/go.sum bytes to the frozen originals after schema compilation. Registry metadata resolution is Docker build behavior; the network restriction applies to the compiler RUN, not a claim that the build engine never resolves image metadata.

Copy the compiled probe into a separate image based on the original pinned distroless final base, user 65532:65532, with the probe as entrypoint. Verify image identity/configuration, extract the probe from a stopped container, hash it and retain Go build information. The schema build has at most 180 seconds under the existing shared 1,080-second build deadline; it is not a new unbounded build job. Failure preserves the original attempt. The build report records `compiled_not_executed`, image/binary/source/recipe hashes and runtime_qualified=false. Compilation does not execute ordinary or altered inputs.

The coordinator-only execution helper accepts a successful same-commit build report and one exact byte input up to 65,536 bytes. It verifies the recorded probe source and image identity, refuses an existing schema container/result path, and launches one labelled container with network=none, restart=no, read-only root, 256 MiB/one CPU and a twenty-second observation deadline. It passes the bytes unchanged via stdin. The probe imports the original router.CreateLocationRequest and UnmarshalValidateBody; no handler, UI validation or persistence call is added by the probe itself.

Retain stdout/stderr, exit status, input hash and schema identity privately. A valid original structured result records accepted/rejected plus decoded model/error. Nonzero exit, initialization logs/errors, malformed/oversized output or timeout is an instrument/unavailable outcome, never a schema rejection. Timeout preserves partial evidence and explicitly records that the same container may still run; the parent observes/stops it, retains evidence and never resends the input. Do not use --rm or silently recreate it. The parent owns teardown and evidence sealing.

S covers original JSON decoding and declared validation tags only. Authentication, procedural timezone/group checks, handler behavior and persistence remain outside S. The complete qualification registration must prescribe the ordinary S check before altered scientific inputs; no execution is authorized by this component preparation. An ordinary S failure ends qualification under the existing rules, without replacing the schema baseline.

Validation here: five synthetic command/report tests using mocked subprocesses, Python compilation and the existing seven build guards. No Go compiler, Docker, application, schema input or scientific experiment executed. The original probe remains uncompiled until the fully registered qualification job runs.
