# PetClinic terminal extraction v2

This stage replays the twelve source-qualified integrity-control observations as six terminal pairs. It adds no application execution and does not qualify a new dispatcher, branch order, deadline or process lifecycle. The historical runner, validator, component reducer and artifacts remain unchanged.

The new evidence validator preserves registered commands, returned identities, parent relationships, native form bindings, request/response accounting, readable pre-candidate state and confirmed owned-backend exit. It separates two completed observations from those execution conditions: native submission disabled after loading the intended target, and a readable changed owner/pet/visit graph after a rejected producer command.

A completed native block requires the recorded disabled state, the registered edit intent, no PUT, complete native capture and unchanged target/relationship readback. The existing component reducer assigns the disabled-submit predicate to the native continuation. A readable rejected-state change must agree with the recorded graph and its direct read trace; it is a shared state observation and cannot create native-exclusive detection credit. Unreadable state, inconsistent verdicts, missing capture or command/identity evidence remain incomplete. Unknown assertions remain unclassified execution failures. Unexpected prefix statuses are outside this version's qualified extraction selection and halt; no clean rejection is inferred from an arbitrary non-201 response.

Pair comparability requires correct API/native consumer labels, the same anonymous actor, the pinned initial graph, distinct owned backend processes, the same pre-candidate graph, producer command/status, post-prefix graph and intended edit. Incomparable pairs remain incomplete and repeat eligible under the common terminal policy. Missing evidence or unconfirmed cleanup halts. Signatures retain predicate verdicts and HTTP statuses, while raw records retain their complete identities and graph values.

The archive loader first checks the historical artifact hash inventory and the pinned historical component qualification. It uses the archived cleanup schema exactly: successful runner exit and the recorded frontend termination exit, with confirmed direct-child exits. This is not a claim of detached-descendant absence. Pair IDs are explicitly archive replay identifiers, not newly executed job IDs. No historical branch order is relabelled as a new campaign schedule.

Seventeen tests cover the twelve archived controls, blocked-native fixtures for all three workflows, changed rejected-state graphs, source/capture/intent tampering, backend reuse, cleanup precedence and raw-record preservation. Negative fixtures are not live application findings. Next is immutable per-job dispatch and source-qualified loading of fresh control runs. P2 and the primary freeze remain open.
