# SeatSurfing joint stopped-runtime checkpoint component

Preparation only. Coordinate the existing PostgreSQL checkpoint with the native browser storage snapshot, immutable JWT key files and verified source-build report. No application/browser is started or stopped by this component. Before invoking it in a later registered job, the worker must retain live settled-network, actor, token-lifetime and stop observations; booleans in an observation file alone do not establish those facts. Bind the actual captured storage hash and complete network-trace identity. Unmapped browser state, including sessionStorage/workers or mutable browser state not represented by storageState, prevents qualification until explicitly supported.

Require the stopped application to carry the disposable SeatSurfing fixture label, match the built image, have a read-only root, no tmpfs or extra mounts and no restart policy. Bind only the fixed private/public signing-key files, read-only, at /run/study-private.pem and /run/study-public.pem with matching JWT environment paths. The PostgreSQL helper now also requires the same disposable-fixture label on application, database and browser; its existing exact image/network/session/version checks remain mandatory.

Capture creates a new private directory, captures the database, and writes the exact native storage, signing-key bytes, build report and observation alongside hashes and the database-baseline identity. Preserve all captured storage fields, including cookies and any included IndexedDB, without rewriting credentials. Reject foreign origins/cookie domains and duplicate localStorage keys. This component does not infer that browser memory is fully captured.

Before database restore, verify all retained bundle members, original container identity, origin, build report, unchanged keys and database-baseline hash. Changed fixed keys cause failure; do not generate replacement keys or silently log in again. Restore the database through the existing atomic pg_restore/equality check, then return the exact validated storage path for the future new browser context. The output explicitly says the browser context has not started. Final image/key/stop guards are rechecked. There is no claimed cross-resource transaction: a failure after database restore must retain its database report and remain unqualified.

The future coordinator/worker must still demonstrate application restart, startup-side-effect checks, restoration into a fresh browser context, actor and token continuity, complete ancillary trace and warm-versus-restored ordinary equivalence. This private bundle is insufficient by itself. All keys, tokens, reports and dumps require sealed-artifact retention; do not publish plaintext bundle files.

Seven synthetic bundle tests and eight synthetic database-guard tests run without Docker, PostgreSQL, browsers or network. They check identity/integrity rejection and stop/isolation guards, not actual recovery. An enclosing CI recipe and workflow/input freeze are required before any runtime invocation.
