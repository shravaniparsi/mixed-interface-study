# Source-aware replay comparator D: design gate

Prospective comparator specification, not an evaluation registration or a finding of novelty. The original mixed-interface workflow question remains open. This document does not reopen closed schedules or authorize paid model calls.

## Shared evidence and observation

C (conditional transfer) and D (native-source replay) receive the same pinned frontend source, API/task documentation, explicit source-to-model mapping, transformation/defaulting rules and operation/actor/lifecycle context. Both start from the same recorded API state or request and reconstruct the same consumer model at the same registered point. Neither receives held-out issue fixes, correctness labels, extra defaults or privileged field-state information. C's access to active/materialized field facts has to come from a reproducible acquisition process whose cost is charged to C; caller assertions in the development adapter are not that process.

The baseline loads original supported validators and schema into their pinned actual framework runtime, reconstructs the model using only documented/qualified transformations, and observes native validation status. It does not flatten frontend constraints into global API requirements. If an actual field is absent, a mapping is ambiguous, a transformation unsupported, runtime setup fails, or needed remote/async behavior is unavailable, record the corresponding unknown/error outcome. Do not treat a missing field handle as a passed field, or suppress it by adding a default. The comparison needs ordinary valid inputs and legitimate interface differences as well as candidate violations.

## Qualification and fairness

The48-row Angular development grid provides36 measured per-rule observations and12 access failures, not an end-to-end qualified D implementation. A production-source adapter must load the original schema (including all applicable custom rules) rather than recreate selected validators from C's lowered representation. Native field-state semantics are evidence of what the frontend does, not automatically what the API should require. Both methods still require independent task/contract evidence to label defects.

Use one shared mapping/input reconstruction implementation where feasible and report its cost separately; otherwise freeze each method's acquisition and budget. Do not give C manually curated mappings while making D rediscover them, or charge D runtime preparation while excluding C's source extraction and framework qualification. Compare outcome accuracy/coverage at a fixed evidence budget, and total setup/acquisition plus evaluation cost. A cached single-project microbenchmark cannot establish project-level setup savings. Report unsupported projects in the full frame, not only those successfully installed.

The OAS-only comparator A remains separate. Native RBCTest response-body mode is not interchangeable with request-validator replay; an adapter must retain that distinction. No status-code-only baseline substitutes for a competent logical oracle. B, direct unconditional transfer, remains an ablation, not a claim of state-of-the-art comparison.

## Primary comparison and rejection conditions

C versus D asks whether acquired conditional predicates provide useful accuracy/coverage/cost tradeoffs over replay using matched information. Identical outputs are a legitimate result. C losing coverage because it lacks field materialization is a cost, not a precision improvement. C cannot claim efficiency if its field facts require an uncounted replay for every input. If both implementations need the same framework execution and differ only by redundant predicate evaluation, there is no demonstrated computational advantage.

Report per-project counts and cluster-level uncertainty only after selecting the independent frame and effect target. Payload variants and repeated executions are not independent projects. Keep acquisition failures, unresolved labels, abstentions and evaluation errors in distinct denominators. Do not infer intended-behavior false positives merely from disagreement between frontend and API implementations.

Before corpus collection: implement a source-schema replay adapter, identify an observable acquisition distinction for C, establish independent labels for interface obligations, and register an external sampling frame plus all-in costs. The current development work satisfies none of those gates merely by passing regression tests. If no method distinction survives this comparison, stop the new-algorithm claim; do not weaken D or change the study goal to the easiest positive result.
