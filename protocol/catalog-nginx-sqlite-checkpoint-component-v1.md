# AccessList SQLite checkpoint component

This is an unexecuted component specification, not a runtime dispatch or full application checkpoint. Use only the integrity-verified application dependency better-sqlite3 13.0.3. The helper opens the source database read-only, captures a transactionally consistent typed schema/table inventory, invokes the original driver backup API to a new private file, and compares source-before, source-after and backup logical state. No table, audit row, internal sequence or timestamp is omitted. It preserves INTEGER versus REAL versus TEXT versus BLOB versus NULL and duplicate rows. Unsupported result types fail.

Prospective component bounds: 2,000 schema entries, 100,000 rows, 32 MiB encoded row content, 64 MiB backup pages, 5-second database lock timeout and 20-second backup deadline. These are failure bounds, not sampling or row truncation. The enclosing qualification job must enforce its original 30-minute limit and per-command timeouts. Existing destination files are rejected; partial failed backups remain failures, not resumed checkpoints. No source mutation, VACUUM, schema rewrite, disabled constraint or copied producer body is used.

The component must be qualified with the actual installed driver/version and application fixture. Local encoding tests only verify representation, not a live backup or restoration. A complete checkpoint must additionally coordinate generated files, keys, browser tokens, daemon activity and warm/restored starting-state comparison. The component alone cannot establish any of those. Restoring a database is a separate operation that must run with application writers stopped and requires its own checked recipe before execution. Keep complete database evidence private because it contains authentication and account data.

Design references consulted 2026-11-18: [SQLite Online Backup API](https://www.sqlite.org/backup.html) documents snapshots of a live database. [better-sqlite3 backup API](https://github.com/WiseLibs/better-sqlite3/blob/master/docs/api.md#backupdestination-options---promise) documents asynchronous backup completion, restarts when another connection writes, and cancellation by closing the source or throwing in the progress callback. These current documents guide the design; they do not prove behavior of the as-yet unexecuted pinned driver or application.
