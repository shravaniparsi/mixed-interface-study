# SeatSurfing native browser bridge and launch helper

Prepare a private JSON-lines bridge and a coordinator-only launcher. These components do not dispatch a qualification job or define its complete ordinary scenario. The future coordinator must bind their hashes in the published qualification registration and establish the build, fixture, actor, loader and state-comparison prerequisites before scientific inputs.

The bridge launches exactly the supplied process once, checks the pinned native worker's ready message including mode/browser version/runtime-unqualified flag, and sends at most six unique command IDs. A command has one original deadline, no longer than ninety seconds; startup has one forty-five-second deadline. A shorter read observation timeout leaves the same process and command pending. It permits observation of that same command within its original deadline, never a resend or replacement. A terminal worker/protocol failure or original deadline expiry prevents subsequent commands. Explicit close is cleanup, not a retry.

Worker stdout carries only private artifact references and hashes. Require exactly the request-ID-derived result filename, a SHA256 match, a regular non-symlink file within the private result directory and a JSON object no larger than 32 MiB. Reject path traversal, substituted symlinks, missing/duplicate response identity and hash mismatch. Retain original stdin requests, stdout, stderr and status under a fresh private directory. The original stream limits remain two MiB per response line and sixteen MiB total stdout. The enclosing job must also limit stderr/disk/process resources. Files may contain synthetic credentials and record content; seal them before any remote artifact retention and do not publish them raw.

The launch helper requires the same-study-commit successful original build report, running labelled original application and pinned PostgreSQL, and the recorded browser image configuration/platform. PostgreSQL must be network=none; the application must share its namespace. Refuse an existing browser container: only the outer coordinator may explicitly retain/stop/remove a prior registered branch after its required checkpoint checks. Never delete or replace a pending worker to resolve a timeout.

Launch the browser with the pinned image, label, network=container:study-seatsurfing-postgres, restart=no, 2 GiB/two CPU limit, 512 MiB shared memory, read-only root and 512 MiB writable /tmp. Set TZ=UTC. Mount the study checkout and browser tools read-only, exactly one private configuration file read-only, and one dedicated writable evidence directory. In a restored branch, verify the exact saved storage hash and mount only that file read-only at the absolute path recorded in configuration. Do not mount the signing keys, database or entire checkpoint directory into the browser. Launch the original native worker with Node; it independently checks Node, Playwright and Chromium identities.

Do not use docker --rm: on explicit bridge close, the worker receives EOF, retains its final trace and closes Chromium, leaving the stopped container for checkpoint inspection. The parent owns Docker-container teardown, application pause/stop and database capture/restore. It must keep the warm worker alive while pausing/resuming it and must establish full joint restoration before invoking a new restored worker. The launcher explicitly does not claim joint restoration from a matching storage hash.

Validation: nine local tests using real pipes and a fake Python worker, plus pure Docker-command construction. They verify exact artifact loading, timeout/pending-process preservation, no duplicate resend, no resend after the original deadline, hash/path/symlink rejection, pinned isolated launch parameters and single-file restored storage mounts. No Docker command, browser, application or scientific input ran. Actual container launch and ordinary equivalence remain unqualified.
