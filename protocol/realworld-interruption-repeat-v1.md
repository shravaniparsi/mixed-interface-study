# RealWorld interruption and repeat qualification v1

The supervised entry point owns the unchanged paired runner in a new process group. SIGTERM and SIGINT unwind through bounded group cleanup and preserve a cleanup sidecar. Historical adapters, validators and archived results remain unchanged. The direct, unsupervised entry point is outside this qualification.

The Linux hosted harness registers three sequential stages before execution. The first receives SIGTERM after an API control has completed while a native-continuation adapter and Chromium descendant are alive and both ports 18765 and 18766 listen. The wrapper must exit with code 143 within 18 seconds. Within four further seconds, no observed descendant identity may remain live and neither port may listen. PID plus process start time governs descendant identity. Rescue cleanup is recorded and fails qualification.

Two separate complete runs follow, each with a new fixture, output directory and all fourteen registered branches. Both require the unchanged source, normalization, integrity and timing validator to pass. Their branch schedule, actors, prefix and final business state, check verdicts, guard verdicts and declared HTTP outcomes must agree. Generated slugs and server timestamps are excluded only from cross-attempt business-state comparison; within-branch binding checks remain mandatory. Timings and raw evidence hashes are not required to agree. These repetitions are not independent research samples.

The incomplete interrupted attempt is retained and never resumed or merged. This establishes behavior only at the observed checkpoint, not every startup, write or cleanup phase. It does not qualify failure-repeat scheduling for mutation candidates, selector calibration or the primary experiment freeze.
