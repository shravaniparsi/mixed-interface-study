# SeatSurfing isolated ordinary API worker v1

This is coordinator preparation, not an application dispatch. The fixed input schedule, project attempt cap, budget and scientific-case count remain unchanged.

The parent launches one API operation in the already isolated PostgreSQL/application network namespace using the inspected pinned Playwright image's Node 24.18.1 runtime in UTC. The worker has a read-only root, 512 MiB memory and one CPU. The API and native browser launchers use the host runner UID/GID so their mode-0600 evidence remains readable by the coordinator; the containers receive no host privilege escalation. Its mounts expose the study source read-only, precisely one configuration file and one captured browser-storage file read-only, and one fresh private evidence directory. It receives no database password, JWT signing key, host network, published port or Docker socket. Application/database image and ownership, running state, namespace, build preparation and executing study commit are checked before launch.

The worker verifies the exact browser-storage hash and one original origin, rejects duplicate local-storage keys, and derives the original access token and expiry from that storage. It never logs in or refreshes. Nonempty cookies fail this transport component because no cookie mapping has been qualified. The storage capture itself still requires original token identity, empty session and Cache Storage, and no additional pages or workers. A once-only `session_storage` native command captures credentials immediately after login without changing the native worker phase. This is separate from the later editor checkpoint capture. The complete native sequence remains six commands: login, session storage, native create, open API target, editor capture, warm edit.

The one-shot worker permits only frozen ordinary creation, independent source-defined loading, or continuation with one of the two frozen unrelated edits. Loading uses fresh API GET responses and never fabricated native traces. The API's own request and response evidence remains private. The Node process has an 85-second hard deadline; the parent has a 95-second deadline. No observation failure or partial mutation is retried. Original per-request bounds still apply. A timed-out container can remain running until the parent explicitly stops and retains it; timeout is not HTTP rejection.

Each operation has a distinct fixed container name and new evidence directory. The helper refuses existing names or output paths and leaves its container for explicit parent retention/cleanup. The parent must not reuse an operation to obtain a different outcome. Two prescheduled ordinary fixture cycles may reuse names only after the entire previous fixture has been retained and torn down. A successful result binds operation, exact configuration hash and storage hash; it does not establish HTTP success, persistence, browser-header equivalence or scientific qualification.

Five synthetic Node tests cover credential/storage binding and operation selection. Six mocked Python tests cover isolation, result binding, namespace refusal, storage tampering and timeout behavior. They launch no containers. The native worker syntax check and existing SeatSurfing Node tests also apply. Full coordinator integration, actor verification, request/ancillary comparison, evidence sealing and prospective workflow registration remain required before the first qualification attempt.
