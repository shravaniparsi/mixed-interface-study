# Infrastructure feasibility extension v1

This is a prospective extension after closure of the original nine-project frame, not a correction to its results. The closed frame and all exclusions remain unchanged. The preceding turn made progress by archiving the Booklore timeout and publishing complete-frame disposition; no application comparison was measured.

First stage: one Ubuntu24 standard public Actions job, at most 15 minutes, using the unchanged pinned installer and Node20.20.2. Increase only its installation deadline from 240 to 600 seconds. No automatic reruns, alternative browser, dependency-version change or application execution. Preserve installation output, package lock, executable identity, local browser smoke result and runner metadata. If installation fails, stop this extension's first stage and retain that outcome. A passing local form submission is infrastructure evidence only.

Smoke check: start an ephemeral loopback HTTP server serving one text input and a native submit button. Launch the measured Chromium via the pinned Playwright package, fill the input and click submit normally, and verify the server received exactly one POST with the fixed value. Deny requests to non-loopback origins. Close the browser and server; retain version, status and elapsed time. No application credentials or Docker credentials are needed.

Only after this preflight is assessed may a separate execution freeze be published for infrastructure-only recovery of original workflows. Eligibility is established now: original build succeeded and controls never reached application resource writes because of harness installation/readiness failure. This includes Booklore and Kanban, excludes Celerio's frontend compilation failure and all source-scope exclusions. Both eligible rows must be retained regardless of outcome; no selection by suspected validation discrepancy, new candidate component or extra source read is allowed. Each would receive at most one additional 30-minute qualification job, specified before dispatch. Their original failures remain in the primary denominator; extension outcomes must be separate. No variants are authorized by this preflight protocol.

Even two recovered workflows cannot satisfy the original four-family feasibility threshold. Any later expanded study requires its own outcome-independent frame and frozen baselines. No claim of Q1 readiness follows from successful infrastructure. No paid services, larger runners or model calls; the existing $100 ceiling remains. Service timing metadata is recorded separately from actual invoice costs.
