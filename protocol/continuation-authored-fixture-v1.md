# Authored browser observation qualification v1

This is development qualification, not an independent-input study or a reopening
of any closed project. No natural defect, algorithmic advantage or Q1-readiness
claim can follow from its engineered outcomes. The existing cohort protocols
and stopping limits remain unchanged. Publish this protocol, all fixture code,
nine-case schedule, dependency lock and hash manifest before any runtime run.

Run once on standard free ubuntu-24.04 GitHub Actions, Node 20.20.2 and Playwright
1.62.1/its installed Chromium. Twelve-minute job cap; one dispatch for this
version; no automatic rerun. Installation and execution happen only on the
runner. No paid model, image pull, external application, real account or external
browser request. Record runner/runtime identities, complete case observations,
request traces and synthetic state files. Any job/setup failure remains a failure,
not a semantic result. Normal dependency installation precedes local fixture
startup; all browser traffic is limited to the fixture's loopback origin.

cases.json freezes nine ordered cases and expected outcomes. Native ordinary
creation uses the real form and Save button; API creation uses JSON. Each case
gets a new browser context and reset JSON file. The independent file read after
production establishes fixture ground truth separately from HTTP status. The
native editor has required Title and independent Description inputs. Continue
only by filling Description with the fixed value and clicking Save. Do not
force-enable buttons, bypass browser validity or programmatically submit.

Cases: native ordinary, API ordinary, backend rejection of null, normalization
of null, accepted null blocked by required native Title, removed browser actor,
competing version increment, unintended title write, unavailable API readback.
The classifier receives observations and the supplied producer title, not the
fixture mode or expected label. It retains status, native invalid events,
native POST count and full API readbacks. Validity inspection is read-only;
its emitted invalid-event counter is cleared before the ordinary click. The
blocked-submit observation window is fixed at 500 ms. This bounded window is
fixture-specific, not a sufficient universal absence-of-request test.

The stale case performs the prescheduled version increment after form load and
before Save; it is a known competing write, not assumed equal starting state.
The missing-observation case intentionally makes the API reader return 503;
file ground truth cannot silently fill that measurement channel. Authentication
failure is distinct from browser validation blocking. Preserve unsuccessful
rows and full evidence; never omit them from qualification counts.

A second, Python-only pass applies write_observations_v2 and the existing
write_contract checker to captured values. Description is the declared intended
assignment, version increments are the declared derived assignment, all other
fields remain protected. This pass checks that successful ordinary/normalized
writes preserve the declared frame and the extra-write fixture fails it.
Snapshots are not restarted/restored; restart remains not_planned. No claim of
real application checkpoint qualification or native/JSON payload equivalence.

Passing requires all nine observed labels to equal the prespecified labels and
the independent frame checks to pass. It qualifies only this authored evidence
path. Failure stops this version and requires diagnosis, without replacing or
hiding the failed run. Any further development version needs a separately
published change and bound before dispatch. No new independent cohort is
selected or authorized by this fixture.
