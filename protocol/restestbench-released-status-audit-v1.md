# Released result status audit

This offline qualification audit follows the source-exposed synthetic scoring probe. It is not a new defect-discovery evaluation. Before inspecting result bodies, selection is fixed to every execution_results.json and evaluation_results.json under results/runs/results_1, results_2 and results_3 at RESTestBench commit 4decc1e36ea3dd41b64ce3e3ac6a85bc72df36ae. Three untruncated Git tree inventories identify 720 files (360 execution and 360 evaluation files). All selected bytes must match their Git blob identifiers.

First count the exact executor message `Mutation could not be applied`, preserving matching sources and a complete file-level inventory. A zero count establishes absence of this exact recorded status only; it does not certify successful mutation application, all execution semantics, or published rankings. Positive matches require joining valid-run and evaluator records before estimating score impact. No aggregate ranking correction will be inferred from text matches alone. Backups, generated tests and model traces are outside this status screen. This scope is fixed before the result scan, after learning directory sizes and file counts. No models, services or generated tests are executed.
