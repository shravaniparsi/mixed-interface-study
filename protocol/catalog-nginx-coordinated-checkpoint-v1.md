# Coordinated checkpoint component, runtime unqualified

This component has not run on an application and does not authorize dispatch. The full ordinary qualification recipe remains pending. It joins the existing original-driver backup, paused filesystem capture, stopped-container guards and verified SQLite byte restoration.

Capture requires a live caller callback providing retained observation identity, settled browser and application operations, verified empty certificate fixture and settled initial timer, unchanged token and a refresh interval outside capture. The component validates the proof structure; it does not establish these facts by itself. Capture backs up with the installed original driver, pauses the original application, copies both mounted trees, retains Docker metadata/root-layer differences, resumes the same process and compares full logical database state against both the backup and paused raw copy. It does not start a replacement warm process.

Restoration prevalidates both trees and the standalone backup before stopping the original container or changing either destination. It restores mounted files, replaces the database and removes only the previously validated SQLite sidecars. Full logical inspection uses a byte-identical private copy of the restored standalone database, with its directory writable for SQLite auxiliary files. Original database and inspection-copy hashes must remain unchanged. The application remains stopped throughout; partial failures do not trigger startup or a retry.

SQLite permits read-only WAL database access when sidecar files exist or can be created. This motivates the writable private inspection directory rather than changing the restored application's journal mode. Source consulted 2026-11-18: https://www.sqlite.org/wal.html (read-only databases). This documentation does not establish compatibility with the installed driver; that remains a runtime gate.

All raw outputs are private, including database rows, Docker environment metadata and filesystem state. No application restart, full root-layer comparison, actor equivalence, ordinary continuation or scientific case is implemented by this component alone. Seven local tests with mocked Docker/driver/filesystem operations cover unsettled capture, copy failure, corrupt second-tree and backup rejection before stopping, partial restoration, logical-state mismatch and the successful stopped/unqualified status. Lifecycle commands use the captured immutable container ID rather than a reusable name. These tests establish failure sequencing only; actual Docker/driver/filesystem coordination remains untested. The existing two qualification attempts and 30-minute bound remain unchanged.
