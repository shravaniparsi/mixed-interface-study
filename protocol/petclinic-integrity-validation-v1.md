# PetClinic execution-integrity controls v1

This prospective engineering regression executes six previously examined candidates, once through each continuation channel, from an independently restarted seeded backend. The selection manifest fixes order and expected prefix status: three positive candidates and three HTTP 400 rejection candidates, twelve branches total. It adds no new boundary observations or independent study sample.

The hosted environment builds the unchanged backend and frontend commits in the registered candidate manifest and runs their native test suites. A rebuilt jar has its own recorded hash; it is not assumed byte-identical to the earlier local jar. Before starting application branches, archive the runner, helpers, registry, selection, workflow and protocol hashes, bootstrap report and runtime/browser metadata. A fresh output directory is required. No automatic retry, partial replacement, resumption or cross-attempt merge is allowed.

Positive branches must pass exact submitted-command checks and ordinary entity/relationship preservation assertions. Pet continuations check the returned ownerId; visit continuations resolve the returned petId and its ownerId. Native form checks cover all displayed editable fields and the pet owner's name. Native PUTs must match the same intended complete payload as their API comparator. Browser responses must be fully captured before context shutdown, with matched request metadata and no capture errors. Backend termination uses a five-second graceful deadline followed by a two-second forced-exit deadline; an unconfirmed exit invalidates the branch. Full browser-descendant cleanup qualification remains separate.

Immediately before each candidate POST, after any valid setup resources exist, record the complete owner graph. A rejected prefix must leave this readable graph unchanged and execute no continuation. Comparison retains owner, pet and visit values and relationships. HTTP 5xx is recorded separately as prefix_server_error, never folded into ordinary rejection. Graph equality covers this API projection, not database atomicity or unobserved resources.

The suite has a 480-second outer deadline plus twenty seconds termination grace. Failed attempts and their sources remain evidence. Postflight requires all twelve ordered branches, matching initial and post-prefix pair states, applicable passing guards, trace-backed command observations and rejected-state snapshots, capture accounting and confirmed backend exit. The existing historical component reducer remains restricted to its previously qualified source; this suite's integrity validation does not silently extend that reducer to new evidence. Broader paired diagnostic evaluation, timing calibration and primary freeze remain incomplete.
