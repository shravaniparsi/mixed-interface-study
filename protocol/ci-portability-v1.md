# Hosted execution amendment v1

Recorded before the first GitHub Actions application run. The private repository is `shravaniparsi/mixed-interface-study`.

## Purpose and evidence scope

Hosted runs first establish reproducibility and adapter portability. Use standard Ubuntu runners and fixed application/artifact versions. Record the repository commit, workflow/run/attempt identifiers, runner image and architecture, CPU and memory information, browser, JVM, Python and Node versions, dependency/build hashes, and the configured concurrency. Record actual available environment values without inventing unavailable runner metadata.

The earlier macOS/Chrome results remain a separate environment stratum. Hosted Chromium and Linux are not assumed equivalent to the local browser/OS combination. Preserve platform-specific outcomes and adapter failures. Technical reruns do not create new applications, workflows, faults or untouched cases.

## Costs and timing

Every hosted budgeted integration must perform its own registered calibration on that host. Do not reuse the Mac's route-cost sidecar or its 20.695759-second budget as measured hosted costs. Use the existing budget formula and scope; retain hashes and actual timing/timeout records. The full candidate validation and calibration precede comparative sessions. Only runs using the same host configuration and within-run comparison context are eligible for a within-run engineering comparison.

Shared runner setup and dependency installation are reported separately from application-case timing. GitHub job elapsed time also includes these steps and does not equal the experimental execution budget. Configure one application job at a time per repository, explicit job timeouts, no scheduled campaigns, and manual dispatch for application runs. No paid model APIs, larger runners or account-wide billing changes are required.

GitHub's private-repository compute and artifact allowances depend on the account's plan and remaining usage. A job timeout limits execution duration; it does not prove that a run incurred no charge. Report consumed runner time and any available billing evidence separately from the earlier $0 local cash-spend record.

## Quartz scope

The first hosted Quartz registry run uses only the four `route_only` controls from v2. Verify output binding, native UI requests, independent fresh RAM-store resets, preserved fields, the native admin actor, stopped scheduler, and zero triggers/job executions. No boundary candidate becomes authorized as a primary effectiveness result merely because CI is available. Follow `multiworkflow-freeze-gates-v1.md` before the paired-oracle campaign.

## Preservation

Always upload outputs on success or failure, with the run ID and commit attached. Record failed setup attempts rather than replacing them silently. Download and retain relevant run evidence before artifact expiration. Compact summaries may enter Git after review; historical raw traces remain locally preserved and are not part of the initial source push. A passing workflow or control run is not evidence of selector superiority or journal acceptance.
