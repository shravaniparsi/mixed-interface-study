# SeatSurfing independent API loading and continuation

Prepare `load_seatsurfing_api_state_v1.mjs` and `run_seatsurfing_api_continuation_v1.mjs` for the later restored API branch. Neither starts an application/browser nor dispatches a qualification job on import. The enclosing registered coordinator must establish restored full relevant state, original credentials/actor, isolated networking and private evidence retention before invoking them.

The loader accepts only the stable location ID, original credential metadata and transport implementation. It accepts no native materialization, producer payload, native trace or target-repair value. Read fresh /user/me and /setting/, then start the original location chain and /setting/timezones concurrently. The location chain reads /location/{id}, conditionally /group/ when original permissions.groups is at least 10, then the original spaces, map, attribute catalogue and location attribute values. Use the original source mapping shared with the native reconstruction, retaining distinct API envelopes and provenance. No API response is fabricated as a native browser event.

Retain every dispatched GET's URL, method, headers, status, complete bounded response body, hash and timing. Require HTTP 200 and valid JSON for source inputs. Follow no redirects and perform no explicit retry. Bound the entire loading operation to thirty seconds and each observed body to 512 KiB. Require original token lifetime to exceed the loading deadline plus two minutes before any dispatch. On timeout, abort supported transports, preserve pending/partial envelopes, prevent subsequent reads from the operation, and return an immutable snapshot. A missing observation does not establish that the server performed no work. The enclosing worker still enforces a process deadline and database quiescence.

The continuation requires UTC before any request and only the two already frozen unrelated edits. After successful independent loading, derive the complete update using the existing source materializer, then invoke the existing bounded main/attribute executor. Loading failure prevents update dispatch. It performs no automatic post-save readback; the parent separately captures persistence and matches native behavior. Loading and update each have at most thirty seconds under the enclosing worker/job bound.

This component loads the inputs required by the mapped scalar edit. It does not claim to reproduce every resource/user-preference request issued by the complete UI. The ordinary comparison must retain the native/API acquisition traces and account prospectively for any relevant state effects, including asynchronous session-activity writes. It must establish complete update/ancillary equality and full relevant state before interpreting scientific cases. This component introduces no audit-field exclusions.

Default transport is Node fetch with the original bearer token and the executor's JSON header. Cookie handling, browser-added headers and transport equivalence remain unqualified; the parent must verify the actual fixture's authentication/header/cookie requirements before accepting this baseline. Supplying a transport implementation alone is not proof of equivalence. Actor, restoration, original schema and post-operation persistence are independent gates. The result always leaves runtime/full-state/native-equality qualification false; HTTP acceptance is not scientific success.

Validation: nine synthetic API-loader/continuation tests plus the seven existing native-loader tests. Fake transports cover fresh persisted values, permission-controlled reads, rejection without retries, insufficient credentials, oversized bodies, pending timeout with no later dispatch, no update after failed loading and UTC rejection before requests. No real API, application or scientific input ran.
