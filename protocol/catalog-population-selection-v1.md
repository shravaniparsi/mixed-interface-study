# Curated catalog metadata population and fixed selection v1

## Question and scope

Can a new, prospectively selected set of public self-hosted applications support independent tests of incremental native-continuation information after API acceptance? This stage constructs a metadata sample only. It does not establish API/UI workflow eligibility, application license sufficiency, executable provenance, causal identification or positive findings. No prior closed cohort is reopened. The population is the 1,362 software blobs in the catalog tree pinned at 114743487b2cfd1a9c68deff3511c11c3b307695, not all OSS web applications. Catalog curation removes some inactive, nonworking or security-troubled projects and therefore creates survivor bias.

## Fixed acquisition and parser

One GET to https://codeload.github.com/awesome-selfhosted/awesome-selfhosted-data/tar.gz/114743487b2cfd1a9c68deff3511c11c3b307695, at most 120 seconds and 20 MiB compressed, no retry, mirror, alternate revision or replenishment. Stream the response with the byte bound. Archive uncompressed regular-file total must be <=20 MiB; at most 3,000 members. Do not execute or broadly extract it. Read only the 1,362 software entries identified by the already retained tree, and AUTHORS for catalog attribution. Verify each software Git blob identity and declared size against that tree, requiring complete coverage; maximum 64 KiB per entry and 2 MiB total software bytes. Any archive/hash/coverage failure stops selection with retained failure. Other archive members may be present in compressed data but are not read for content or executed. Catalog data remains attributed to awesome-selfhosted contributors under CC BY-SA 3.0; retain its LICENSE and AUTHORS with redistributed metadata. Application source licenses are separately assessed later.

Use installed Ruby 2.6.10 / Psych 3.1.0 safe_load, only Date/Time permitted scalar classes, aliases false, JSON output, 30-second local parse bound. Do not install or run catalog tools. Parse errors are per-entry unavailable, not silently repaired. No app repository, issue, documentation, demo or runtime requests in this stage.

## Ordered metadata exclusions

Evaluate every entry and retain all failed checks plus a first-failure disposition in this order:
1. YAML must parse into a mapping; name/source_code_url strings and platforms/licenses arrays of strings are required.
2. source_code_url must be an HTTPS github.com owner/repository root URL (optional trailing slash and .git), no query or fragment. Other hosts and nested paths are outside this acquisition design.
3. platforms must contain exact Docker. This undercovers Docker-capable software without that catalog label; do not add discovered equivalents.
4. depends_3rdparty must be absent or boolean false. True, null and other types are excluded conservatively.
5. Every license identifier must be in this fixed conventional open-source set: 0BSD, MIT, Apache-2.0, BSD-2-Clause, BSD-3-Clause, GPL-2.0, GPL-3.0, AGPL-3.0, MPL-2.0, ISC, EPL-2.0, LGPL-2.1, LGPL-3.0, Unlicense. A terminal -only or -or-later is stripped before matching. Empty lists are excluded. This metadata screen is not legal adjudication or a complete OSI list; do not widen it after counts are known.
6. Quarantine prior overlap using the union of the 347 repository references in prior-repository-reference-index-v2.json and GitHub repository URL references in the retained catalog schema/template documents. Exclude an exact repository or shared GitHub owner. Also exclude catalog filename stem or name matching an alphanumeric-lowercase repository basename from that union. Record the matching references. This conservative proxy neither proves common authorship nor certifies absent exposure: 19,117 historical raw artifacts are unavailable locally, aliases may be missed, and model-training exposure is unknown.
7. Quarantine descriptions containing the standalone word fork (case insensitive), or entries carrying fork_of/forked_from keys. No external ancestry lookup at this stage. Unresolved ancestry is retained as unresolved, not independent by declaration.

## Fixed order and denominator

Normalize repository owner/name to lowercase and remove .git. Collapse duplicate repository entries, retaining all catalog paths and the lexicographically first eligible entry as representative. Rank eligible repositories by ascending SHA256 of the UTF-8 string `catalog-independent-v1|114743487b2cfd1a9c68deff3511c11c3b307695|` followed by normalized owner/repository; tie-break by repository. This seed is now fixed before entry contents; it is a reproducible deterministic ordering, not a claim of probability sampling. Select the first repository per GitHub owner in that order, up to 12 owners. Later entries with selected owners are grouped, not independent replications. Retain the complete ranked list, every exclusion, every owner group and the actual denominator; if fewer than 12 qualify, retain the smaller sample without altering filters.

Twelve is a feasibility workload ceiling, not a power calculation. No replacements for subsequent source, provenance, deployment, control or experiment failures. All selected projects remain in the qualification denominator. No minimum positive-finding target. Before opening selected application sources, publish fixed workflow-selection, source-acquisition and runtime/stop rules incorporating continuation-request-matching-policy-v2.md and competent H/S/A/U baselines. This metadata stage alone authorizes none of those app requests. Historical source-aware baselines and ordinary-control results remain development evidence, not held-out measurements. Generalization remains limited to this filtered curated frame and unresolved project ancestry.
