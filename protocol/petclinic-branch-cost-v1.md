# PetClinic monotonic branch-cost preparation

The new v4 runner preserves the v3 application operations and adds a monotonic branch clock. It is preparation code, not a qualified execution path. Existing campaign loaders still pin v3 and will not silently accept this new runner. No application is dispatched by preparation or unit tests.

The clock starts as the first operation of `execute`, before the start checkpoint and backend startup/reset. Its interval includes the independent backend reset, application actions, UI capture drain, context closure, backend cleanup, raw JSON write, raw JSON readback, identity validation and hashing. The end is sampled after that work. Writing the finalized cost sidecar and controller summary occurs after the end boundary and is not counted. Browser launch is shared common setup and has a separate monotonic duration. Existing request and wall-clock fields retain their original meaning and are not summed into branch cost.

Each branch first writes an incomplete cost checkpoint with its candidate, channel and start time. A final sidecar binds the observed interval to the exact raw-file SHA-256. A complete interval requires both backend-exit confirmation and successful closure of the branch browser context (or absence of a context). Semantic rejection, blocked UI or an application assertion failure can still have a fully measured attempted interval; these are not successful speed results. If cleanup is unconfirmed, an observed elapsed interval may be retained, but `branch_total_s` remains null. If no end is observed, no duration is inferred from timestamps or request sums.

The helper rejects foreign evidence, changed hashes, malformed/nonfinite clocks, backward clocks, inconsistent elapsed values, unfinished branch status and double finalization. Unit tests use synthetic records and deterministic clocks; they supply no application evidence or primary sample. The helper and new runner are source-hashed in the preparation manifest.

Next add a versioned independent file loader that verifies raw-file hashes, cost sidecar identity, helper/runner source copies and summary cardinality alongside existing semantic and cleanup checks. Then qualify the new instrumented path on a fixed exposed control selection. Preserve missing/incomplete records on failure. P4 remains open until this live qualification and primary preflight enforce the registered timing contract.
