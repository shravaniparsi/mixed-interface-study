# SeatSurfing actor acquisition integration v1

This coordinator helper connects existing read-only actor acquisition to the existing offline identity verifier. It neither logs in nor refreshes credentials and does not dispatch a qualification run.

Inputs are the original build/provision reports, exact browser-storage bytes and hash, original native network events, provisioned public key, expected organization and (for later branches) the prior verified continuity object. The helper checks the executing study commit and current source preparation, storage origin and unique credential keys, exact provisioned key hash, and provisioning's build-report hash. JWT payload decoding supplies only UUID-validated database selectors; it never establishes authenticated identity.

The actor acquisition performs one original read-only repeatable-read query, preserving its exact raw stdout/stderr privately even on query failure or timeout. A successful report includes the raw JSON bytes as text, their hash, parsed data, query hash, build hash and actual application/database container IDs. The helper verifies these against the requested selectors, original provisioning and current inputs before invoking the offline verifier. Provisioning now retains the database container ID as well as the application ID. Neither a replaced database nor a parsed result that differs from retained raw output can pass this binding.

The dependency-free Node file entry point verifies the original RSA signature, native actor response, session and unused refresh token, expiry, original roles and continuity using the established verifier. It records the exact input hash and actual Node version, emits no credential-bearing console output, and writes a new mode-0600 private result. The parent allows fifteen seconds and requires successful status, matching input hash and verified identity. Failure or timeout is unavailable evidence, never permission to repeat a login or replace an actor.

The report distinguishes verified database acquisition provenance from the pure verifier's narrower identity check. This still does not qualify full database state, restore equivalence, browser-added transport headers, complete API identity observations or a scientific outcome. The enclosing coordinator must bind each branch's current observations and enforce the existing runtime/deadline registration. No claim is made that signature verification independently reconstructs all server permission semantics.

Validation includes five synthetic input-binding tests and one mocked coordinator test with four scenarios (success, changed database, changed parsed data, wrong verifier input hash). Eleven existing/extended Node actor tests include a real offline file invocation on synthetic RSA evidence, successful identity, and rejected identity mismatch. The query and provisioning guards are rerun. No application or database is started by these tests.
