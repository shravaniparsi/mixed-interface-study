# SeatSurfing original actor evidence component

Prepare two components for the later registered ordinary coordinator. `capture_seatsurfing_actor_database_v1.py` performs one read-only, repeatable-read PostgreSQL transaction on the labelled, isolated study fixture. It accepts strictly validated UUID selectors for the user, session and refresh token. It retains original user/session/refresh rows, assignments, assigned roles and stored role-permission rows, with observation time, expiry projections and the ban-inactive predicate. It records query/result/build identities and container IDs. It requires the original successful build identity and pinned PostgreSQL configuration, checks container identities before/after the query, refuses evidence overwrites and has a thirty-second query deadline with no retry. Output is private: original user rows can contain password hashes and other sensitive fixture fields. The parent must seal this output with other private evidence.

This collector starts no container and changes no record. It may run while the application is paused or running, with PostgreSQL running and unpaused; its transaction snapshot is not proof of application idleness. The original session/refresh source writes UTC timestamps. Its epoch projections explicitly interpret those timestamp-without-time-zone values as UTC. The runtime coordinator must verify the fixture's time configuration and enforce a bounded observation/capture interval.

`verify_seatsurfing_actor_v1.mjs` performs no request, database query or browser action. It verifies the original RS512 token signature against the retained fixture public key, standard original-password-login claim shape, two-minute remaining lifetime and matching issuer/audience. It cross-checks every captured native GET /user/me in the supplied trace: exactly one original request-header record, successful complete response/body hash and completion event for each, original bearer token, and matching user/email/organization. It retains the complete original resolved permission map and role IDs. It does not replace administrator permission resolution with a hand-built catalogue.

Cross-check the database user, account type, disabled/ban state, session owner and expiry, unused original refresh token and expiry, original unscoped role assignments and organization system role against the native identity. Require database evidence observed within thirty seconds of verification. A later branch must equal the retained original continuity object, including token/refresh hashes, session, issuer, organization, original permission map, roles and authentication-feature fields. Do not authenticate again, rotate credentials, reassign roles or infer actor equality from the login email alone.

The returned identityConsistent flag is an input-consistency result. The component explicitly leaves databaseAcquisitionProvenanceVerified, fullStateEqualityEstablished and runtimeQualified false. The coordinator must bind the actual query artifact/build/container IDs and fixture public key, establish that the network trace came from the original worker, enforce unchanged browser credentials, and independently verify full relevant state and restoration. Matching supplied JSON alone is not execution evidence. Issuer/audience agreement is checked within the signed token; this component does not independently derive installation ID from the settings table.

The already retained routes.go middleware starts `SessionRepository.UpdateActivity` asynchronously on each authenticated request. Thus a finished native response or browser-network quiet is insufficient evidence of database/application quiet. The checkpoint/ordinary recipe must separately account for outstanding work and session last_activity differences. This component authorizes no audit-field exclusion: full database checkpoint comparison remains intact until a separate prospective operation-specific comparison is published.

Preparation validation: ten synthetic Node tests with locally generated RSA keys and fake network/database records, plus two Python tests of read-only SQL and selector validation. They reject altered signatures, another bearer/user/session, used refresh tokens, missing administrator role, stale evidence, changed resolved permissions and missing native response capture. No application, browser, database connection or scientific input ran. These components do not authorize a qualification dispatch or expand its stopping bounds.
