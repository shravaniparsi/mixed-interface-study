Start Java -Xmx1g -jar application.jar with --spring.profiles.active=dev,api-docs --server.address=127.0.0.1 --server.port=8080, in a new working directory. Preserve original development H2 URL, credentials, Liquibase contexts (including faker) and application beans. The isolated fresh working directory gives a fresh development database. Execute the app and observer in a fresh Linux network namespace with loopback enabled and no external interface. This prevents outbound mail/telemetry and external services; it may make external-service health fail. No user secrets, external writes or application data mutation requests. Initialization may create its original development fixtures. Record this isolation as a deployment condition, not production equivalence.

For at most 300 seconds, request /management/health at five-second intervals, each timeout three seconds, stopping on HTTP 200 or 503 or process exit. These are bounded startup probes, not rerun experiments. Health 503 can indicate an unavailable external service; retain its response and do not classify it as healthy. Only after a 200/503 response, request exactly /v3/api-docs, /v3/api-docs/default and /v3/api-docs/swagger-config once each, in that order, each timeout ten seconds and maximum response 4 MiB. No login, alternate path search, parameter changes or retries. Record all statuses/errors, bytes, hashes and parsed top-level metadata. Accept an obtained specification only if a response is 200, valid JSON with openapi version string and a nonempty paths object. Config JSON alone does not qualify. Do not interpret specification contents as independent intended correctness labels.

Preserve Java version, binary hash, namespace interfaces, process exit, startup requests, raw bounded response bodies and application log; terminate the process group in finally with TERM then KILL if necessary. Capture harness status even on timeout and retain failures. Network isolation is a qualification prerequisite; if unshare fails, do not fall back to an unrestricted run. No tests or reserved source are read. A successful retrieval qualifies availability only, not a competent oracle baseline, workflow compatibility or new defects.
