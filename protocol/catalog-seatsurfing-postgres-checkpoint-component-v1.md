# SeatSurfing stopped-runtime PostgreSQL checkpoint component

Preparation only: no Docker or database command may execute until included in a prospectively published qualification recipe. Use study-seatsurfing-postgres with the recorded PostgreSQL config identity and observed image-declared version 18.7 (server_version_num 180007), the verified built application identity and the existing pinned browser config. Require stopped application and browser, a running database with NetworkMode none, and application/browser attached to that namespace. Bind the application build report to the frozen source revision and build-preparation-v2 manifest hash. These are prerequisites, not proof the still-unimplemented build report is trustworthy; the runtime must verify its full source and package inventory.

Require only postgres and seatsurfing databases, no other sessions in the application database, and no large objects or foreign/materialized relations requiring unsupported restoration. Capture all user-table rows (including duplicate rows), sequence state, schema, cluster roles/memberships, role/database settings, tablespaces and server configuration without application-field exclusions. Bracket the custom-format dump with matching stopped-state fingerprints. Raw dumps/baseline files are private. Hashes do not justify exposing raw credentials or records.

Restore the hash-verified dump into the same stopped-runtime database using pg_restore --clean --if-exists --single-transaction --exit-on-error, then require full fingerprint equality. Preserve database identity and cluster settings. Remove only pg_dump's paired random restrict transport-guard tokens from schema hashing; no application value or timestamp is stripped. Any command warning, mismatch or unsupported state fails qualification. The outer coordinator must enforce the overall process budget and retain errors privately; individual commands have a 120-second bound.

This database component does not restore browser storage, JWT key files, application filesystem or process caches. A separate coordinator must prove network/process quiescence, restore all relevant state together and compare a warm ordinary reference against restored branches after startup. Do not launch a study using only this dump. Seven synthetic guard tests use mocked Docker/SQL responses and verify rejection of unsafe states; they do not qualify pg_dump/restore or PostgreSQL 18.7 behavior.
