# OpenAPI-advertising public-system metadata screen

This is a single exploratory, outcome-informed feasibility screen after the closed maintained-packaged frame, not an extension of its sample or a claim of independent confirmatory evidence. The motivation is the unresolved original-schema baseline and deployment qualification, not known validation bugs. The user has specified public open-source systems only.

Publish this protocol, collector and pre-query exposure snapshot before retrieval. Make exactly one GitHub repository search request: `topic:self-hosted topic:openapi archived:false fork:false stars:>=100 pushed:>=2026-01-01 created:<2026-01-01`, sorted by stars descending, first page, at most 20 rows. Retain API tie ordering, total_count and incomplete_results. No alternate query, threshold change, pagination, retry, replacement or repeated screen if results disappoint. A failed request remains unavailable. Cap response at 4 MiB and request duration at 30 seconds. No issue, fix, release or candidate implementation search.

The explicit OpenAPI topic targets an original API contract; it does not establish a supplied schema, supported dialect or actual request coverage. The lower popularity threshold broadens metadata eligibility compared with the prior >=1000-star frame; it is not evidence that smaller-star projects are simpler or more deployable. Top-ranked topic search is a convenience frame with popularity, self-description and recency bias. Native UI and reproducible packages remain unverified. Report all records, including overlaps and nonapplications, and do not replace them.

Snapshot prior references from the two retained exposure indexes, all current tracked JSON repository fields and current tracked textual GitHub URLs before the request. This is a conservative exposure screen, not proof of complete history or model-training independence. Exact matches are exposed; same-leaf aliases and upstream-family uncertainty are unresolved and cannot be called independent. Existing closed cohorts remain closed even when a returned repository has a new revision or owner. Metadata descriptions may themselves disclose behavior; preserve them as exposure.

This authorizes metadata collection only. Do not fetch candidate trees, source, release assets or layers, start applications, call models or provision accounts. Any later qualification must have a distinct frozen acquisition/engineering budget, full queue record, ordinary controls, lineage assessment and exact H/S/A/U definitions. No scientific admission or minimum sample size follows from this search. Existing $100 ceiling and free standard Actions restriction remain. Stop after the single response and assess whether further qualification is justified; no search-until-success loop.
