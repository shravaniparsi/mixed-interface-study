# Technology-defined project-frame feasibility: metadata only

Purpose: determine whether a bounded external repository frame can support future independent evaluation. This is not an admitted experimental cohort, an evaluation registration, or permission to open outcomes. The candidate's method distinction, complete comparator and independent contract-label gates remain unresolved. Metadata feasibility must precede choosing an effect target or promising a sample size.

One GitHub repository search: `topic:angular topic:spring-boot fork:false archived:false created:<2026-01-01`, sort stars descending, page1,per_page20. Selection uses technology tags and popularity, not reported validation faults or observed method performance. Angular/Spring align with the development adapter but make this a narrow, popularity-biased convenience frame, not representative of web applications. Topics are self-reported; they do not prove a usable API/frontend or independent origins. Preserve all returned entries, total_count and incomplete_results. Do not change query, sort, page or replace projects if the frame is unsuitable.

Before search, construct an exposure index from repository references in currently tracked local artifacts. Record scanned/skipped/missing files and their sizes/hashes. A match means prior reference exposure, not necessarily prior source/outcome exposure; no match is not proof of independence or absence from model training. Keep known prior applications and cloned/upstream project families unresolved until explicit genealogy review. Repository count is not independent project count.

At most21readonly API requests:1search and at most1default-branch git-ref lookup per returned repository. No source/tree/readme/issues/commits/tests/patches or benchmark labels opened. Pin SHA using git/ref/heads (no commit messages). Each response≤2MiB, timeout30seconds, total deadline180seconds, no retries. Use sequential requests and retain each error; a missing pin does not silently exclude/replace a row. Save raw responses privately with mode0600 and publish only sanitized repository metadata, object SHA, response hash and request errors. No package installs, app execution, model calls, notifications or paid service use. No change to prior closed cohorts.

Fields retained: repository id/full_name/html_url/default_branch/language/topics/star count/created_at/updated_at/fork/archived/size/license SPDX, query rank, pin result, exposure references. Record source-collection time and HTTP rate-limit metadata when provided. No scientific accuracy/prevalence/coverage estimates from metadata.

After collection, report frame composition and prior-reference overlap only. Source eligibility, genealogy, label availability, framework versions and execution feasibility remain unknown. Any subsequent structural screening requires its own prospectively bounded file policy and must not inspect outcomes before the comparative design is ready. A useless/overlapping frame is retained as a feasibility result; no search expansion to obtain favorable projects.
