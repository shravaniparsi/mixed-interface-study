# GoModel development experiment draft v1 — not execution registration

This draft resolves scoring and control requirements for the frozen literal schedule. It grants no application execution. The final runner, literal state scope, dependency hashes and final protocol must be published before any altered producer. The remaining preparation deadline is unchanged. The ordinary preflight qualification must first close with retained evidence.

## Scope and denominator

One development repository and one workflow, nine frozen producer payloads: the shared ordinary payload plus eight omission/null variants. Preserve all nine outcomes, including rejection, accepted normalization and unavailable stages. Do not substitute variants, fields, workflows or projects after results. Twelve planned target-specific sham/repair pairs are correlated: four pairs on the shared ordinary state and one pair on each altered state. These are development evidence and never become independent evaluation observations.

## Required control order

Run the shared ordinary producer first and all four ordinary pairs before any altered producer. This qualifies both selected unrelated-edit controls and all repair actions, beyond the existing request_set calibration. Failure prevents the altered stage. Use the exact frozen ordinary state for all ordinary pairs, rather than calling independently created states equivalent. The native ordinary creation control, executable provenance, local actor and isolation must remain verified.

Each altered payload starts from the same qualified clean fixture with no previously scheduled API-created record. Retain producer response and complete before/after state, then stable-name API and database readback. A rejection is not assumed to roll back: compare state. Acceptance requires independent confirmed persistence; missing target and explicit null remain distinct. Compare sent and persisted representations and retain producer normalization separately from later UI normalization.

Before each pair, establish its complete checkpoint after the same single original startup-maintenance initialization used in qualification. Preserve both sides of that initialization, allowing only planner-statistic changes there. Require the stored target record and every other application value unchanged. No iterative stabilization is allowed. For each pair, perform a warm sham, then a restored sham and restored repair. The warm sham is an equivalence check, not an extra sample. Every restored start must match DB/files, actor, browser storage and form exactly before any native write. Warm/restored sham behavior, requests and full effects must agree under the predefined timestamp exceptions before causal interpretation of repair. If initialization or any restore fails, preserve the available observations and mark causal interpretation unavailable; do not rerun or correct that input.

## Baseline and outcome scope

H records status and persistence. S remains unavailable for this route in the qualified original OpenAPI artifact. D runs the original-native preflight with the same actor, loaded record, type descriptor and intended controls, intercepting mutations before transmission. Its output is the emitted method/path/body/actor or qualified client-blocking evidence, not a prediction of backend validation or preserved persistence. Discard its browser context and verify original starting state before the actual native continuation. Retain baseline coverage and missingness per branch. Do not treat D/U agreement on shared frontend behavior as independent validation or superiority.

On native continuation retain actionability, input values/attributes, invalid events and constraint-validity states, visible original errors, all requests/responses, final independent record readback and complete state. A ten-second wait without a request alone is unavailable, not blocked. Native constraint blocking requires a captured invalid event from the attempted submit, invalid original controls, no mutation within the fixed window and unchanged state. Other client blocking needs a source-mapped original guard with positive runtime evidence; an unexplained error, disabled button, timeout, pending request or asynchronous validator is unavailable. Backend rejection is separate and requires its actual response; still inspect writes.

For successful responses, score intended unrelated change and full frame separately. Expected full-frame effects are the chosen unrelated config value, the chosen repair value only in the repair branch, target updated_at and guardrail revision +1 with its updated_at. Every other DB/schema/file value must match. Raw timestamps remain; only those two row timestamps may differ across successful equivalent branches, and each must be nondecreasing. A changed target in sham is reported as a target change during unrelated editing, not a silently permitted frame effect. Missing-to-empty and null-to-empty are distinct. Target-only representation change is not automatically a defect. Extra changes outside that scope remain explicit state differences.

The pure helper development/redesign-gomodel-scoring-v1/frame.mjs implements only this config-state classification and has synthetic unit tests; it does not implement full request, rejection, blocking, restoration or causality scoring. It is not a completed experimental runner. Before execution, the offline verifier must reproduce all outcome gates from raw evidence, and tests must cover missing/null, boolean/number distinction, unrelated writes and repair attribution.

## Analysis and pending execution budget

Report a descriptive flow from scheduled producers through persistence, native observations, full-frame outcomes, baseline coverage and causally qualified pairs. Show per-property omission/null pairs, keeping the shared ordinary control explicit. No pooled binomial confidence interval or p value treats variants/branches as independent samples. One development workflow cannot support a population defect rate. Any later evaluation analysis must be frozen before evaluation source/outcomes and account for the prespecified repository sampling and attrition.

The final execution registration must give one attempt limit, exact per-stage and total timeouts, free-runner allocation, no-correction rule, artifact retention and spending checks before dispatch. This draft does not fill those gaps by implication. Preserve the project ceiling of $100 and no new paid service. Track this development effort and original source exposure separately from evaluation. The objective remains stronger independent evidence, not manufacturing a positive result from this project.
