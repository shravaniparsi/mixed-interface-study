# RealWorld identity adapter and independent extraction

Status: source and mock-response integration prepared; live dispatch qualification remains open. No application campaign, corpus promotion or primary-boundary execution is recorded by this change.

The versioned `realworld_identity_case_v1.mjs` implements API-produced profile updates followed by an API or fresh native settings continuation. It binds the restored principal, three fixture article references, the expected post-prefix username, the complete loaded settings form and the exact continuation payload. Username updates preserve registered unknown acceptance policies. The API and UI paths use the same intended full settings update. Email changes and unexpected acceptance of null/empty usernames remain unsupported.

Snapshots are collected before the prefix, after acceptance, and after continuation; rejected prefixes receive a final snapshot and no continuation. Related-state comparisons permit only the submitted profile fields in nested profiles of the renamed account, and then the intended bio edit. Unrelated article, comment, tag and other-account changes remain comparison failures. Failed identity bindings retain raw responses and stop comparison rather than silently changing the expected principal.

`realworld_identity_extract_v1.py` independently reconstructs Python snapshots, request/response accounting, exact submitted payloads, response order, captured native login identity, settings bindings, profile reference resolution and related-state checks. It checks response-backed snapshots against the three fixture references and recomputes each reported boolean. HTTP 400/422 prefixes are distinguished from server failures and unsupported success codes. Unknown requirement policy remains unresolved even when a mismatch is recorded. Invalid captures or contradictory summaries produce missing evidence, not a semantic conclusion.

Twenty tests cover synthetic API and native traces, inconsistent summaries, wrong identities, lost or reordered responses, extra writes, altered fixture state and preservation of supported mismatch observations. One execution test invokes the actual Node adapter against a deterministic mock API for accepted, 422 and 500 responses, then independently reconstructs its emitted evidence in Python. The real frontend is not exercised by these tests. A separate cross-language test compares the Python projection with the JavaScript snapshot contract.

The extractor is deliberately not a provenance certificate or terminal supervisor. Before a live campaign, a versioned job loader must bind exact registry/case/job bytes, executed source hashes, backend/frontend commits, offline reset hashes, distinct branch evidence, timing and confirmed process cleanup. Pair comparison must establish equal initial state, prefix command, prefix status, expected identity and assigned continuation command. The common terminal-v2 repeat policy must retain every attempt. Null/empty rejection paths and the unresolved 60/61-character cases may then be exercised only as the previously exposed engineering cohort, with the ordinary profile control as reference. No primary study readiness gate is closed by these mock tests.
