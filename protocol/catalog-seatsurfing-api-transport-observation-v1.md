# SeatSurfing passive API transport observation v1

The isolated API worker now subscribes to the existing Node/Undici diagnostic channels for request creation, header sending, body-sent notification, response headers, response completion and request error. It modifies no request and sends no additional request. It retains at most 128 request records and 1 MiB of diagnostic header text, with at most 16 KiB per request. Callback errors are retained as observation failure without throwing into the HTTP client. A successful worker must bind every declared API envelope to exactly one diagnostic request with matching method, isolated URL, supplied headers, response status and completion. Duplicate dispatch, unexpected origins, cookies, unsupported chunked framing or missing diagnostics make the observation unavailable.

This is PARTIAL header observation, not packet capture. The official Undici diagnostics documentation describes sendHeaders as raw outgoing headers (https://github.com/nodejs/undici/blob/main/docs/docs/api/DiagnosticsChannel.md, accessed 2026-11-18), but a real synthetic loopback test on local Node 22.22.3 observed Content-Length at the receiving server without that field appearing in the diagnostic event. The implementation therefore retains `headerCaptureCompletenessEstablished=false`, `contentLengthObserved` and `bodyBytesIndependentlyObserved=false`; it does not fill in an inferred wire header. If Content-Length is observed, it must match the supplied body's UTF-8 length. Automatic headers that are actually observed remain in the private evidence for subsequent source-based comparison.

The synthetic test compares all observed diagnostic headers to the actual receiver's headers and permits only Content-Length as an unobserved field. It exercises an ephemeral loopback HTTP server with synthetic credentials, not SeatSurfing, Docker or a study fixture. Its first sandboxed run could not bind a local socket; the authorized escalated test then revealed the header-capture limitation. Both the unsuccessful observation and resulting explicit scope are described here. The final test passes on the existing local Node runtime; the pinned Node 24.18.1 application-worker behavior remains to be verified in the registered qualification run. Missing events at that runtime fail rather than silently qualify.

The diagnostic channels are documented as experimental. This component establishes correspondence for observed headers and lifecycle events only. It does not finish the original middleware/handler/header audit, all-client accounting, broader transport qualification, runtime registration or the scientific study. Seventy-one SeatSurfing Node tests pass locally, including synthetic request and identity checks; no application attempt is consumed.
