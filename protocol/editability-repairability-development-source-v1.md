# Development-only source feasibility budget v1

Apply only to the eight development candidates in the frozen repository schedule.
Do not acquire evaluation source or inspect evaluation outcomes to construct the
method. Source review does not qualify a workflow or executable. Keep candidate
order, unresolved prefixes and acquired-source exposures visible.

Before every acquisition wave, publish exact paths, pinned commit/blob identities,
declared sizes, dependency purpose, collector and protocol. Per project: at most
256 scheduled paths and 16 MiB retained decoded source. Each scheduled path,
including failure, consumes a slot. Per file <=1 MiB decoded, response <=2 MiB,
one request <=30 seconds. No retry, alternate ref, clone or substitute file for
a failed request. No execution or dependency installation from acquired files.
Metadata and source acquisition elapsed time are reported separately from
adapter/review effort; neither is represented as total human effort.

Wave 1 acquires only original root README, license, Dockerfile and default compose
files when present. Missing root files remain missing; do not guess alternatives.
Later files require a concrete workflow, dependency or deployment question and
a separately published path schedule. Do not chase every import or use issues,
fix histories, exploit reports or test failures to select mutation targets.
Incidental source comments about prior defects are recorded as exposure.

For source eligibility, map the original API producer, native producer/editor,
stable-ID readback, independently editable fields, source-aware validation,
compatibility obligation, actor/bootstrap, persistence and isolated deployment.
Prefer original integration/ordinary tests as deployment evidence, not tests
selected for known defect outcomes. No external-account, financial-transaction,
file-upload or inter-user-message task is substituted for the registered workflow.
A candidate may be unsupported; do not invent APIs, weaken D, modify validation,
or treat an unreviewed workflow as proven absent.

Later runtime qualification needs an explicit per-project registration, original
executable provenance, state/actor equivalence, ordinary controls and effort/run
bounds. This source budget does not authorize starting applications. The later
caps remain two source-eligible development workflows and six separately selected
evaluation workflows; development source review cannot select evaluation outcomes.
