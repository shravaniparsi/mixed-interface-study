# RealWorld response-capture repair: control validation

This engineering validation is fixed before its hosted execution. It tests response capture and source-qualified extraction, not diagnostic advantage or selector effectiveness. Historical incomplete records remain unchanged.

The generated adapter executes only the four `route_only` cases in the unchanged 18-case RealWorld registry, in registry order, with phase `controls`. Each branch uses the existing independent SQLite reset, 75-second execution allowance and recorded parent/worker cleanup. No calibration or timed selector sessions execute.

The legacy adapter executes these six existing candidates, once per registered continuation, in registry order: `article-valid`, `comment-body-valid`, `profile-bio-valid`, `article-update-unique-partial`, `comment-native-control`, `profile-native-control`. They produce ten ordinary control branches across four workflow templates. The previously incomplete profile control is included under the repaired source version. Legacy execution retains its existing reset and 90-second child limit; this run does not establish missing per-branch owned-process cleanup evidence for that runner.

Both adapters track page-local API requests from admission through response-body completion or request failure. On context replacement or final shutdown, draining starts with a five-second deadline. Requests arriving while work remains are included. When no admitted work remains, listeners are detached synchronously and the context closes immediately afterward. Requests outside that closed capture window are not counted. Late callbacks from an ended scope cannot append observations. Network, body-read and drain-timeout failures invalidate capture and the adapter result.

The hosted script saves a plan containing exact source/input hashes and captured runtime/browser metadata before starting the two runners. The generated run precedes the legacy run. Outer limits are 180 seconds for generated controls and 240 seconds for legacy controls, with 20-second forced-stop grace; the application step retains its nine-minute limit. No automatic retries, partial replacements or cross-attempt merging are permitted. Failed attempts must be preserved; any repair starts a new complete attempt.

Acceptance requires all fourteen branches to finish normally with their ordinary business checks passing; source-qualified extraction must qualify all fourteen. Revised adapter and capture-helper hashes must match the executing archives. Every recorded native API request must have one matching captured response and a completed context-drain record, with zero capture errors/timeouts. Generated reset and worker/parent cleanup evidence must pass the existing reducer checks. Source hashes are compared with the pre-dispatch plan after execution. The plan and summaries retain actual environment provenance.

Passing controls qualifies this capture repair on the exercised paths. It does not prove all future responses will succeed, validate forced-timeout cleanup in the legacy runner, close payload/state-parity gaps, or complete the primary study freeze. The forty Quartz boundary cases remain unexecuted.
