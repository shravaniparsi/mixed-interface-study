# Private runtime evidence retention

The public research repository must not receive plaintext database snapshots, signing keys, synthetic login tokens/passwords, full Docker environments or raw startup/browser logs. Preserve them as authenticated encrypted artifacts so a public-runner execution remains auditable. No live application evidence has been sealed yet.

Use the versioned public recipient certificate in manifests/catalog-nginx-evidence-recipient-v1.pem. Its RSA-3072 private key is kept only in the user's local workspace outside this research checkout, in a mode-0700 directory with a mode-0600 key and a local ignore-all file. The private key is never supplied to Actions, printed in tools, or committed. Preserve that local key; losing it makes future ciphertext unrecoverable. The certificate is a recipient identity, not a web-server trust certificate.

After application/browser cleanup, seal each quiescent private evidence tree using OpenSSL CMS AuthEnvelopedData, AES-256-GCM content encryption and RSA-OAEP-SHA256 key wrapping. The public output contains only private-evidence.cms and sealed-evidence.json. The report includes certificate/ciphertext/archive SHA256, byte counts and entry counts, without raw filenames or source exception text. On sealing failure, delete partial ciphertext and write only a generic failure report. The parent must record sealing failure as unavailable evidence, never as a successful qualification.

The archive preserves regular files, directory metadata and literal symlinks without following them. Reject special files, hardlinks, a conflicting reserved inventory name, more than 100,000 entries or more than 512 MiB of regular-file content per sealed tree. Include a private inventory with exact nanosecond modification times, modes, ownership, file sizes/hashes and literal symlink targets, since tar metadata alone does not reliably preserve all checkpoint metadata. Re-inventory after archiving and require equality. Plaintext temporary archives are created in a mode-0700 temporary directory beside the private source, outside the public output, and removed on exit. Archive destination must be separate and new; never overwrite a prior artifact. The parent must allow bounded sealing time within the 30-minute job ceiling and upload explicit public ciphertext/report paths only.

Retrieve ciphertext and the public report after the job. Decrypt with the local-only key, require OpenSSL's successful authentication result, then verify the complete plaintext archive hash before reading/extracting members. Never consume plaintext emitted by a failed decryption. Treat archived symlinks as retained evidence; do not blindly extract arbitrary links or restore state until membership/target checks and exact metadata restoration are implemented. This component does not delete source evidence or claim to verify application results.

Four local synthetic tests exercise authenticated encryption/decryption, changed-ciphertext rejection, content/private-inventory preservation, nested-output/overwrite rejection, symlink non-following and unsupported/reserved members. A separate small synthetic round trip verified the actual published certificate against the retained local-only private key. No credentials or private key bytes were emitted. Linux-runner OpenSSL compatibility remains subject to CI and the bounded live workflow; there is no plaintext fallback.
