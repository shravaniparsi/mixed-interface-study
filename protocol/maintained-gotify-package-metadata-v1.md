# Gotify package metadata qualification v1

Before registry observation, select exactly ghcr.io/gotify/server:master, a tag documented by the pinned Makefile. Compare its linux/amd64 configuration revision label with selected source commit 01086b95a8b69ee87383f6e8bcae601d8c33384b. No alternate registry, tag, architecture, historical search or retry if it differs or is unavailable. This is package metadata qualification, not an application run or scientific outcome.

Use at most five HTTP requests, each with a 30-second timeout and 2 MiB response ceiling: anonymous tag manifest; if challenged, one GHCR anonymous pull-token request and one authenticated manifest request; one linux/amd64 child manifest when the tag is an index; one config blob. Token responses and Authorization headers are kept in memory only and never published. Archive non-token responses, hashes, status and content type. Verify child-manifest and config SHA256 against their descriptors and record immutable index/manifest/config digests. Do not download filesystem layers, start containers, execute binaries, authenticate to the application or perform business writes.

If more than one unqualified linux/amd64 descriptor matches, choose the lexicographically first digest and retain the full candidate list. Do not select an attestation (unknown architecture). Missing architecture, oversized response, digest mismatch, request error, missing revision label or differing revision is explicit unavailable/mismatch. A matching org.opencontainers.image.revision label supports publisher-declared source provenance only; it does not prove reproducible source/binary equivalence or native UI inclusion. Those require subsequent fixed execution qualification. No package mismatch changes the chosen workflow or source revision. Any source-build route needs a separate bounded registration within the existing ordinary qualification budget.

The public/free execution and $100 total ceiling remain unchanged. This inspection uses no paid service and no GitHub Actions job. Publish this protocol before the one-shot registry requests and preserve every failure.
