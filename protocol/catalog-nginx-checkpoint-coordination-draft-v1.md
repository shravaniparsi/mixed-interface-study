# AccessList coordinated ordinary checkpoint design — not dispatch authorization

This design connects the existing database, filesystem and native-actor components. It is not yet a complete runtime recipe, workflow/input freeze or permission to consume an application attempt. No application outcomes have been observed. Keep the existing two qualification jobs of at most 30 minutes and all scientific-input limits.

## Required sequence

1. Build the same frozen application using registered dependency pins. Verify source/tree/blob identities, dependency locks and actual installed versions, generated frontend/backend inventories and resulting image identity. Use the original application and nginx processes. Run the application in an isolated Docker network with original IP_RANGES_FETCH_ENABLED=false, an empty certificate fixture and private synthetic administrator credentials. Do not propagate CI=true, NODE_ENV=test or DISABLE_RATE_LIMIT=true into the application. Pin actor/client network addresses across branches; record actual topology.
2. Produce the ordinary record with native controls and separately with the original API, check intended state/readback and complete source-materialized ordinary update. The native producer and unrelated-edit controls, payload values and workflow selection must be frozen before this stage. Password masking is part of the readback contract; never restore a producer password into a native model.
3. Establish a quiescent pre-edit state with no pending browser request or application operation. Retain original browser storage and token. Use the original driver backup helper and full typed database inventory. Capture the filesystem only while the original container is authoritatively paused, including both /data and /etc/letsencrypt; retain a complete container-diff/config inventory as well. Resume without recreating the warm process and verify the database again. Require the source/checkpoint database states and relevant filesystem states to agree. Read-before/read-after agreement alone does not prove absence of intervening writes: empty timer fixtures, settled request evidence and the paused interval must support the coordination. Any unresolved write activity makes the checkpoint unavailable.
4. Execute and retain the warm native reference from that state, including its full request, response, readback, database and generated-file effects. The existence of two matching restored branches cannot replace this warm reference.
5. Stop all application writers, verify authoritative container state and original restart policy, validate all checkpoint trees before any restore, restore both mounted trees and the SQLite backup using a separately checked restore routine, then recreate the original application at the same network identity. Preserve JWT keys and the same browser token; do not re-login. Confirm schema/data, actor permissions, original entity readback, actionability, generated files and all other relevant starting state against the warm checkpoint before the restored native branch. Repeat from that same checkpoint for the matched API branch.
6. Compare complete update method/path/body and actor authorization, response and persisted outcomes. Retain full differences. Do not omit target fields, audit rows or timestamps to obtain equality. Cases remain inadmissible until all prescheduled ordinary controls pass.

## State-specific requirements still to instantiate

The original startup regenerates the proxy/backend peer secret. A prospective comparison may establish its operation-specific consistency by checking exact substitution in the original production template, agreement with the backend environment and the same client-IP semantics. This is not currently an admitted wildcard exclusion. Other startup edits (IPv6/config rewrites, ownership, logs and process PID/cache state) need an exact file inventory and explicit checks; a blanket /data or /etc exclusion is forbidden. The pure filesystem helper does not cover a running container's memory, root-layer changes or database consistency.

SQLite backup bytes are a separate database artifact. Raw database/WAL/shared-memory files must not be blindly mixed with a restored standalone backup. A concrete restore routine must verify stopped writers, preserve the original raw checkpoint, apply the correct sidecar treatment and prove full restored logical state with the same installed driver. The separately specified stopped-writer file-replacement component implements the byte/sidecar step, but its integration with the original driver and full application checkpoint remains unqualified.

AuthContext refreshes tokens every five minutes. Retain refresh observations and require the comparison token/actor to match; do not silently suppress refresh, relax expiration or use a new login. Original access checking loads the user and permissions and checks token scope/password-change state, so token text equality alone is not the full actor proof.

The originals create timestamped audit entries and regenerate password hashes. Any outcome equivalence must use explicit operation-specific checks while retaining raw values. No such exception is admitted by this draft. Ordinary qualification can fail, and failure does not authorize a different workflow or finding-driven repair.
