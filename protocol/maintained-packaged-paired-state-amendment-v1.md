# Maintained packaged frame: common-state continuation amendment

## Timing and reason

This amendment applies only to the maintained packaged frame registered in maintained-packaged-workflow-mapping-v1.md. It is made during source mapping, before workflow admission, ordinary application controls, producer variants or continuation outcomes. At local checkpoint 278c6ef, no application in this frame has run. All previous closed studies, source bounds, repository membership, exposure records, selection order and failures remain unchanged.

Gotify's pinned model includes createdAt and its application initialization passes time.Now into the database. Separate API creates in separate resets therefore need not yield equal records even after identity normalization. Dropping generated timestamps would weaken the declared equal-state comparison. Instead, the new frame will compare two continuations from isolated copies of one API-produced state. This replaces the separate-producer requirement for this frame; it is a prospective design change, not a clarification of an unchanged protocol.

## Experimental unit and branches

Each fixed input is still one logical case: the unchanged control or one omission/null of a preselected text field. Start from the same registered clean fixture and actor setup, execute one API producer, retain H and S once, and obtain complete target-resource readback. Rejected producers remain rejected and receive no continuation credit. If producer acceptance or readback is ambiguous, classify unresolved without substituting another input.

For an accepted producer, quiesce the application using a predeclared shutdown/checkpoint procedure. Capture every writable persistence location necessary for the resource, its relationships and authentication state. This includes application/database volumes and required browser cookies/storage. Preserve the original producer trace, logical state readback, snapshot inventory and hashes. Do not edit the database, timestamps, record identifiers or validation logic. A project with external or uncopyable state is unavailable under this design.

Restore that immutable snapshot into two independent local environments: A for the equivalent API edit/readback and U for the ordinary native edit/readback. Run them sequentially on isolated local ports/networks within the registered bounds. Neither branch may see the other's writes. A browser/storage fixture is cloned for both; use the same local user and privileges. The snapshot is consumed read-only as a restore source and is never replaced with a branch result.

Before either edit, read back the complete target resource and all source-established fields/relationships needed by the continuation. Compare each branch to the retained producer state and to the other branch. No timestamp, generated identity or other value normalization is allowed in this common-state comparison. JSON object member ordering is irrelevant; array ordering and values are retained. A difference, missing field, background-state drift or incomplete restoration yields unpaired/unresolved, not a successful comparison. Browser rendering or navigation that changes the target must be recorded before the edit and included in that determination.

The API update follows the original native serializer, including readback properties actually forwarded by object spread. Capture submitted requests and all defaults/transformations. Neither observer may repair the producer state before its primary observation. The previously registered bounded repair diagnostic, if applicable, follows U's primary result and retains both traces. It does not add a new independent case or replace the original result.

## Qualification and limits

Before variants, qualify snapshot restoration and all three ordinary controls (native create/native edit; API create/native edit; API create/API edit). The API-created ordinary A/U controls must use the same captured state. Project execution registration must specify consistent snapshot/checkpoint commands, required volumes, identity checks, actor/browser state, complete readback comparison, mutation tracing and failure handling. Snapshot qualification is included in the existing maximum two 30-minute ordinary jobs; it does not grant an extra attempt. If it cannot be qualified, record unavailable and do not substitute a later workflow.

The maximum remains nine logical inputs per workflow and eighteen scientific continuation branches, fifteen minutes per branch, three concurrent jobs, free standard public Actions and the existing total $100 ceiling. Producer creation and snapshot/restore work must be included in the scheduled job budget and cost ledger, not treated as free overhead. No outcome-dependent retries, new variants, workflow substitutions or expansion of the frame.

## Interpretation

The estimand is the difference between native and API continuations conditional on the same observed API-created state, revision, actor and registered fixture. It is not independent replication of producer behavior, a prevalence estimate or a test of every time-dependent deployment state. Variants remain correlated within workflow and project family. Record the single producer count separately from the two continuation branches, including rejection/unavailability denominators. Deterministic branch ordering does not justify randomized causal claims; isolation and equal starting state support the bounded within-state comparison only.

Report full snapshot/readback qualification coverage and all unresolved cases. Keep H/S as separate descriptive observations, not ground truth. The Q1 contribution still requires sufficient independent-family coverage, competent baseline comparison, new evidence and defensible novelty. This amendment supplies none of those results by itself.
