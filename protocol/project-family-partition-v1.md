# Prospective family-level development/evaluation reservation

Applies to all20fixed candidate repositories. This is a reservation of potential evaluation material, not application admission, a completed independent evaluation registration, or proof of project independence. Metadata/package filenames/declarations are already exposed; implementation code, test contents and issue outcomes remain unread for this frame.

Before computing assignments, freeze this rule and implementation. Build connected components using (a) same GitHub owner, and (b) one conservative generator-risk bucket for repositories with .yo-rc.json filename markers or generator-jhipster/jhipster dependency declarations, including the generator repository if present in that bucket. Use only the already recorded metadata; do not infer definitive shared ancestry from the bucket. Overgrouping is deliberate to avoid treating obvious generator-related risk as cross-split independence. Unrecorded genealogy remains unresolved.

Canonicalize repository names to lowercase, sort each component's members, and compute SHA256 of the literal seed `mixed-interface-independent-frame-v1` plus a newline plus newline-joined members. Sort components by that digest. Assign the first floor(number_of_components/2) to development and the rest to evaluation_reserved. No stratification by version, installability, favorable examples, labels or method support. Do not try alternative seeds or split ratios after viewing assignments. Keep all20rows and the original search ranks/pins.

Only development implementation sources may inform future method changes. Reserved implementation sources may be processed only after candidate/comparator methods, costs, extraction limits, workflow eligibility and label policy are frozen. Any unplanned reserved-source/outcome exposure is logged; no calling exposed material held-out afterward. Source inputs for evaluation must eventually be available to both methods under the matched-information design; this reservation prevents early adaptive development, not all eventual source use.

If later genealogy links development to a reserved project, quarantine the affected reserved family from claims of independent evaluation and record the reason. Do not move it into another evaluation slot or replace it based on results. If this leaves too few independent eligible projects, report insufficient sample rather than manufacture a larger denominator. Same-owner and generator-risk components are conservative bookkeeping units, not demonstrated statistical clusters. Earlier incomplete reference auditing still applies.

No network or application execution in assignment. Record metadata input hashes, group edges/reasons, deterministic digests, assignments and verification invariants. No scientific-case credit, effect target or Q1 readiness follows from this split.
