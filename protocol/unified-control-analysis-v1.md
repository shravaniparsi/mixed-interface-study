# Unified control analysis v1

This is a retrospective engineering analysis of existing, previously examined controls. It adds no application executions and is not the primary experiment or a diagnostic-yield estimate. The input manifest hashes the selected evidence from RealWorld run 42401381642, PetClinic run 42403373655 and Quartz run 42356532879. No earlier attempts, development sweeps or diagnostic reruns are pooled into this cohort.

The source-specific attribution table lists every allowed check identifier, its observation component and its role. Unknown check identifiers, components, verdicts or statuses fail closed. Comparability guards, unresolved policy and shared observations cannot generate exclusive API or UI continuation credit. Missing or ineligible assigned observations are unresolved, never clean passes. A common native read after an API action remains a shared native observation.

PetClinic's revised adapter performs direct target and relationship reads before either continuation. The extension places these in prefix-state inspection. Its finite projection reuses the unchanged historical reducer's entity and graph predicates; request admission, pre-candidate snapshots and shared binding reads are checked separately. Extra or missing binding operations are rejected. New guard/capture/cleanup requirements remain tied to the new runner and helper hashes. Original observations and the historical reducer are unchanged.

Pairs come from the existing candidate inventory, not a new outcome-based match. Eligibility for this engineering comparison requires matching declared producer routes, initial and pre-candidate state, observed producer commands, prefix outcomes and reset evidence. Accepted pairs additionally require matching source-recorded post-prefix business state and intended consumer commands. RealWorld uses its already-recorded business projections; this analysis adds no timestamp or identifier exemptions. Legacy RealWorld reset hashes remain source-recorded assertions, not independent cleanup qualification. PetClinic compares full owner graphs and distinct backend PIDs with confirmed exits. Quartz reuses its previously validated control-pair gates.

Rejected-prefix pairs receive no continuation contrast. UI-only controls remain separate singleton records. Accepted, interpretable pairs receive API-only, UI-only, both or neither labels for *assigned-check mismatches*. Shared mismatches are reported separately by branch and observation component. These labels are not adjudicated defects or root causes. Failed comparability guards yield unresolved pairs; attributing a native payload mismatch to application serialization rather than the adapter requires separate adjudication.

Report branch records, declared pair entries, accepted pairs, rejected-prefix pairs, unresolved pairs and singleton controls by source catalog. Catalog entries overlap across engineering and development strata and are not independent samples. No p-values, prevalence, effectiveness claims or primary eligibility follow from these controls. An ordinary control cohort is expected to show no assigned-check mismatch.

The executable builder verifies all frozen input hashes and regenerates both PetClinic component extraction and the unified report. CI verifies exact regeneration without running applications. Primary scheduling, interruption/browser cleanup, cost instrumentation, broader evaluation and the final freeze remain outstanding.
