# AccessList original generated peer-state comparison

This prospective rule covers only the startup-generated peer secret in the original production.conf, the matching s6 environment file and the actual original backend process environment. No application has run. It is not a wildcard environment/configuration exclusion or full starting-state qualification.

Require the acquired original template SHA256 e5afb7b37e50ea5eaf4bf982fa7e289236b2460c56658748af541806882c919c. Fix the ordinary admin port to 81. Require the secret file to contain exactly 64 lowercase hexadecimal characters, with no trimmed whitespace or repaired format. Require exactly one NPM_PEER_SECRET entry in the backend process environment and exact agreement. Identify that process by a node executable, final index.js argument and /app working directory; require exactly one match and fail on inaccessible or ambiguous process evidence. The inspection helper reads only that matched process environment, returns hashes/consistency facts and never prints its contents.

Reconstruct the complete configuration using the original template substitutions and the exact original line-wise IPv6 transformation for the prospectively selected boolean setting. Require the entire actual file to match reconstructed bytes. Only then replace the single verified secret occurrence with its template marker for cross-startup comparison. Compare that normalized hash across warm/restored states while retaining the full raw configuration privately and reporting its original hash. Reject all other configuration changes. Do not write or inject a secret or modify the original application.

This rule allows the documented regenerated secret to differ only when its original proxy/backend consistency is proven. It does not permit a different actor/token, relaxed rate limiter, other environment changes, a different proxy endpoint, unexplained file modes/ownership/timestamps, or suppression of the raw observation. The enclosing qualification must still check the fixed network topology/client identity, original container/process lifecycle, database permissions and all other relevant starting state. A pure-template test is not live runtime qualification.
