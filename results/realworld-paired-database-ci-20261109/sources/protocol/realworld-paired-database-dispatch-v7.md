# Bounded live paired database diagnostic, version 7

This is a new engineering diagnostic using four previously exposed cases: valid bio route control, null username, 60-character username and 61-character username, in that order. Each case executes its registered API and UI consumer branches from independent resets, once each. The unsuccessful producer path retains both branch identities but does not launch either continuation. No new primary boundaries, repeats, restart observations or stable-defect claims are introduced.

The exact jobs come from the frozen exposed identity registry. A source certificate and dispatch checkpoint precede execution. The owned-process wrapper bounds each pair to 180 seconds, retains every attempted job and confirms teardown. Any runner, capture, source, reset or verification failure stops dispatch. The first route control must be clean. A semantic terminal halt prevents subsequent jobs; a halt on the final scheduled pair can coexist with completion of the bounded diagnostic measurements. The output explicitly retains those semantic classifications and is not a completed terminal campaign. There is no resume, replacement or retry within an attempt.

The version 7 loader validates source inventory, application revisions, registry, job, branch order, runtime, timing and fixture resets. It reconstructs the existing semantic checks unchanged, then independently verifies each branch's trace measurements and database captures. Capture directories are derived from the exact registered branch ID. The database projection includes the selected user fields and article identities, content and ownership. The producer measurement compares the before-prefix and after-prefix committed-state projections from that branch. The optional post-continuation projection is retained separately. No other execution supplies missing data.

Native UI qualification requires a real captured settings edit, fresh actor binding, exact submitted command, confirmed response capture drainage, and a database snapshot before the shared API checks. Browser-generated requests caused by saving may occur before that final snapshot. Backup costs remain nested in instrumented adapter/branch timings and are not directly comparable to version 6 timings.

Success means independent reconstruction of the declared diagnostic evidence, not predetermined application outcomes. Username length requirement policies remain unresolved. Shared API-prefix failures cannot establish an API-versus-UI discrepancy. Original archives, including the halted identity campaign, are unchanged. P2–P5 remain open; these engineering repetitions are not independent primary samples.
