# RealWorld exposed identity dispatch v6

This engineering campaign selects exactly the previously exposed profile bio control, null and empty username cases, and the 60/61-character username cases from the pinned development registry. It does not select or execute untouched primary boundaries. Both consumers receive independently restored SQLite fixtures. Null/empty inputs retain rejection expectations; username length policies remain unresolved.

A versioned pair runner snapshots the identity adapter, contract, extractor and shared capture dependencies. The loader validates exact schedule membership, branch order, registry, source inventory and hashes, pinned application revisions, fixture hash equality, trace bindings, timing and owned-process cleanup. The independent extractor reconstructs profile and related-state checks from captured responses and requests. The pair bridge requires equal actor, initial state, prefix command and status, accepted state, intended continuation command and reset identity, plus distinct evidence for each branch.

Terminal policy v2 governs every result. Unknown acceptance policy alone remains unresolved and does not trigger repeats. An independently reconstructed failure of a specified preservation check takes diagnostic precedence while the unresolved policy remains recorded. Application response failures and incomparable observations remain incomplete and receive the standard bounded repeat schedule. Capture failures, timeouts, execution failures and unconfirmed cleanup halt. The initial sweep and followups are immutable, checkpointed before dispatch, and cannot be resumed or replaced. No observed failure is silently converted into a clean qualification result.

The campaign validator reconstructs the entire ledger and reports all terminal categories rather than demanding a particular application result. Verification certifies evidence and dispatch consistency; it does not certify all cases as semantically complete or establish a defect count. Every attempt is retained. Live coverage may be updated only after reviewing the verified outcomes and preserving all remaining policy and unexpected-acceptance gaps. Primary P3-P5 gates remain open.

The first hosted attempt stopped in baseline setup before any candidate write because the article-list response omits body. That attempt is retained under `manifests/realworld-identity-setup-failure.json`. The corrected snapshot adds a full detail read for each pinned fixture article and checks its fields against the list summary. Both projections and tests use that shape. Qualification requires a separate fresh campaign, not a resumed or relabeled first attempt.
