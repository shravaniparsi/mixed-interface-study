# PetClinic terminal dispatch v2

This engineering campaign selects only the three accepted and three rejected controls already exercised in the integrity pilot. Its frozen contract binds the full registry bytes, exact candidate selection, alternating consumer order, and all permissible initial and conditional followup jobs. It does not freeze or execute the primary study.

Each immutable job starts two independent H2 backend processes, one per continuation branch. A fresh browser is launched per pair and a fresh context per native branch. The unchanged native Angular frontend is owned by the campaign. The versioned runner preserves the original runner's commands, capture, identity and state guards; it changes selection and branch scheduling. Job and source hashes, raw branch evidence, backend ownership and cleanup, and the frontend exit are retained. Cleanup records establish direct-child exit, not detached descendant absence.

The common terminal campaign checkpoints before each dispatch. Only completed diagnostic observations can schedule the bounded repeat policy; an execution failure halts and retains the attempt. A runner timeout or nonzero exit produces a halted-executor record, not a guessed semantic outcome. Fresh output directories are mandatory; resume and replacement are unsupported. The campaign has a 480-second outer deadline and a 120-second per-pair deadline; an exhausted deadline can leave followups incomplete and cannot yield stable evidence.

Extraction uses the separately tested PetClinic terminal extractor. Exact selected prefix statuses (201 or 400) remain required. Unexpected acceptance/rejection and unsupported assertion failures are not qualified scientific outcomes. The six-control runtime qualification requires three clean accepted pairs and three matched rejections, verified by independently reconstructing the complete campaign. Synthetic tests exercise binding corruption and failure retention; they are not application results.

Primary dispatch remains disabled pending remaining corpus bindings, cost accounting, bounded primary batches and final freeze.
