# PetClinic exposed-registry dispatch v3

This engineering campaign contains only the eighteen candidates already executed in the development slice. The four immutable batches cover owner required-field omissions, owner formats, pet fields, and visit fields. Each includes a positive reference from the same workflow. The owner reference appears in two batches: nineteen initial pair attempts cover eighteen unique candidates and do not imply nineteen independent samples.

The contract pins registry bytes, prefix policy bytes, exact batch membership, consumer order and permissible followup jobs. Every branch owns a fresh H2 backend process; every pair launches a new browser. The assigned consumer order alternates within each batch. Batch identity is recorded in both the plan and runner summary. The new runner differs from v2 only in immutable selection/batch binding and allowing recorded pair-state inequalities to reach the comparability classifier; unknown assertions still halt.

The v3 prefix extractor distinguishes completed requirement mismatches, unresolved policy, application-response failure, and execution failure. Initial diagnostic or response-failure outcomes trigger two candidate repeats, each with the batch's positive reference, using the common terminal policy. Server errors remain semantically incomplete even if repeated identically. Whitespace policy observations do not trigger diagnostic repeats. No attempt is resumed, replaced or discarded.

Each pair has a 120-second deadline. Each batch has a 900-second outer deadline, with termination and a 20-second kill grace; hosted jobs have a 25-minute overall ceiling. At most two fresh hosted jobs run concurrently. Expired or failed batches retain their partial ledgers and cannot be marked qualified. These engineering limits do not satisfy the separate primary-study batch and cost-accounting gates.

Independent replay verifies every source snapshot, environment hash, job, raw branch binding, direct-child cleanup record, common-policy schedule and result. Qualification requires completed ledgers and clean positive references, not predetermined outcomes for the other cases. Application-response failures remain explicit incomplete observations. A completed mismatch is not a defect adjudication or a new discovery; the hyphenated-name issue was already observed in development. Primary freeze remains false.
