# Previously executed RealWorld rejection controls, dispatch v4

This version admits six exact records from realworld-boundary-registry-v1: article-valid, comment-body-valid and profile-bio-valid, followed by article-body-omitted, comment-body-omitted and profile-username-empty. All three rejection pairs were previously executed in the integrity qualification. The new registry preserves their payloads and expectations and fixes selection order by canonical digest. It does not enable untouched boundaries or generated/native-producer cases.

Each rejection uses the same-workflow positive API baseline as its repeat reference. The unchanged common terminal policy schedules no repeats for complete matched rejections; diagnostic mismatches remain repeat eligible and missing evidence halts. A scheduled consumer branch whose producer is rejected must record an explicit stop and no trace events in the continuation phase. The assigned consumer remains unreached and receives no exclusive detection credit.

The prospective adapter's existing full observable-state snapshot is used without modifying it. The snapshot covers public current-user fields, the complete own-article list, global tags and their comments. Independently reconstructed snapshots must be readable before a pair can be a complete matched rejection. A coherently recorded but unreadable post-rejection snapshot is incomplete evidence and halts; it does not establish preservation. A trace-supported changed snapshot remains a mismatch even when the older narrow count predicate passes. This is bounded API-visible state preservation, not database atomicity.

The new wrapper corrects a completeness gap in the prior pair classifier: the old component reducer can legitimately record an unreadable snapshot without a structural issue, but its absence of a failed predicate must not be interpreted as a clean rejection. Old source-pinned archives remain immutable. Tests explicitly reproduce that gap with synthetic evidence and verify the new incomplete classification. They also cover missing snapshots, forged state verdicts, hidden continuation traces, explicit stops, server errors, cleanup precedence and end-to-end accepted/rejected scheduling. HTTP prefix statuses enter repeat signatures so different observed statuses are not collapsed.

The six-pair live qualification expects six accepted baseline branches and six HTTP 422 rejection branches, with readable unchanged post-rejection state, no downstream continuation and no follow-up jobs. Negative fixture counterexamples are not live application findings. Unexpected acceptance of the empty-username case remains outside the accepted-profile normalization helper's qualified scope and must not acquire complete semantic qualification by assumption.

Fresh job fixtures, independent branch resets, the 180-second job deadline, five-second termination grace and two-second kill confirmation are unchanged. The outer suite is bounded to 480 seconds. Incomplete runner exits halt and retain evidence; no automatic replacement or resume is permitted. This stage adds no broader lifecycle fault-injection qualification. P2 remains open for other legacy/generated RealWorld and PetClinic bindings; primary batching, timing scope and final freeze remain outstanding.
