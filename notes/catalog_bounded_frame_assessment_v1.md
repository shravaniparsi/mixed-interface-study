# Bounded catalog study: contribution decision

The current registered cohort does not support the proposed empirical claim.
Twelve projects were retained, four entered application qualification, eight
qualification attempts finished, and no workflow completed all required controls.
Zero scientific cases ran. This is a failed feasibility study for the registered
comparison, not a qualified null result about frontend/API incompatibility.
It does not supply Q1-ready evidence or establish incremental detection value.

## What the retained evidence supports

Three projects have recorded scope exclusions (ChartDB, socks5-proxy-server,
sE2EEnd). Four exhausted their two allowed runtime attempts (Mathesar, Viseron,
Nginx Proxy Manager, SeatSurfing). Five have bounded pre-execution unavailability:
OpenELIS bootstrap under the source cap, CloudBeaver executable provenance,
Meme Search and changedetection.io comparator mapping, and Jitsi candidate
mapping. The latter dispositions are not exhaustive project exclusions. Unused
source capacity and incompletely covered workflows remain visible.

The source audit verified all 563 scheduled blobs across 49 waves, totaling
4,679,766 decoded bytes, against both retained SHA256 and Git blob identities.
Per-project counts and bytes match the progressive ledgers. This verifies source
provenance and accounting, not scientific validity or complete source coverage.

Live GitHub metadata confirms all eight application qualification attempts are
terminal failures. Their reported run durations sum to 1,351 seconds (22 minutes
31 seconds). Each reports zero Ubuntu billable milliseconds. These values cover
only these eight jobs: preparation/unit CI, historical frames, storage and any
account charges are outside this subtotal. A total-project dollar-cost claim
is not established by the timing endpoint. No paid runner or model expenditure
was introduced in this closure work.

## Why the scientific claim remains unresolved

The unit of scientific evidence would have been an accepted producer state with
qualified ordinary controls and comparable native/API continuation, grouped by
independent semantic obligation and project lineage. There are no such cases
in this cohort. No defect frequency, comparative sensitivity, effect size or
confidence interval can be estimated from zero qualified cases. Infrastructure
failures and unsupported mappings cannot be converted into application defects,
true negatives, or source-aware baseline errors.

Mathesar reached native production and complete ordinary request matching but
failed a registered ancillary-request check. Viseron exited during initialization.
Nginx Proxy Manager failed native navigation with a retained log-path permission
error. SeatSurfing failed browser-worker startup. These observations explain
qualification failures; they do not establish application validation defects.
The final failure root causes are not all independently intervention-tested.

The exact native-JSON request gate also limits the question: HTML-form editors
with distinct JSON APIs are relevant to mixed-interface compatibility but do
not automatically fit this comparator. Broad Docker/reference screening did
not guarantee two editable text fields, source-matched deployments or feasible
state restoration. The source cap prevented the OpenELIS fixture route. These
are limitations of the design and execution envelope, not natural properties
of the research problem being tested.

This cohort is curated and not a random prevalence sample. Source-reviewed
comments disclose prior fixes or workarounds and cannot be called blind findings.
Fork flags alone do not establish independent ancestry. Earlier closed studies
remain separate; their rows cannot be pooled to inflate independent evidence.

## Decision and remaining goal work

Do not run further application attempts or substitute workflows in the four
exhausted projects. Do not silently change the complete-request comparator,
source limits or scientific inputs. Do not open another cohort merely to search
for positive findings. Preserve this study as feasibility evidence and keep the
larger publication goal incomplete.

Before any further empirical study, a methodological decision is needed: can
a development-qualified comparison of equivalent user operations accommodate
HTML and JSON transport without hiding different fields, normalization or side
effects, and can a deployment harness pass ordinary controls reliably? Those
are research-design questions, not permissions to reinterpret this cohort.
A defensible future design would require explicit development qualification,
competent baselines, outcome-independent selection and a new prospective
registration before outcomes. If those foundations cannot be established within
the budget, the honest decision is not to claim the proposed empirical paper
is ready. Manuscript polishing cannot supply the missing evidence.
