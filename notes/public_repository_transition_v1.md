# Public repository transition

The repository was changed from private to public on 10 November 2026 with explicit user authorization. GitHub confirmed PUBLIC visibility. Unit-check run 42796847066, attempt three, acquired a runner and executed checks, establishing that the previous provider billing rejection no longer prevented this public workflow from starting.

That first public attempt exposed a report-portability issue: analysis enumerated artifact directories in filesystem order. Reconstructed timing and setup lists therefore differed across hosts, with possible last-bit differences in accumulated floating-point totals. The follow-up public test also exposed a Python-version difference in built-in floating-point summation. All case outcomes, raw timing observations, counts, categories and exposure labels were unchanged. The three analysis entry points now sort artifact and native-summary paths and use explicit `math.fsum` for timing totals. The saved derived primary report was regenerated; raw evidence and frozen runtime sources were not changed. A regression test reverses filesystem enumeration and requires the same complete reconstructed report.

No application experiment was rerun during the visibility change or CI diagnosis. Before recovery application dispatch, the public runner environment must be measured and qualified. The existing experimental acceptance contract was frozen for specific two-CPU Linux host contexts; public hosted Linux runners may use different hardware. Successful source CI alone does not authorize changing those environment restrictions. Any additional accepted context must be documented prospectively and validated with the existing empty/nonempty live controls, with timing strata kept separate.
