# What the benchmark's oracle establishes

The registered runtime experiment tests conformance to RESTestBench's supplied requirements and golden tests. Passing the original program and rejecting a mutant does not by itself establish desirable application behavior or detection of a real-world defect.

A concrete counterexample is NestJS requirement 28 at upstream commit `4decc1e36ea3dd41b64ce3e3ac6a85bc72df36ae`. Both description modes explicitly describe the absence of ownership authorization as a security vulnerability. The precise description requires an authenticated non-owner's update and deletion to succeed. The golden test asserts successful responses, the attacker's changed title in both the update response and later retrieval, and deletion of a second article. This is intentional documentation of existing behavior, not an undisclosed flaw in the benchmark. Its three registered mutants remove assignment, remove persistence, or delete a nonexistent slug; they are not ownership-check repairs.

This matters to the proposed study: externally supplied text is separate from our checker but is not automatically an independent normative specification. A successful inference system could faithfully recover this requirement and enforce the undesirable behavior. Any later comparison must identify whether its target is requirement conformance, regression detection, or security/correctness. Those labels are not interchangeable. The currently registered runtime phase remains unchanged, including this requirement and all its mutants. We have not executed a security repair or measured its effect on the score.

Local evidence is `data/requirements/nestjs-realworld/requirement_28.json` in `results/restestbench-applicability-v1/inputs.tar.gz` (SHA-256 `599363110d05bbb2d1ab0e735e29bd975510d9c85c9b3ce5bcfe16ab2af84012`) and pinned `data/tests/nestjs-realworld/test_28.py` (SHA-256 `39f680e9c2c6d62dd4d54b5e18ee24624cf0dc143e0a8b611563024e37408896`, independently matched to the valid-input inventory). The complete precise description and golden test were inspected. This is a source-supported scope clarification, not a count of additional natural defects or a general claim that the benchmark is invalid.
