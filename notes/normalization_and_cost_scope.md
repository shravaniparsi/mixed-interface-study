# Normalization and execution-cost scope

The pinned backend stores unique article-tag relationships and serializes their names in sorted order. The profile update schema distinguishes omitted fields from explicit null; bio/image null or empty values serialize as null. The pinned native settings form filters null values from submissions, and the new-tag control trims entered tags. These implementation facts now have an explicit policy and executable accepted-state expectations. They are not independent defect requirements.

The policy preserves exact submitted JSON values, including array order, duplicate elements, missing properties, null and empty strings. Tag state membership and returned sorted-unique representation are separate checks. Whitespace and case are preserved by the harness. Partial article nulls, identity changes and credentials remain outside these helpers rather than receiving guessed defaults. Seven source files were byte-compared against the pinned Git objects and archived with hashes.

The new audit reads the existing 22 RealWorld controls without rewriting their records or old verdicts. Eleven applicable accepted controls match their source-based expectations, eight rejected prefixes receive no accepted-state prediction, and three comment controls remain outside this normalization scope. For the two body-update controls, preserved fields come from the pre-prefix article listing and the new body comes from the captured command; the old body is not claimed to have been observed. Fourteen synthetic tests exercise counterexamples including duplicate and unsorted responses, missing/null distinctions, unsupported partial nulls and whitespace. They are software checks, not new application observations.

Reproduce with `PYTHONPATH=src python scripts/audit_normalization_controls.py --verify`. CI checks exact regeneration. The normalization helper is not yet wired into the prospective application runners, and the archived controls do not exercise all representations covered by its synthetic tests. Integration requires new source qualification and native representation controls before primary use; historical reports retain their original meaning.

The timing contract starts a branch before reset and ends after evidence capture and confirmed teardown. It includes startup, authentication, producer, continuation and shared verification. Common build/frontend setup is separately reported outside that branch interval. Exclusive phase intervals must not double-count asynchronous capture; gaps and overruns remain explicit. Existing combined phases cannot establish pure channel costs. Common instrumentation and later calibration are still pending.

See `protocol/normalization-and-cost-scope-v1.md` and `manifests/normalization-policy-v1.json`. This step starts no applications, executes no new boundaries and does not complete the primary freeze.
