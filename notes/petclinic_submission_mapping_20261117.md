# Automated submission mapping: exposed development application

Recovered the exact TypeScript 6.0.3 compiler package named in the application's pinned lockfile. Verified the archive against the lockfile SHA-512 integrity before loading its parser. Only the compiler module was loaded locally; no npm installation, application module execution, Angular component mounting or API service run occurred. Parser/archive hashes are recorded with the mapping manifest.

Implemented a bounded TypeScript-AST recognizer that follows a form call to its bound model, the submission callback, injected service call, corresponding service method, HTTP write and body parameter. It accepts a final object spread of the form-model value, including a unique const payload alias, and rejects recognized transformations, direct assignments, overlapping fields and ambiguous calls. The five field names come from the earlier source inventory, not guessed API names. Parsing syntax is not proof of full program semantics: import resolution/shadowing and indirect side effects remain explicitly unqualified.

On the two pinned, previously exposed owner components, the recognizer traces five fields into the POST body and the same five into the PUT body. The relation is identity if the property is present in the form model. The URL remains its source expression; base URL configuration is not inferred. These ten field-path entries share one project and five field identities, and are not independent data cases, defects or ten semantic contracts.

Eight development checks pass: add and edit source traces, plus rejections for a later spread override, transformed HTTP body, mutable payload alias, direct payload mutation, different bound model and transformed spread. These adversarial source edits are engineering fixtures, not injected defects in a scientific benchmark. No performance comparison or extraction-accuracy claim is made from them.

The source mapper does not yet establish field activity, actor/lifecycle conditions, initialization/defaulting semantics, indirect call effects, import binding resolution, interceptors, runtime serialization, persisted state or independent business requirements. The previously inspected edit component's empty-string defaults remain distinct from identity at submission. The mapper must not be used to propagate persisted-state rules backward through those defaults. All current output is static mapping candidates, not qualified executable API obligations.

Next qualification should resolve the same source chain's activity/defaulting and actual binding semantics, or explicitly reject unsupported patterns. Adding more source patterns without a qualified chain would not advance the original workflow-compatibility experiment. Independent-input sampling, strong comparator qualification and a measurable method benefit remain outstanding. Cost remains zero paid compute/model calls for this work.
