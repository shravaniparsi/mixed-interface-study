# PetClinic execution integrity and hosted controls

The PetClinic adapter now checks exact submitted commands, returned-resource relationships and complete loaded native form fields. Visit continuations resolve the returned visit.petId, then the pet's ownerId, before editing. Pet continuations check the returned ownerId and displayed owner. Immediately before each candidate POST, after valid setup resources exist, the adapter records the owner/pet/visit graph. Rejected prefixes are compared with that state; HTTP 5xx remains separate from HTTP 4xx rejection.

The [hosted application run](https://github.com/shravaniparsi/mixed-interface-study/actions/runs/42403373655) passed at source commit `631a6675a6ddf60ceb93c5854ce222da8420ad23`. The predeclared suite covered three previously examined positive candidates and three known rejection candidates, each through API-semantic and fresh-native continuations with independent backend resets: twelve branches in total. All six positive branches completed their intended edit with matching final graphs across the paired channels. All six rejected branches returned HTTP 400, executed no continuation, and preserved their pre-candidate graphs.

The run passed 72 integrity guards. Three native contexts captured thirteen API requests and thirteen matching responses, with no capture errors or incomplete drains. Every branch confirmed its owned backend exit; the wrapper also confirmed frontend termination. Backend shutdown now has separate graceful and forced-exit deadlines. These successful controls do not establish full browser-descendant cleanup or interruption recovery.

The unchanged pinned applications were rebuilt on the hosted runner. Backend native verification passed 248 tests with no failures, errors or skips; the frontend passed 88 native tests. The [harness unit run](https://github.com/shravaniparsi/mixed-interface-study/actions/runs/42403343740) passed 182 Python, six bootstrap and 47 Node tests, 235 total. Native and harness tests establish execution readiness; they are not research samples. The rebuilt jar's own hash and observed runtime versions are retained rather than assuming binary identity with the earlier Mac build.

Downloaded evidence was independently checked against the pre-dispatch source and environment hashes. Recomputed validation matched the hosted result exactly. The [protocol](../protocol/petclinic-integrity-validation-v1.md), [selection](../manifests/petclinic-integrity-controls-v1.json), all twelve raw branch observations and compact provenance are retained in the repository. Full logs and source snapshots are also downloaded under `results/ci-runs/42403373655`.

Graph equality covers the returned owner/pet/visit API projection, not database atomicity or resources outside that projection. These are engineering controls on previously examined cases, not new defects, independent samples or an estimate of diagnostic advantage. The historical component reducer remains restricted to its originally qualified source. Its new-source integration and unified paired analysis are next, followed by broader paired evaluation and timing/cleanup qualification.
