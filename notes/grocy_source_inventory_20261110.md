The existing prospective resource priorities remain products, locations and tasks. Inspected files under `https://github.com/grocy/grocy/blob/7d15c46bbdc35d4958cae99209ba170667dc1d64/`:

The controller itself does not show form-specific validation; filtering, database constraints and other layers still require inspection.
- `views/locationform.blade.php` and `public/viewjs/locationform.js`: name is required in the HTML form. - `grocy.openapi.json`: schemas declare Location, Task, ProductWithoutUserfields, QuantityUnit and ApiKey. Some examples show numeric strings and nulls despite narrower property types. Response-schema disagreement is therefore a measured signal, not automatically a defect authority. The API and native observer must not receive separate credit for a shared contract discrepancy.

Ordinary scoped actor setup should grant the documented master-data/stock/task permissions, not infer that an admin actor is required.

Use an ephemeral actor/password/key and omit authentication material from retained output. No fixed password is needed in a public registry.
- `views/login.blade.php`: username input, password input with id `password_input`, hidden base64 password field, and login button. Authentication requests must not enter the retained resource trace.
