Prepare a new reproduction directory
The commands below are instructions, not a record of a second run. Set the four environment variables to directories on the reproducing machine. PETCLINIC_ARTIFACTS is the directory containing these notes, manifests and scripts. Put Node 24.19.0 on PATH, and point PETCLINIC_JDK at the JDK 17.0.2 installation. No global package installation is required.

export PETCLINIC_ARTIFACTS="/absolute/path/to/mixed-interface-study"
export PETCLINIC_WORKDIR="/absolute/path/to/new-petclinic-runtime"
export PETCLINIC_JDK="/absolute/path/to/jdk-17.0.2"
export PETCLINIC_PLAYWRIGHT_MODULE="/absolute/path/to/playwright"
mkdir -p "$PETCLINIC_WORKDIR"
git clone https://github.com/spring-petclinic/spring-petclinic-rest.git "$PETCLINIC_WORKDIR/backend"
git -C "$PETCLINIC_WORKDIR/backend" checkout --detach 5180cc9bd0163393c4e628bedc1bc4c27cfaab1b
git clone https://github.com/spring-petclinic/spring-petclinic-angular.git "$PETCLINIC_WORKDIR/frontend"
git -C "$PETCLINIC_WORKDIR/frontend" checkout --detach fba8956cbdd04e09973f81eb39379955a825bfc3

Playwright must already be available at the configured module path, or be resolvable as the package name playwright from the runner. For a new reproduction environment, a project-local installation of playwright@1.62.1 is sufficient; use the installed Chrome browser rather than downloading another browser. The recorded pilot used the existing bundled package and existing Chrome. For an explicit browser path set PETCLINIC_CHROME_EXECUTABLE; without it the runner selects Playwright's Chrome channel. Different browser/runtime versions must be recorded as a different reproduction environment.

Build and run native checks

JAVA_HOME="$PETCLINIC_JDK" MAVEN_USER_HOME="$PETCLINIC_WORKDIR/maven" ./mvnw -B -Dmaven.repo.local="$PETCLINIC_WORKDIR/maven/repository" verify
cd "$PETCLINIC_WORKDIR/frontend"
npm ci --no-audit --no-fund --cache "$PETCLINIC_WORKDIR/npm-cache"
npm run test:ci

Start servers in separate terminals
Backend, foreground:
"$PETCLINIC_JDK/bin/java" -jar "$PETCLINIC_WORKDIR/backend/target/spring-petclinic-rest-4.0.2.jar" --server.address=127.0.0.1 --spring.jpa.show-sql=false

Frontend, foreground:
cd "$PETCLINIC_WORKDIR/frontend"
node node_modules/@angular/cli/bin/ng.js serve --host 127.0.0.1 --port 19766

The native backend uses H2/spring-data-jpa, an in-memory seeded database, port 9966 and /petclinic context. Native security is disabled; both routes use the anonymous actor. The unchanged frontend expects http://localhost:9966/petclinic/api/. This API endpoint must remain compatible with the frontend environment; changing the runner's --api option alone does not reconfigure Angular. Wait until the backend health endpoint http://127.0.0.1:9966/petclinic/actuator/health reports UP and the frontend reports readiness.

Run the paired routes
node "$PETCLINIC_ARTIFACTS/scripts/petclinic_route_smoke.mjs" ui --output "$PETCLINIC_WORKDIR/results/paired" --playwright-module "$PETCLINIC_PLAYWRIGHT_MODULE"

Stop only this backend using Ctrl-C in its terminal. Restart the identical backend command above, leaving the frontend running. Wait for health UP, then run:
node "$PETCLINIC_ARTIFACTS/scripts/petclinic_route_smoke.mjs" api --output "$PETCLINIC_WORKDIR/results/paired" --playwright-module "$PETCLINIC_PLAYWRIGHT_MODULE"

The browser runner checks for ten initial owners and records a canonical full owner-graph hash. It accepts --frontend, --api, --output, --playwright-module and --chrome-executable, with PETCLINIC_* environment alternatives listed by --help. Only loopback HTTP endpoints are accepted; browser requests outside the allowed loopback ports are blocked. It does not start or reset servers. Use a new output directory for each repetition; existing route files are rejected.

Compare ui-route.json and api-route.json: both status values must be passed, and initial_state_sha256, created and final_state must be equal. For the creation payload, parse the UI trace POST request JSON and compare it with the direct API POST request object. Both recorded pilot payloads included id:null and the same five editable fields. Keep both raw traces even when a comparison fails. Stop both owned servers after the run.
