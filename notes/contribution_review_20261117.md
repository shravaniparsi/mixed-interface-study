# Contribution review after the matched-input comparison

This is an internal review of the current evidence package and prospective manuscript, not an external referee report or a journal acceptance forecast. The project studies workflows that combine browser and API operations. Recent development work validates request serialization and finds schema/backend differences on one application. Its current supplied-rule evaluator has substantially less coverage than native-source replay on the same observed fields.

1. Publication-blocking contribution issue: the current conditional evaluator is not a demonstrated new algorithm. Its field result is 4 determinate observations against replay's 14, with no disagreement on four shared decisions. Adding missing predicates would repair coverage but would not by itself establish novelty. Decision: retire the new-algorithm claim for this implementation; retain it as a development baseline. Do not weaken D or rerun favorable authored inputs to rescue the claim.

2. Publication-blocking target issue: the original manuscript asks about API-created state that breaks a later browser workflow. The recent five-fixture experiment observes registration HTTP responses, not a later native workflow. Its three schema-accepted/backend-rejected fixtures must not be presented as that phenomenon. Satisfying this objection requires native end-to-end producer/readback/consumer observations, ordinary valid controls and equivalent actor/state assumptions, with unsuccessful producer attempts kept separate.

3. Publication-blocking inference issue: current assertions are pre-existing tests but independent requirement authorship is unverified, and fixtures are exposed. The next independent study needs prospectively fixed sampling, workflow eligibility and outcome definitions. Descriptive interface incompatibility may be measured without asserting an intended-behavior defect, but that distinction must be explicit; a defect claim still needs supporting obligations.

4. Publication-blocking generality issue: the metadata frame is the first 20 star-ranked Angular/Spring Boot repositories, partitioned conservatively into development/reserved families. It is neither a random sample of web applications nor established independent projects. The nine reserved repositories must not be consumed as a search for favorable findings. No significance claim or sample-size inflation from field/payload variants is justified.

5. Publication-blocking method-effectiveness issue: the original selector and agent-intervention questions remain unsupported. A descriptive empirical paper would be a separately registered design, not a retroactive positive result for those questions. It must explain what knowledge it adds beyond existing client/server validation comparisons, or it is not a defensible Q1 contribution.

The next decision-changing development qualification is an ordinary-valid native admin create/edit workflow in the already exposed application. The built JAR contains the original browser assets; login/navigation setup still needs verification. This control can establish whether a genuine native workflow harness is feasible. A successful control alone would establish neither prevalence nor novelty. No new outcome-driven payload search follows from this review.

The active goal remains stronger independent evidence and an honest Q1 assessment. This review does not mark that goal achieved, promise publication, or make more implementation passing tests a substitute for the required evidence. The initial manuscript remains a prospective draft and must not be submitted as completed work.
