## First dependency evidence

All three registered Gotify dependencies were retrieved and hash-verified. Applications.tsx binds the create callback to appStore.create and the edit callback to appStore.update({...toUpdateApp, name, description, defaultPriority}). AppStore posts the three create properties to application, lists application for readback, and puts to application/{id}. Critically, update destructures only id and serializes the remaining object: the TypeScript Pick annotation does not remove runtime properties. A competent API continuation must preserve this actual native mapping rather than reconstruct a narrower three-field update. Authentication, server routes, persistence and immutable package relation remain unresolved. NumberField keeps a string input and passes successfully parsed integers; numeric priority is ordinary fixed context, not a varied text field.

AdventureLog review has begun. Entry 28 directs invitations to Django admin; entry 29 is an information dialog. CategoryModal's script and input bindings establish create and edit for display_name and icon, POST /api/categories, PUT /api/categories/{id}, and GET /api/categories. Create derives name from display_name and defaults an empty icon; edit spreads the readback object and trims display_name. The icon has an ordinary text input, not solely an emoji selector. Full markup, API proxy binding, stable persistence, actor and source/package relation remain unresolved. Category is an earliest plausible resource, not yet selected. ChecklistModal was only partially displayed in a truncated tool response and is not recorded as fully reviewed.

The next dependency wave registers four explicit Gotify imports, two server route candidates justified by the observed application endpoint, and AdventureLog's explicit types import and sole API catch-all route.
