# Mapping review in progress

This is partial source assessment, not final cohort selection. All 240 files were collected uniformly; the remaining candidate review is pending.

Gotify's earliest two selected paths are application create/update dialogs with name and description scalar text fields, plus numeric default priority. Both delegate persistence to callbacks. The first dependency wave registers same-directory parent/store candidates and the explicit NumberField import before reading them. These are binding investigations, not proof of API identity or admission. Client create/update expose only one scalar text field plus numeric expiry; user create/update exposes username plus an excluded password and boolean rights. Neither currently satisfies the two eligible text-property requirement.

Prest's two selected views were read completely. The authentication dialog collects a secret bearer token into client memory or sessionStorage, and the other file is a generic dialog primitive. Neither establishes an eligible persisted resource create/edit pair in this fixed prefix. This is a scoped sampling limitation, not evidence that Prest Studio lacks CRUD functionality.

Maxun's first three selected views were read completely. UrlForm is a read-only address/navigation control, ProxyForm switches between configuration creation and configured-state display/test/removal rather than an established native edit flow, and KeyValueForm is a nested dynamic-key editor with no persistence binding. The later robot create/edit files still need review. No final Maxun eligibility decision is made.

No workflow has been selected, no ordinary controls have run, and no findings have been measured in this frame. The source mapping identifies eligibility and dependencies; it must not favor a predicted validation discrepancy.
