# Adapter-preservation prior-art scope check

The claim-source-verification skill required a separate skeptic. A fresh-context skeptic inspected the public records below; neither agent executed their tools. The results delimit candidate claims and do not establish absence of other relevant work.

- **mcp-statecheck:** a public implementation is described for stateful MCP testing, controlled-failure replay and SDK comparisons. Arbitrary-target replay is outside its documented initial scope. Generic stateful MCP differential testing is therefore not an invention available to this project. Scope evidence: https://github.com/lxingy3/mcp-statecheck . Implementation bodies and replay evidence were not independently validated in this check.
- **RISU Problem-Semantics:** public prior work on translation fidelity exists. Its normative profile concerns HTTP responses represented as RFC 9457 Problem Details; the project describes a bounded multi-converter experiment. This is not evidence of comprehensive request-input omission/null/default coverage. Sources: https://github.com/risu-research/openapi-mcp-problem-semantics/blob/main/profile/PROFILE.md and https://risuinstitute.org/work/problem-semantics/ . This is an experimental project record, not verified peer-reviewed acceptance.
- **Projection Assurance:** broader consequence-preservation research is public. Its author-controlled profiles do not establish the proposed independent request-input study. Source: https://risuinstitute.org/work/projection-assurance/ . The existence of this record defeats a generic claim to invent consequence preservation; its reported results were not independently replicated here.
- **AutoMCP:** §3.5 of the v1 manuscript explicitly includes inspection of results or follow-up state queries for writes. Therefore reject the claim that prior OpenAPI-to-MCP evaluation uses only HTTP success. The reported evaluation does not establish systematic paired omission/null/default preservation across multiple converters or exhaustive business-state checking. This is a limit of the described procedure, not proof those checks never occur. Source: https://arxiv.org/html/2507.16044v1#S3.SS5 . No replication code was executed; the v1 manuscript's peer-review status was not established. Its count inconsistencies make exact-rate reuse inappropriate without artifact verification.

The remaining candidate is an independently generated, source-contract-based comparison of schema-valid input preservation across pinned converters, separating representability, request transport and persisted effects. This is an empirical extension proposal, not a verified novel algorithm. Schema validation and a full captured-request comparator must be included; a status-only baseline would exaggerate the contribution. New inputs must be frozen before implementation/outcome inspection, and any controlled synthetic source API must remain explicitly synthetic.
