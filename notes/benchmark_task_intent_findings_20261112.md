# Static task-intent screen results

The screening rule and implementation were committed as 1adb0bad before this screen ran. The pinned 812-task file yields 233 tasks with creation words and 81 with change words, with 20 in both sets and 518 in neither. These are lexical counts, not validated write operations. All task records remain in the exported inventory; no evaluator values were used. The sample has not been selected for scientific execution.

A first human-readable capability check inspected only Shopping Admin lexical candidates, chosen for the previously disclosed resource-feasibility screen. Its matched templates cover sale status, description updates, page headings, shipment tracking, addresses, product options, new simple products and marketing rules. This is a convenience-based feasibility lens, not a representative cross-site sample.

Templates 256 (simple-product creation) and 251 (description update) are plausible semantic components. Their published instances do not target the same named products. Creation tasks 694–698 name Energy-Bulk Women Shirt, Energy-Bulk Man Yoga Pant, FancyBoy Man Causal Jeans, Swatch Smart Watch, and Lelelumon Yoga Mat. Update tasks 464 and 543–546 target Antonia Racer Tank, Bella Tank, Selene Yoga Hoodie, Radiant Tee, and Lucia Cross-Fit Bra. The source intents, rather than evaluator definitions or outcomes, supplied these identities.

Thus this pair of templates does not immediately give independently authored create-then-edit instances. A continuation could be adapted by substituting a newly created product into the description task and establishing its review-dependent requirement, but the resulting composed task would be study-authored. Native editor availability, API support, preservation fields, attribute-set semantics, stable reset and business-valid input domains are still unqualified. No experiment is justified by the lexical match alone.

Decision: retain the complete structural frame and this limited exposure record. Do not claim WebArena provides 812 or 190 native-continuation experiments. Any adapted task must be declared as adapted, its mapping frozen before outcomes, and its evidence distinguished from untouched benchmark tasks. The independent literature check establishes adjacent-method differences only, not novelty. No application jobs, model calls or issue-oriented selection occurred in this screen.

A subsequent read of all matched single-site GitLab templates exposes another limitation of the lexical screen. Templates 303, 300 and 325 use 'open' for navigation. Template 292 uses 'Set up' for repository creation, so the change-word match does not identify its true operation. Templates 327, 328 and 337 describe issue creation, while other matches concern comments, code edits, profile settings, memberships, projects and groups. These observations are exposure records and examples of classification ambiguity, not an exhaustive semantic eligibility decision or evidence of a defect. Task-level GitLab fixtures and evaluator outcomes remain uninspected.
