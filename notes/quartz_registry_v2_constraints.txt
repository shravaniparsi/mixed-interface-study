Status and relationship to v1
This is a separately versioned, source-only catalog. No Quartz boundary input,
generated candidate, selection strategy, server or browser was executed for
this preparation. No known issues were searched. The generic generator and
method code remain unchanged. v1 remains the rejection/control stratum; its
comparison wording correction did not change its cases or the successful
positive control's actual full-state hash evidence.

v2 is not frozen. A Quartz registry executor, validation of the declared
bindings, protocol review and unresolved-policy handling are still required.
The existing fixed positive-control script does not execute either registry.
The four earlier ordinary controls are separate evidence, not executions of
the generated v2 controls or mutants.

Unresolved key-policy stratum
Native serialization at lines 1357-1368 trims each key, rejects a blank result
and rejects duplicate keys after trimming. The backend layer copies the map
without declaring those same key rules. Static behavior therefore predicts
that a surrounded key may change on native resubmission, while blank and
post-trim-colliding keys may block submission. These are source hypotheses.

The intended cross-interface key policy remains unresolved. These probes are
not pre-labeled defects, and an observed UI block or key change must not become
a binary conformance failure without independent policy adjudication. Retain
actual raw keys, producer persistence, UI messages, requests and final state.
Do not trim keys or collapse the two distinct collision keys inside the oracle.
The collision input uses distinct raw JSON members; it is not malformed JSON
with duplicate member names.

Native UI exclusions and generator limitations
The unchanged v1 generator emits API payload mutations only. Consequently all
40 UI-producer combinations are explicitly excluded, for distinct reasons:
- Ordinary true/empty/Unicode/typed-map literals have plausible native control
  representations. Their exclusion is an adapter limitation, not inherent UI
  impossibility.
- Native submission sends a complete typed command. No exact omission/null
  action is declared; empty controls are not equated with omitted or null JSON.
- Raw whitespace, blank and post-trim-colliding keys can be typed into a UI
  entry, but native serialization trims or rejects them. It does not submit the
  exact raw API map. DOM changes and request interception are not UI mappings.
- Required-class exclusions retain the pinned select's eligible-value limits.

Map cases use the existing enum operator to replace the complete jobDataMap
property with one explicit JSON object. No dynamic key, nested-key mutation,
random generation, static API enum or new generic operator is introduced.
Path keys, multiple simultaneous mutations, actual duplicate JSON members,
large/exceptional numbers, broad Unicode exploration, execution, triggers,
recovery and persistence modes remain outside this finite catalog.

Bindings, typed reads and comparison scope
The generator stores oracle metadata but does not implement or validate its
runtime bindings. A future adapter must bind returned jobKeyDTO group/name to
the update URL; map response jobClassName to request jobClass; and retain
returned durable, requestsRecovery and jobDataMap. It must not restore baseline
values over accepted mutated producer state. A native consumer must inspect
loaded typed entries before editing description. An unexpected class cannot
be repaired by choosing the baseline class.

For ordinary accepted/normalization cases, compare declared producer values,
the documented UI display projection and preserved non-edited fields after
continuation. Preserve JSON scalar types, strings, raw keys and array order;
object-member ordering is immaterial. Normalization is stage-specific: null
description projects to an empty UI input, and omitted/null map becomes stored
{}. Other values and key-policy observations are not silently normalized.

Only the listed business fields and environment checks are compared. Scheduler
name, instanceId, quartzVersion, clustered, threadPoolClass, threadPoolSize and
runningSince remain outside this prospective declared comparison. This is
distinct from the earlier successful control's actual complete-state hashes.

Rejected creation stops continuation but still requires a stored-state read;
HTTP rejection alone is not proof of rollback. Generated or skipped consumers
earn no dependency coverage. Same-route variants retain the existing method's
same dependency/route targets; no payload-variant objective or fault label is
added to the selector. The cost 1.0 remains an unmeasured schema placeholder.

Execution prerequisites
Fresh RAM-store reset per complete case; identical admin/ROLE_ADMIN actor;
matching pinned native artifacts and declared classpath; the documented JVM
timezone; fixed durable job; STOPPED scheduler; zero triggers and executions.
No test may start/resume the scheduler or execute a job. Adapter validation and
protocol review remain outstanding before any freeze or candidate execution.
