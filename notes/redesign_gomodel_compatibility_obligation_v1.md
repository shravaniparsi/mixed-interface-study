# GoModel compatibility obligation before altered outcomes

Original admin documentation (wave 2, file 1, plugin/guardrail endpoints) describes GET /admin/guardrails as returning instances and PUT /admin/guardrails as creating or updating one instance. The original native GuardrailsStore loads that GET collection and sends edits to the same PUT route. GuardrailEditor offers the original edit controls for those records and disables identity/type rather than making API-origin records a separate read-only lifecycle. The original handler returns the persisted instance view by name after Upsert. The ordinary API-created record was visible and editable under the same actor in the verified calibration.

Together these sources support a workflow-level expectation that ordinary API-created guardrail instances participate in the native editor. This is an inference from the original integrated contract, not an explicit promise that every omitted/null configuration will round-trip identically. The sources reviewed do not establish that omitted and null fields must preserve their representation through an unrelated save. Consequently observed normalization is descriptive and does not by itself establish a defect. An actual inability to perform an unrelated edit would still require checking intentional validation, lifecycle and documented restrictions before defect attribution. No malformed outcome has been observed for this schedule.

The fixed header_edit configuration is not attached to an inference workflow; the active-workflow phase-conflict restriction is not deliberately triggered. Original type, actor, record identity and ordinary strings remain fixed. This bounds the compatibility question to local instance editing, not effects of invoking plugins or sending model requests.

Pinned source identities are in manifests/redesign-development-source-wave2-v1.json (first scheduled admin-documentation entry), wave5 (handler, GuardrailEditor, GuardrailsStore) and wave6 (header_edit). Runtime support is results/redesign-gomodel-ordinary-v2 with its artifact and freeze. Treat the source inference and runtime feasibility as separate evidence.
