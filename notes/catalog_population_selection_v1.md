# Fixed catalog cohort v1

The pinned catalog population contains 1,362 verified software blobs (836,885 bytes). Frozen metadata checks yielded 585 eligible entries and 585 unique eligible repositories. The first-failure dispositions are 226 non-root/non-GitHub URLs, 425 missing Docker labels, 56 third-party-dependency exclusions, 35 license-screen exclusions, 21 prior-overlap exclusions and 14 fork-metadata exclusions. All failures are also retained per entry; these ordered counts are not the prevalence of every failing condition.

The deterministic hash order selected twelve distinct GitHub-owner groups. They are prospective qualification candidates, not twelve proven independent applications or twelve scientific observations. No application source, API/UI outcome or runtime was retrieved during selection. The catalog supplies descriptions and identities, so future work is metadata-exposed. Prior exposure checking is conservative but incomplete, as documented in the reference index; shared ancestry and unresolved aliases remain to be assessed before scientific admission.

There will be no replacements for later eligibility, provenance, source-mapping, deployment or ordinary-control failures. The complete ranked list and exclusions are retained. Next: freeze source/provenance acquisition, workflow selection, native/API request mapping and runtime caps before inspecting these applications. Hardware, cloud authentication, missing mutation APIs and unavailable native editors must become recorded qualification outcomes, not reasons to search for a more favorable replacement.

Acquisition used one 5,414,914-byte catalog archive, SHA256 a90f041d6a3c6cfbce0c2338ce2c66ae08156ebefb1101688c93378ef7ef9f39. The initial collector failed because its software-entry size bound was accidentally applied to the catalog AUTHORS file. A separately published offline correction used the identical archive and left the failed attempt intact; it changed no sample filters or ordering. All 1,362 blob identities, ledger coverage/counts and selection ordering were then reconstructed locally without importing the selector. Three focused selector tests passed. This verifies metadata bookkeeping, not scientific validity.
