# Targeted novelty check during the fixed development run

Checked 17 November 2026. This is a targeted check, not a systematic review or proof that a research gap exists. No reserved implementation was inspected.

- Offutt, Papadimitriou and Praphamontripong, *A Case Study on Bypass Testing of Web Applications*: the author-hosted full paper describes sending inputs around client validation and evaluates AutoBypass on 16 deployed applications. Its reported observations include invalid input affecting output/navigation. Thus bypassing frontend checks, and even observing some downstream output effects, cannot be claimed as new. Source: https://www.albany.edu/faculty/offutt/research/papers/autobypass.pdf (abstract/introduction and discussion around printed pages 19–23).
- Yandrapally et al., *Carving UI Tests to Generate API Tests and API Specification* (2023): the author-submitted abstract describes generating API tests and specifications from UI navigation, with evaluation on seven applications. Consequently using native UI traffic as API seeds or inferring an API from it is not a sufficient new contribution. Source: https://arxiv.org/abs/2305.14692 . Only abstract-level claims used here.
- Li et al., *A REST API Fuzz Testing Framework Based on GUI Interaction and Specification Completion*, CMC 86(3), article 95, issue date 12 January 2026, DOI 10.32604/cmc.2025.071511: publisher records describe APIDocX, GUI-triggered traffic extraction, parameter generalization and documentation completion for fuzzing. This further weakens a generic GUI-assisted API testing novelty claim. Source: https://www.techscience.com/cmc/v86n3/65438 . Publisher abstract/metadata checked; full-method comparison remains open. The ScienceDirect mirror returned 403 on direct opening.

Decision: the current development run can qualify observations of persistence, native editing and single-field repair. It cannot prove novelty or method superiority. A defensible further comparison needs the same persisted producer state followed separately by equivalent API-semantic and native UI actions, together with competent schema and native-validation baselines. The native continuation must contribute observations beyond request rejection, static rule disagreement or known UI-derived API testing. Independent applicability and outcome coverage remain missing. Do not label the work a novel agent-specific problem without an actual agent intervention and a demonstrated additional effect.
