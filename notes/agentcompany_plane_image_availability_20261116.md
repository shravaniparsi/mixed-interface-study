# Plane image availability and qualification decision

The previous goal turn made progress by archiving the independent instruction catalog and initial capability evidence. This turn resolved the eight unique image references in the pinned Plane Compose file using public registry metadata. No layers or database backups were downloaded, no containers ran, and no research model calls were made.

Seven references resolved to immutable linux/amd64 manifests. Their distinct compressed layers sum to 736,451,092 bytes. This excludes the unresolved MinIO image and is neither measured installed disk usage nor a memory estimate. Backend image reuse across four Compose services is not counted four times in that total. The archived manifests, platform selection and byte hashes are checked by scripts/extension/resolve_plane_images_v1.py. Original registry responses remain in results/agentcompany-plane-images-v1.

The configured minio/minio:RELEASE.2024-11-07T00-52-20Z reference failed with HTTP 401 after the Docker Hub anonymous bearer exchange. A separate Docker Hub repository metadata request returned 404. The exact same release tag in the upstream Quay namespace returned 401 both before and after the standard anonymous bearer exchange. These responses establish unavailability through the tested anonymous access paths at collection time; they do not establish global deletion, paid/private availability, or permanent failure. The original error is preserved; there was no repeated full-stack run.

An upstream release metadata check confirmed the tag exists in the MinIO source repository. No image equivalence follows from a matching release name. Search results about distribution changes were used for navigation only, not as proof of the cause or chronology. No substitute product, image release or third-party mirror has been chosen.

Decision: the original Plane stack is not yet qualified for a runtime experiment. A dispatch now would fail the image-availability precondition. Do not run the eleven-service stack, silently omit object storage, or reinterpret a different image as the original benchmark environment. This is an infrastructure exclusion from immediate execution, not a scientific task failure, detected validation defect, or evidence for the proposed testing method.

The overall research goal remains active. Two independent design questions remain: whether a clearly labeled, source-built adaptation can preserve the exact task semantics within the free execution bound, and whether the full externally defined task frame contains enough qualified dependency diversity to test an actual contribution. Resolve the full-frame eligibility question before investing in rebuilding a service for a single task. The Plane-only descriptive screen is not sufficient for sampling or a superiority claim. No later outcome may be used to decide the eligible task frame.

The next action is a complete instruction-only eligibility screen of the already archived 175-task catalog under explicit semantic rules. Preserve missing/ambiguous tasks and app overlap. Only if that yields a scientifically useful frame should a prospective adaptation/ordinary-control protocol be registered. Existing cohorts stay closed. Image unavailability does not authorize selecting a different benchmark because it is more likely to yield defects.
