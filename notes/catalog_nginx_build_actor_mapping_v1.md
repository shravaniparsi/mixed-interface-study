The production Dockerfile expects frontend/dist, copies the original backend and root filesystem, installs backend dependencies and embeds BUILD_COMMIT. Original s6 overlay installation targets version 3.2.3.2 and downloads its noarch/architecture archives; exact archive identities remain needed for a reproducible build record.

Backend startup runs migrations, setup and schema compilation, then conditionally fetches IP ranges. IP_RANGES_FETCH_ENABLED=false disables both that fetch and its timer through original source. The certificate timer is started independently and remains to be reviewed for a certificate-free fixture. Startup errors are retried internally once per second; readiness must examine the original endpoint and retain failure rather than equate supervisor liveness with success.

AuthContext calls getToken(identity,secret), which POSTs the complete two-property JSON body to /tokens through the original base transport. Successful non-2FA responses are stored by AuthStore; the provider refreshes tokens on a five-minute interval. The token model is not a database table: it signs RS256 with the persisted private key and verifies with the public key and expiration checking. This does not prove that no other authentication operation writes the database. A future ordinary branch must preserve the same token/actor and observe refresh events rather than silently suppress them or call a new login.
