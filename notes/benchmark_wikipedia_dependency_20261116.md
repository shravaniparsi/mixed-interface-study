# README task: original Wikipedia dependency

Selected task 558 explicitly requires the provided wiki, not current web content. The pinned benchmark Dockerfile uses kiwix-serve 3.3.0 and defaults to `/data/wikipedia_en_all_maxi_2022-05.zim`. The developer settings identify the original download URL on metis.lti.cs.cmu.edu. This is a May 2022 encyclopedia snapshot. A contemporary film list cannot be silently substituted, and the task's film list has not yet been read or frozen from this source.

Five source files were retrieved from benchmark commit 6473f72db5dcefc97b5725b59e734504edc28a21 and checked against the archived Git tree's blob IDs. `evidence/benchmark-wikipedia-source-v1.json` lists the file hashes; raw files are retained under `results/benchmark-wikipedia-source-v1`. Only relevant noncredential lines of developer settings were retained separately with their complete-source hash and Git blob identity.

The environment documentation estimates roughly 100 GB of external data. The setup script downloads the ZIM and then copies it into a Docker volume, potentially retaining two copies. The previously measured disposable runner had 92,139,700,224 bytes free before downloading the 22,006,162,655-byte compressed GitLab image. These are different measurements and an approximate source estimate, not a verified exact ZIM size or proof that all alternative retrieval methods are infeasible. They do rule out assuming that the documented combined local setup fits our observed runner without further work. The documentation calls the environment MediaWiki-based, but the Dockerfile and tests identify Kiwix; the implementation is the evidence for the runtime type.

Two metadata-only HEAD requests to the original archive URL, HTTP and HTTPS, returned URLError from this environment. No content was downloaded. This establishes neither global unavailability nor absence of HTTP range support; no response headers were obtained. Preserve this attempt instead of treating it as a successful archive-size check.

Status: README family remains selected and unqualified. No scientific README cases were executed or dropped, no title list was guessed, and no smaller replacement task was introduced. Next acceptable route is recovery of the exact snapshot article through a verifiable archive or bounded range retrieval; alternatively, a separately registered content-source adaptation would have to be explicit and could not be reported as unmodified benchmark execution. This note authorizes neither a 100 GB download nor another experimental run. Membership and MR qualification continue independently.
