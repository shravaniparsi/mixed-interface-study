# Null/omission calibration: completed, no incremental exception detection

Design and runner were published at 2557158 before dependency installation. Source inspection identified a missing standard global.Promise binding in the VM harness; correction 825ae87 was published before the first measurement. One installation and one measurement completed. Node 16.13.2 and Mongoose 4.7.1 are a reconstructed environment, not verified historical deployment dependencies. The lockfile records exact resolved transitive packages. Installation used about 5.6 MB of files and 1.27 seconds, with no lifecycle scripts, paid compute, Actions jobs, browser or database.

Twelve in-memory schema observations feed two extracted constructor versions, giving twenty-four component combinations. These are correlated checks of one externally reported fault, not twenty-four defects or independent workflows. Six inputs comprise reported omission/null conditions and four analyst representation controls. Both schemas validate all six in memory. Before the backend change, omission remains absent and null remains null; after it, omission becomes an empty array but null remains null. The original constructor throws for the two pre-change nullish states and the post-change null state. The revised constructor throws for none of the twelve serialized states.

The shared nonnull predicate flags exactly those three serialized states that crash the original constructor. Thus no observed constructor exception escapes the information-matched API-state predicate. The array predicate flags seven serialized states, including string representations that do not throw. These disagreements do not establish false positives: the array expectation is externally specified for the omitted-field API test, but extending it to every input is an analyst choice. Likewise, absence of a constructor exception says nothing about whether all rendered values are correct. For example, the old constructor's splice may change supplied content; that is outside this exception-focused comparison and is not added as another finding.

The revised constructor tolerates three states still flagged by the nonnull predicate. It changes consumer robustness, not necessarily producer contract validity. No full React rendering, HTTP acceptance, database persistence, native form submission, or post-creation workflow was executed. The old and new backend/front-end combinations are controlled component pairings, not proven historical deployments. The result confirms this narrow mechanism in the chosen environment, not an end-to-end application defect.

## Decision

Close this calibration with zero incremental exception detections and zero application admissions. Do not launch full application reconstruction solely to repeat a predicate already caught by the competent API baseline. Keep the case as a retrospective mechanism/calibration example, not a central novelty claim or independent discovery. The scientific contribution still needs independent cases or a demonstrably useful method beyond known contract validation. The original fifteen-task and fifty-report frames remain unchanged.

All measurement rows, outputs, dependency lock, installation record and execution provenance are retained in results/reported-null-component-calibration-v1. The verifier recomputes coverage and comparisons without executing the application; it checks source-response hashes against admission metadata but does not independently reproduce those private source bytes or validate historical deployment equivalence.
