# PetClinic terminal extraction preparation

The new extractor replays the twelve archived integrity-control branches as six comparable terminal pairs: three clean accepted pairs and three matched-rejection pairs. It verifies the historical artifact hash inventory, original source-qualified component evidence and recorded direct-child cleanup before constructing terminal envelopes. The archive identifiers preserve the fact that these are prior observations, not newly dispatched jobs.

The evidence layer now distinguishes completed native blocking and changed rejected-state graphs from execution failure. A blocked form needs the registered edit intent, no PUT, complete native capture and unchanged target/relationship readback. Its signal belongs to the assigned native continuation. A readable graph change after a rejected producer command remains a shared-state mismatch and cannot create native-exclusive detection credit. Unknown assertions, unreadable graphs, inconsistent verdicts, missing capture and unconfirmed cleanup remain incomplete or unsafe to continue.

Seventeen tests cover the twelve archived controls, blocked-native fixtures for owner, pet and visit workflows, changed rejected-state graphs, source/capture/intent tampering, backend reuse and raw-record preservation. Negative counterexamples are synthetic fixtures, not live findings. Unexpected prefix statuses remain outside this extraction version's qualified selection.

The deterministic preparation command produces a source-fingerprinted manifest and derived replay. CI regenerates both and compares their contents. Historical runner, validator and reducer sources remain unchanged. No applications ran, no new samples were added, and no per-job dispatcher or broader lifecycle path was qualified in this step.

Next is PetClinic immutable per-job dispatch and a fresh control run using these terminal envelopes. P2 remains open, alongside the remaining RealWorld bindings, primary batching, timing scope and final freeze.
