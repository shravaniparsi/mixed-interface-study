# Quartz form measurement correction

Read-only examination of the initial collection found that all eight nonempty-map Quartz cases had empty `typed_entries` measurements. The ordinary string case, initial-067, has a retained screenshot showing the key and value inputs populated and a preview containing `sample: ordinary value`; its recorded form map was nevertheless empty. The adapter used DOM name-attribute selectors for interpolated Angular form names. The empty-map qualification controls could not detect this extractor error.

The eight affected comparisons are marked `measurement_invalid` in the descriptive analysis. Their original terminal classifications and repeat signatures remain literal archived observations. They cannot support eight application defects or native-UI failure claims. The exact affected forms, previews, bound maps and raw-file hashes are recorded in `manifests/quartz-form-measurement-audit-v1.json`. The independent byte-level replay of the original run remains valid; that replay does not establish the measurement's semantic validity.

Version 3 reads the actual rendered map rows and checks their field structure. It preserves keys and typed values without normalization and rejects an empty extraction that conflicts with a nonempty preview. Separately versioned runtime and classifier sources keep the original frozen sources intact. The registered correction covers all 22 Quartz pairs after live empty/nonempty qualification, as specified in `protocol/quartz-form-correction-v1.md`. All corrected cases are exposed, and none replaces an original observation.
