# SeatSurfing initial candidate review

This review uses the fifteen already retained wave 1-3 files (276,603 decoded bytes). No new source or runtime has been executed. Attribute editing exposes label plus type/boolean controls; group editing saves one name plus separate membership actions. Neither currently establishes two independently editable scalar text properties. Booking exposes subject but user is a typeahead or disabled field and additional booking attributes are disabled; inspect the original selector before assigning a final disposition. The earlier confirmation route remains uninspected.

The location form has editable name, description and announcement controls, with required non-whitespace name and 512-character description/announcement limits. The original submit copies these and other existing values into Location, saves it, then invokes attribute and space handling before the selected map branch. Designed-map and uploaded-file branches invoke loadData; the no-map-change branch only updates local saved/changed flags. Do not insert an automatic readback into that native branch. The acquired attribute helper constructs an inner Promise without returning/awaiting it; retain this original asynchronous behavior in the comparator rather than silently repairing it. No runtime consequence is established. Space bulk updates are conditional on changed/created/deleted spaces. No simplified single-request baseline is frozen.

The location backend uses UnmarshalValidateBody, which decodes JSON then invokes the original validator. Both create/update declare required name and length-constrained fields, check area-admin permission and validate timezone, days, blocked dates and groups. An incidental source comment describes clearing stale map data before a map-type change; retain this exposure, not as a demonstrated defect. The API creates a stable location ID and has a readback endpoint. Persistent defaults, authentication, original request serialization and executable provenance remain unresolved.

The Dockerfile builds the frontend and Go server, with mutable Node/Go/toolchain bases and a digest-pinned distroless final base. The compose file uses PostgreSQL. These are declarations, not qualified images or executed dependencies. The frozen tree lists a frontend lockfile larger than the 256-KiB source-wave limit; it has not been fetched, split or bypassed. The next source wave is restricted to eligibility and essential contract/bootstrap declarations. CloudBeaver remains pending and no fixed-cohort repository is replaced.
