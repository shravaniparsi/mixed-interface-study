# Source-review decision checklist

Apply to the remaining fixed candidates in order under protocol/editability-repairability-evaluation-v1.md. No new selection rules or budget extensions. Record evidence locators and unresolved items in the maintained execution status, not a new narrative per wave. Root documentation/license/Dockerfile/default compose first; absence is recorded from the pinned tree.

| Gate | Required evidence before proceeding |
|---|---|
| Exposure/provenance | Frozen repository/ref; prior index gaps retained; known application aliases/lineage reviewed |
| Application fit | Original native creator AND editor, advertised persistent named-entity API creation; documentation alone cannot invent a UI |
| Ordered selection | Earlier mapped create operations resolved; no leap to an easier later operation |
| Actor/compatibility | Same actor/lifecycle, stable-ID retrieval and source-supported continuation obligation |
| Text inputs | At least two independently editable scalar text controls in original initialized structure; fixed ordering and scope exclusions |
| Full native sequence | All writes caused by native creation, edit, sham and repair; dependent records and normalization included |
| State/restore | Relevant DB/files/schema/sequences/history/queues/cache/session/browser state; operation-specific derived effects; unsupported state explicit |
| Deployment | Original public-source/dependency/runtime path, no private/external account; original supported fixture configuration |
| Baselines/scoring | Schema dialect/validator, original native preflight with positive interception evidence, exact success/failure/unavailable criteria |
| Resource decision | Source limits and clocks; implementation feasibility within existing two-hour window; registered job/correction/branch limits |

Resolve decisive ineligibility before investigating irrelevant infrastructure. Absence of root build files alone is not ineligibility. If documentation and original tree show a library without native CRUD UI, document the evidence and close source qualification without building it. If fit is plausible, schedule only exact dependencies needed to resolve the table. Unknown essentials remain unknown; bounded source failure is attrition rather than a negative scientific result.

A selected workflow must have a complete written execution design before the adapter clock begins. This does not authorize implementation off-clock, withholding an eligible selection to obtain easier results, or replacing a selected workflow after failure. Stop at the unchanged registered limits. Reuse scripts/evaluation/source_wave.py for exact-blob collection and verification rather than generating a new collector per wave.
