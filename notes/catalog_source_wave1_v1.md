# Fixed-cohort first source review

All twelve selected repositories returned canonical identity matches, default-branch revisions and complete recursive trees. GitHub metadata marks none as forked, archived or disabled. This is hosting metadata, not proof of independent genealogy or absent historical exposure. All 58 prospectively scheduled root/setup blobs were retrieved and Git/SHA256 verified; source slots and bytes are recorded per project. No image, dependency, application, browser or scientific case was executed. No replacement was made.

Initial targeted review findings (README ranges and referenced first-wave file numbers):

- meme-search: README 167–220 describes Rails, Python, Postgres/pgvector, job workers and local description/model generation. Earlier README overview describes a read-only integration API and upload-based core flow. Whether any separate editable JSON record qualifies is unresolved; do not equate that integration API with every internal route.
- OpenELIS: README 62–135 describes a local database-only mode without FHIR/analyzer services, and source build/bootstrap. Local synthetic administrative workflows may be feasible; no patient data or external clinical systems will be used. Exact contracts, image provenance and restoration remain unknown.
- Viseron: full README describes a local NVR and configuration-file editing through its web UI. A persistent scalar-record JSON workflow independent of cameras is unestablished.
- changedetection.io: README 151–220 documents standalone Docker/Python deployment and persisted datastore; notification and fetch side effects must be confined to local fixtures or disabled through original supported settings. Optional AI features do not authorize paid model calls. No workflow is selected from these descriptions.
- Jitsi: full README describes browser conferencing and self-hosted deployment. Persistent JSON create/edit record eligibility is unresolved; transient meetings/chat are not automatically eligible.
- Nginx Proxy Manager: full README documents local admin UI, proxy/redirection/user management and persistent data mounts. Original supported local configuration without external certificate issuance must be established before execution.
- CloudBeaver: README opening describes a Java server and React UI with community Docker deployment. Detailed workflow and JSON mutation/readback contracts remain unresolved.
- ChartDB: README 74–112 and Dockerfile describe a frontend build served by Nginx; AI capabilities are optional. This suggests a need to inspect persistence/API boundaries, not proof that all server mutation APIs are absent.
- Seatsurfing: README 25–37 and Dockerfile describe a Go REST backend, booking/admin UIs and a combined frontend/server build. The documented PostgreSQL deployment and local bootstrap still require precise source mapping.
- socks5-proxy-server: full README and Compose describe proxy/Redis plus CLI and Telegram administration. The complete 38-entry tree has proxy and bot scripts, with no apparent browser application. A small entrypoint check is needed before recording a final no-native-UI disposition; no Telegram connection will be made.
- sE2EEnd: README 77–101 describes encrypted file/text transfers, local Keycloak administration and local or S3 storage. File-upload flows are outside scope; any eligible editable metadata/settings record remains unresolved.
- Mathesar: README 51–88 describes local Postgres, record editing and form capabilities. Editable JSON properties, source materialization and original database constraints must be mapped before any baseline or scientific input is admitted.

These are partial targeted source reviews, not complete implementation or license audits.
