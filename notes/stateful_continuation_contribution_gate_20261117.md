# Stateful continuation contribution gate

A targeted two-query search followed the completed goal-evidence audit. Queries were: web application GUI API cross interface state consistency testing persisted invalid state metamorphic testing; API GUI differential testing frontend backend validation persistent state continuation testing. This was not a systematic review. Search snippets were not treated as confirmed findings. Three primary-source pairings were independently checked by a fresh-context skeptic under claim-source-verification:3confirmed at narrow scope,0rejected/partial/blocked. This is AI-assisted verification, not human peer review.

## Verified overlap

Cypress official documentation, Common scenarios / Combine API calls with UI tests, documents HTTP setup, UI action and HTTP persistence verification. Its example seeds a cart, checks out through the UI and inspects the resulting order through HTTP. Supporting excerpt: “Seed state over HTTP, drive the application through its interface, then confirm over HTTP that the change persisted.” This supports present tool capability, not historical priority, comparative effectiveness or equivalence between alternative continuation routes. Source: https://docs.cypress.io/app/guides/api-testing#combine-api-calls-with-ui-tests .

ARMeta v1, May27 2026, describes a multi-agent LLM metamorphic REST testing workflow in its abstract and sectionIII. SectionV reports emergent inconsistencies when different executable tests realize the same high-level scenario through different APIs; systematic analysis is future work in that version. Supporting excerpt: “We plan to systematically incorporate this cross-API consistency analysis into the framework.” Its described evaluation concerns REST requests, not established native UI/API continuation equivalence. Treat it as a versioned preprint, not verified peer-reviewed publication or a field-wide absence result. Source: https://arxiv.org/html/2605.28321v1 .

Atlidakis, Godefroid and Polishchuk, Checking Security Properties of Cloud Service REST APIs, sectionsIII-A–III-C andV, describes active property checks beyond server-error detection. The resource-leak rule includes: “A resource that was not successfully created must not be accessible”. A reported example involves failed creation leaving residual state that conflicts with later creation. Generic follow-up state checking is therefore prior work. This does not establish the stronger native/API continuation relation. Source: https://patricegodefroid.github.io/public_psfiles/icst2020.pdf .

## Contribution decision

Reject three candidate selling points: combining HTTP and UI execution; appending state checks to a request; adding LLM agents to generate API properties. The sources establish prior capabilities, while our evidence supplies no new comparative benefit for those claims. A new cohort alone would not repair that contribution gap.

The remaining empirical candidate is the incremental information supplied by native continuation after matching persisted producer state and equivalent edit semantics. It is a candidate question, not validated novelty. Any further study must distinguish (a) accepted input that leaves an unusable native state, (b) legitimate UI/API contract differences, (c) native normalization or different payload construction, and (d) harness/origin/actionability failures. The last category accounts for unresolved ordinary-control outcomes in the current extension and cannot be counted as an application defect.

A concrete advance would require a prospectively defined measurement with four separable results: qualified paired-state coverage; outcome overlap against schema, source-aware validation and applicable API semantic checks; independently supported mechanism/obligation evidence for discrepant cases; and total acquisition/qualification/execution cost including unavailable workflows. UI-only observations are not method superiority unless the comparator receives equivalent relevant information. Source-derived checks and fully supplied manual contracts remain distinct baselines.

Falsification gate: if qualified paired cases add no information over competent comparators, report that result and reject an incremental-detection claim. If ordinary controls or serializer equivalence fail, the comparison is unavailable, not a favorable native signal. If all apparent discrepancies are legitimate interface differences or environmental failures, reject a natural-defect claim. No minimum positive-finding count is imposed.

This review does not register a replacement cohort, authorize paid model calls, reopen a closed run or settle the broader novelty question. Before additional runtime work, the specific acquisition method or empirical knowledge claim must be materially different from these existing capabilities, and a new sampling/qualification design must explain why it can answer that claim. The present Q1 objective remains incomplete.
