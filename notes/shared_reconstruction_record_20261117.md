# Common evidence record for frontend comparators

The previous turn provided original-source evidence that identical projected API values do not uniquely determine confirmation-dependent submission. This turn adds shared_reconstruction.py, a pure evidence-packaging layer. It does not acquire or reconstruct hidden state, extract requirements, infer API obligations, evaluate either method or authenticate provenance assertions.

An observation explicitly names its target (field validation, form validation, submission decision or API conformance), point, revision, operation, actor, lifecycle and object document. Every supplied fact binds to the canonical hash of that entire observation and carries an origin/evidence assertion. Missing facts, explicitly unknown facts, stale bindings and absent provenance remain unresolved. Known null/empty/false and explicitly observed absence remain distinct. No value is copied from a nearby field or defaulted. The package has a stable shared-input hash and does not alias caller data. Extra facts do not fill unrelated requirements.

Completeness means only that the declared requirements have bound evidence. Requirement completeness and provenance truth are explicitly unverified. A known-absent fact is evidence of absence, not a satisfied guard or accepted input. Consumers must preserve target-specific unknown/error/applicability handling. Both methods must actually consume the same packaged record in the later integration; creating this module alone does not establish that fairness. Acquisition effort and any framework replay remain charged outside this representation and must be included in the eventual comparison.

Ten regression tests passed, covering omission without copying password, distinct null/empty/false/absent states, explicit unknown, scope/document/target binding, provenance, duplicates, unrelated facts, stable hashes, alias isolation and non-JSON/nonfinite rejection. The public-input builder packages the already closed three confirmation rows. All request-only packages leave confirmation unresolved; packages with each recorded confirmation retain that specific value. Its declared scope is confirmation only, not complete workflow reconstruction. No runtime experiment was repeated and no independent evaluation case was added.

The new tests and deterministic packaging verifier are included in automatic unit CI. The next integration must enumerate the full requirements of each target before joining these packages to original-source replay or conditional transfer. Do not interpret conditional transfer's unsupported predicates as successful abstentions, omit ambiguity from denominators, or turn these authored records into independent labels. The main study still lacks an established advantage, complete automatic acquisition, logical-baseline qualification and independently intended-obligation evidence.
