# Conditional transfer evaluator: development implementation

Implemented the evaluation stage specified in protocol/constraint-transfer-candidate-v1.md. Inputs remain explicit rule and mapping records supplied by the caller. This does not implement automatic source extraction, infer intended behavior, qualify a baseline, or create an independent dataset.

Supported predicates are explicit presence/non-null, scalar enumeration, inclusive numeric range, and string length with named Unicode-codepoint or UTF-16-code-unit semantics. Rules retain revision, operation, actor, lifecycle, equality guards, and observation point. Explicit policies distinguish omission, null and empty strings. Unknown mappings, transformations, conflicts, incomplete observations and guard context return unknown with reasons. Out-of-scope observations retain applicable=false rather than claiming a successful check. Malformed rule instructions produce code_error.

The only represented transformations are identity and explicit JSON-string decoding. Unknown serialization is not guessed. The evaluator never supplies a presumed backend default to a missing observed value, which would conceal a persistence defect. Nested-container mismatch is distinguished from a missing object property. Evidence strings are provenance requirements, not proof that a binding, guard or contract is correct.

Fifteen development tests cover ordinary valid/invalid values, create/update scope, optional emptiness, null versus omission, refusal to invent defaults, guard truth/missingness, actor/revision/lifecycle scope, mapping/conflict/readback uncertainty, JSON decoding, different string-length units, Boolean-versus-number typing, malformed metadata/bounds, nested container mismatch and observation-point mismatch. Seven existing scorer tests also pass. They are synthetic engineering fixtures only, with no paper sample count or scientific performance result.

The implementation is pure in-memory Python and makes no model calls, application requests or writes. No dependency installation or paid compute occurred. Automatic acquisition/mapping, a source-aware practical comparator, independent sampling/labels, causal application evidence and cost-benefit evaluation remain unfinished. The next implementation priority is qualifying an actual source-to-rule path; manually supplied records cannot establish acquisition effort savings. Do not add more supported predicates merely to increase synthetic test counts.
