# Independent-input design gate after ordinary qualification

The latest control run is terminal and passed its ordinary three-path checks. The previous turn was progress because it established a usable workflow and preserved the failed development history. This review asks what scientific claim the retained external task frame can actually test.

## Complete retained frame

All 15 explicit no-requested-reply tasks remain represented in manifests/agentcompany-downstream-predicates-v1.json, with their original ten operation families, instruction hashes, literal producer/consumer anchors, substantive contracts, required API checks and adaptation limits. None is removed because a defect seems unlikely. This is single AI-assisted interpretation, not independent human adjudication or an official benchmark grading rubric. The verifier checks coverage and provenance; it does not certify the semantic judgments.

The descriptive downstream relations are three artifact-sharing tasks, three membership/message tasks, two membership/role tasks, two reference-assignment tasks, two code/merge-request tasks, one artifact derivation, one link publication and one membership/bio reflection. These eight descriptive relation categories do not replace the original ten operation families. One task has ordinary qualification; fourteen do not. All 175 instructions were exposed before this design. External authorship does not imply untouched holdout status, statistical independence or random selection.

## What an independent input would be

The externally authored task is the input unit. Both channels in the medium channel task, three issues in the Plane task, four tables in the PDF task and two milestone assignments remain correlated suboperations. The two Sotopia tasks share repository and operation family. A file name variant, omitted field, renamed recipient or repeated fixture is not another independently authored task. Report task, family and application counts separately, with cross-service dependencies retained.

For generated content, execution must preserve the external source: actual PDF tables, actual issue text, actual spreadsheet membership, actual salary records or requested code behavior. Supplying an arbitrary file makes upload/share easier but changes the requested task. Any deterministic transformation needs a separate content-correctness oracle; an HTTP success or successful download cannot establish semantic correctness. That oracle must not read hidden benchmark graders or expected outcomes.

## Comparator requirements

For each task, the API comparator must know the same identities, source content, business predicates and final state expectations as the browser path. It must check final relationships and not merely status codes. Examples include exact issue assignees and milestone IDs, member-role consistency, message recipient/text, public access and matching artifact content. Denied writes also require unchanged-state checks. The manifest specifies the expected checks without claiming each is implemented.

Passive browser readiness information in the ordinary control is engineering evidence. If scientific scoring uses it, give the API comparator equivalent information and an explicit observation budget. Preserve backend version and operation semantics: native ownCloud sharing used an OCS v2 route while the direct control used an OCS v1 route. Identical observed ordinary outcomes do not prove semantic equivalence on unseen inputs.

## Why a grid is not ready

Most retained consumers share or reference a produced object rather than explicitly revalidating all of its original form fields. Their successful continuation would answer an execution question, not establish absence of client-only validation constraints. Their failure could arise from content generation, fixture identity, permissions, asynchronous readiness or harness behavior. A defensible study must distinguish these mechanisms before claiming incremental validation-gap detection.

The ordinary-qualified job-description task has one fixed source-derived payload and no identified independent variation set. Multiplying filenames, MIME types or omissions would create analyst-generated stress cases. Such cases can later be a separately labeled sensitivity experiment, but cannot satisfy the independent-input objective by renaming them benchmark instances. Likewise, a missing native comparator cannot be replaced by an API-only pass.

Decision: do not dispatch a scientific perturbation grid from the single qualified task. Retain the full frame and pursue other families' feasibility and exact oracle definitions. RocketChat repository secret-name inspection returned no DOCKERHUB_USERNAME or DOCKERHUB_TOKEN on this turn; no authenticated pull or unauthenticated retry was attempted. GitLab milestone assignment remains a source-supported candidate whose pinned-image runtime, task initialization and native path need qualification. Its two issue assignments must remain one task. This is a feasibility priority, not selection based on an expected defect.

Even successful execution of all 15 tasks would not by itself establish selector superiority, an agent intervention effect or Q1 readiness. The next scientific registration must specify the incremental-detection estimand, treatment of producer mismatches and missing comparisons, matched observation budget, bounded causal follow-up and stopping rules. It must also state a supported methodological contribution. No scientific execution is registered by this document, and no closed cohort is reopened.
