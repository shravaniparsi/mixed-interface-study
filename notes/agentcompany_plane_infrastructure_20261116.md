The pinned benchmark source (98b68ef82a47690c316f42fddb05baafaab56851) downloads Plane installation, Compose, environment and restore files from the moving TheAgentCompany/plane stable branch. The branch resolved to eec8110ddc059b8c2c40b24d2ae011000f7b7e16 during this review. That resolution describes the inspected source, not proof of the source packaged inside benchmark images. A comment mentioning v0.22-dev is insufficient runtime version evidence.

The archived Compose source declares eleven services: web, space, admin, API, worker, beat-worker, migrator, Postgres, Valkey, MinIO and proxy. These resolve to eight distinct image references, all tags rather than digest pins. Its service dependencies are local to the Plane stack in this file; this supports further investigation of isolation but does not prove that the exact benchmark task can execute without other services. Environment defaults include APP_RELEASE=stable, while the application image references in this Compose file explicitly use 1.0.0. The restore script requires the stack to be stopped and locates pgdata, redisdata and uploads volumes by the plane-app naming prefix. Do not run its broad volume-selection operations against an unrelated shared Docker host.

Route evidence is partial. The public API project endpoint has POST/PATCH/DELETE handlers. The app route file maps project creation and project-member creation to POST actions. The API issue route file exposes a project-scoped issue endpoint, but its implementation and assignment semantics were not reviewed in this screen. No public membership endpoint absence is asserted: the inspected public project route file alone cannot establish that globally. No live authentication, UI field coverage, state equivalence, reset correctness or API assignment behavior has been demonstrated.

Decision: retain pm-assign-issues as a capability-review candidate, not as an enrolled scientific workflow. The full benchmark is not scheduled. Before an ordinary qualification trial, resolve all image digests and compressed sizes, verify backup bytes, establish source/version correspondence as far as the evidence permits, and register a resource-bounded isolated runtime plan. Exact task feasibility still does not establish a novel method or an adequately diverse evaluation frame. Do not treat one successful workflow as evidence that the Q1 contribution gap is closed.
