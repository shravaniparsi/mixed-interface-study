# Redesign reference provenance and population feasibility

The available-reference classification partitions 1,567 repositories into 1,112
with references only in two retained catalog-metadata files, 347 prior references
with unresolved exposure, 96 other references with unresolved provenance, and
12 closed catalog projects with acquired source. These are provenance categories,
not scientific eligibility labels. Missing historical objects and unindexed
conversation/untracked exposure remain unresolved.

At published freeze ba9c212cb27ebbbaec39d51070db790e175d657d, the local-only screen
parsed the 1,362 original catalog entries once and applied the fixed API-advertising
and deployment/license/provenance predicates. Forty repositories from forty owners
passed. The retained verification reconstructs the passing set from all rows and
checks input hashes. Counts are metadata results; no app source, issue, README,
API or runtime was fetched, and no scientific inputs executed.

The additional API-description predicate failed for 1,295 entries. Failed predicate
counts overlap and are not mutually exclusive exclusions. The screen uses only
an explicit standalone API mention in the description, so APIs omitted from that
text are undercovered. It does not establish a writable API, browser editor,
two text fields, deployment reproducibility, restore support, contractual
compatibility or independent ancestry. The forty owner labels are not proof of
forty independent code lineages.

No sample was selected, ranked or replenished, and the previous twelve-project
study remains closed. This is a defined API-advertising stratum of already exposed
catalog metadata under the newly approved question, not a fresh or blind catalog.
The next gate is a prospectively bounded source/metadata feasibility stage that
establishes actual workflow and deployment capabilities without inspecting altered
input outcomes. Its selection order, development/evaluation split, acquisition
limits and stopping rules must be published before collection. Passing source
feasibility cannot be chosen from suspected bugs or expected positive findings.
