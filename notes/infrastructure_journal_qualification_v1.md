# Infrastructure failure evidence: offline qualification v1

The previous goal turn was progress: it retained a failed state qualification and showed that its exact bootstrap diagnostics were unavailable. Authoritative starting main for this turn was 4ceb9bcc6645dc8a94da08369d7ebde1d6001ccc. The application allocation remains closed; no new application, database, repository selection or evaluation source acquisition occurred here.

The new generic command recorder writes a started receipt atomically before launching a child. It records a public stage label, bounds, exit status and bounded combined output; it does not record arguments or environment values. It preserves failed-executable and nonzero-exit diagnostics, terminates the child process group on timeout/output overflow, and writes terminal evidence to the same journal location. A hard interruption may leave a started receipt rather than a false success. Filesystem write errors propagate; inability to create the initial receipt prevents execution.

Eight local synthetic tests passed: ordinary success, nonzero exit retaining its diagnostic, missing executable, timeout preserving prior output, output overflow, credential truncation at the output boundary, receipt-before-child ordering, and prevention of launch when the receipt cannot be written. Tests used disposable local Python child processes, not PostgreSQL, Zipline or altered producer inputs. They qualify these utility behaviors on the local environment, not Linux database startup or causal state restoration.

Redaction replaces explicitly supplied exact credential values and withholds a potentially partial trailing value when output is truncated. This is not a general detector for unknown credentials or personal data. Future use must supply the complete known synthetic credential set and constrain command output; arguments/environment remain omitted. A separate reviewed publication allowlist is still required. The tests intentionally use a labelled synthetic sentinel, never an account credential.

The original state run cannot be diagnosed retrospectively from this utility. Its initdb/pg_ctl error file was outside exported evidence and remains unavailable. No claim that permissions caused that failure is added. Old bound runners and protocols are unchanged. This utility is not integrated into or dispatched against the closed application allocation.

Before another empirical study, infrastructure prequalification needs an explicit separate budget and gate: disposable database create/read/backup/restore/shutdown, a controlled failing startup with sanitized retained diagnostics, and confirmation of service-user traversal permissions. Only then should an original-application qualification consume a scientific adapter attempt. Any renewed application allocation would be an explicitly post-failure methodology revision, not an independent replication or a silent retry. The fixed population/exposure record and all previous failures must remain visible. No new execution allocation is created by this note.
